## 추가 접속 진단 — 07:52 KST

Syntax에서 Grammar SSH 설정의 주소 해석은 성공하고 TCP/22 연결도 열리지만, 4초 안에 SSH 배너가 오지 않았다. SSH 클라이언트에서는 시간초과·연결 종료·재설정이 번갈아 나타난다. 이는 인증 거부가 아니라 Grammar SSH 서비스가 현재 배너 단계까지 응답하지 않는 상태와 일치한다.

## 승인 범위와 다음 진행

사용자는 이번 바깥 왕복 1회의 사전 승인 범위를 정했다. GPU F sweep은 1회로 끝났으므로 다시 실행하지 않는다. 반환장 응답은 CPU16·32GiB·최대3시간 1회, 그 뒤 새 J 중심 T/ne 방향 평가는 최대4회·CPU16·32GiB·최대6시간, 마지막 유한 보정은 최대12개 응답·새 온도 BF 최대2회·방향 제안 최대2회·물질 수용 최대1회·CPU16·32GiB·최대3시간이다. GPU 수송 추가, 재시도, 이 범위 밖 계산은 승인에 포함하지 않는다.

다음 운전자는 Grammar 접속이 복구되면 순서대로 처리한다.

1. 먼저 Grammar `squeue`와 `sacct`를 읽어 이 반환장 응답 작업이 실제 제출·실행됐는지 확인하고, `returned_response` 산출물과 submission marker를 대조한다. SSH 제출 요청은 배너 단계에서 실패했으나, 큐 확인 전까지 중복 여부를 추정으로 단정하지 않는다.
2. 기존 응답 job이 없을 때만, 아직 실행되지 않은 승인된 CPU 응답 단계를 1회 제출한다. 제출 전 입력·수송 J/모멘트·해시를 확인하고, 확인된 job ID를 기록한다. 접속이 계속 실패하면 재시도하지 말고 상태를 보존한다.
3. 응답 완료 뒤 새 J 중심 T/ne 방향 평가와 허용된 유한 보정을 각각 승인 한도 안에서 진행한다. 새 방향 계산에 이전 입력의 probe를 재사용하지 않는다.
4. 각 단계의 산출물 신원과 결과를 비교하되, 유한 F 또는 작은 열잔차만으로 self-consistency나 CMFGEN 동질성을 선언하지 않는다. CMFGEN 물리량·Si II/III·S 분포와 최종 스펙트럼의 사전 합의 기준은 여전히 미달/미검증이다.

CPU16·32GiB 작업을 소형 CPU 작업으로 간주해 Lageunha에 옮기지 않는다. GPU 계산은 승인된 Syntax Slurm 위치를 유지한다. 이번 연결 장애를 이유로 코드·물리 계약을 바꾸거나 계산을 중복 실행하지 않는다.
