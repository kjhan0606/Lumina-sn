## §0. 설계 판단

**단계 1은 작성기 구현·CPU fixture 검증·기존 출력 무변경 증명, 단계 2는 R′ 1런 → 같은 view의 W_R′ 판독·보고 → user의 E′ 실행 여부 결정으로 진행한다.** user 결정(2026-10-02, 원문 「R'1런을 먼저 돌려요.」)으로 선택지 (ii)가 확정됐다. R′는 단계 1 통과와 등록된 제출 조건 충족 뒤 실행하며, 같은 범위의 승인을 다시 요구하지 않는다. E′는 R′ 보고 뒤 별도 user 승인 시에만 실행한다. 단계 2의 입력·관측량·분기·기대·주장 상한은 이 문서에서 먼저 고정한다.

입력 경로는 **런 안에서 최종 pass의 소비 상태가 살아 있는 동안 새 작성기를 호출하는 방식**으로 정한다. 역사적 E/R의 `work/`에는 완전한 최종 소비 배열 덤프가 없으므로, 공개 계수나 최종 인구로 누락된 배열을 추정하여 역사적 스펙트럼을 재구성하지 않는다. 현재 승인 범위는 R 설정을 새 바이너리로 실행하는 **R′ GPU 1런**이다. 동일 상태 작성기 효과 W_R′는 이 런의 짝 출력으로 판독한다. E′→R′ 응답에는 E 설정의 새 런도 필요하지만, E′ 실행은 W_R′ 보고 뒤 user가 별도로 결정한다.

새 작성기는 기존 ④를 대체하지 않는다. 기존 출력과 별도로 새 스펙트럼을 쓰고, 동일한 고정 상태에서 기존 작성기도 별도 파일로 호출하여 작성기 효과를 비교한다. 기존 ④의 최종 호출은 인구 갱신 뒤에 있으므로, 그 파일과 최종 pass 직후의 새 파일을 직접 빼서 순수한 작성기 효과라고 부르지 않는다.

기안자는 astra이며 개정25-r 및 이번 직접 발주에 따른 read-only 기안만 수행한다. 구현·직접시험·빌드·스테이징·실행·판독·판정은 운전자(25-w), 코드 감사는 `gpt-6-sol`(25-v) 담당이다. 기안자는 파일을 수정하거나 시험·계산·프리플라이트를 실행하지 않았다.

## §1. 물리 계약 하나

**질문:** 동일한 최종 pass의 물질·복사장·경계를 고정했을 때, 조립기가 사용한 방출·산란 항을 누락하거나 중복하지 않는 관측자계 출력 경로를 만들 수 있는가? 그 작성기를 E′·R′에 동일하게 적용하면 등록된 대역 관측량은 어떻게 응답하는가?

작성기는 물질·복사장에 되먹임하지 않는다. NRB 율식, 인구·온도·불투명도 생산자, 반복 수와 솔버 허용오차를 변경하지 않는다.

### 1.1 원천별 소비 위치

`J_sc`는 **기존 산란 항이 실제 소비하는 해당 빈의 J**다. 선 원장의 continuum-only `J_c`로 대체하지 않는다.

| 성분 | 보존할 원천·계수 | 새 작성기의 단일 소비 위치 |
|---|---|---|
| 매핑 선 | 조립기가 실제 사용한 `S_l^used`, 매핑 계수 `el=1` | 해당 공명면의 선 점프 |
| 미매핑 선의 열 몫 | `ε_l Bν(T_e)` — §1.3의 조립기 B 폴백과 일치하는 소비 범위 | 같은 선 점프의 열 항. 원천 충돌 시 기본 N 실패 |
| 미매핑 선의 산란 몫 | `(1−ε_l)J_sc` | 같은 선 점프의 산란 항 |
| 순수 전자 산란 | `χ_e J_sc` | 연속체 구간 수송 |
| bf·ff 연속체 | `cmf_cont_src_numerator`의 선 항을 제외한 실제 분자 | 연속체 구간 수송 |
| 침적 방출 | 해당 pass가 실제 추가한 `η_dep` | 연속체 방출 분자에 한 번 |
| 내경계 | 선택한 관측자계 레인의 고정 입사 강도 | 내경계 조건 |

양의 광학깊이에서 미매핑 선 원천은

\[
S_{u,l}=\epsilon_l B_\nu(T_e)+(1-\epsilon_l)J_{{\rm sc},b(l)}
\]

이며, 선 점프는

\[
I^+=I^-e^{-\tau_l}+D^3S_{u,l}(1-e^{-\tau_l})
\]

로 한다. **τ에 ε를 다시 곱하지 않는다.**

관측자계 연속체에는 순수 전자 산란만 남긴다. `cs->chi_es`에 들어 있는 미매핑 선 산란 \(\sum(1-\epsilon_l)w_l\)을 그대로 읽지 않는다. 선을 공명면에서 소비한 뒤 빈 기반 선 흡수·산란으로 다시 소비하지 않는다.

양의 τ 조립 범위에서 다음 원천 항을 대조한다.

\[
\eta_{\rm line,b}^{\rm frozen}
=
\sum_{\rm mapped}w_lS_l^{\rm used}
+\sum_{\rm unmapped}\epsilon_lw_lB_l
+\sum_{\rm unmapped}(1-\epsilon_l)w_lJ_{{\rm sc},b}.
\]

이 대조는 **원천 항의 보존**이다. 팽창 불투명도 빈 수송과 개별 Sobolev 점프의 전체 스펙트럼 동일성을 요구하지 않는다.

### 1.2 η_dep의 위치 확정

아래 행 번호는 T0 기준이다.

- `lumina_cmfgen.c:119–123`: `cmf_cont_src_numerator`의 ON 분자는 `eta_bf + chi_ff*B + eta_ln`이다. **η_dep는 포함하지 않는다.**
- `:2724–2726`: 위 분자를 `chi_t`로 나누어 `S_fixed`를 만든다.
- `:2731–2738`: W5 연속체 분자는 `eta_ln=0`으로 따로 저장한다. 여기도 η_dep는 없다.
- `:2775–2779`: 해당 조건에서 `kappa_dep*B/chi_t`를 `S_fixed`에 추가한다.
- `:2453` 부근의 EPAY 기본값은 0이며, E/R exports에는 `LUMINA_CMF_EPAY`가 없다. 이번 등록은 이 구성을 유지한다.

따라서 이번 레인의 새 작성기가 사용하는 비산란 연속체 분자는

\[
\eta_{\rm cont}^{\rm used}
=
\underbrace{\texttt{cmf\_cont\_src\_numerator}
(1,\chi_{\rm bf},\chi_{\rm ff},B,\eta_{\rm bf},0)}
_{\eta_{\rm bf/ff}^{\rm used}}
+
\underbrace{\eta_{\rm dep}^{\rm used}}_{\text{실제 추가 지점에서 확보}}
\]

로 확정한다.

`S_fixed*chi_tot`를 쓴 뒤 η_dep를 다시 더하지 않는다. `bf_get_eta` 내부의 ff 포함 규약을 임의로 고쳐 분자를 재조립하지 않는다. **기존 조립기가 사용한 bf/ff 분자 자체**를 소비한다.

기본 작성기는 `:3936`에서 `chi_abs*B+chi_es*J`를 사용하므로 Milne 분자뿐 아니라 η_dep도 직접 소비하지 않는다. 또한 `:3879–3880`의 “LINE_EPS off이면 chi_es가 순수 전자 산란”이라는 주석 전제를 E/R의 `LUMINA_CMF_FINE_UNMAPPED_EPS=1`이 만족하지 않는다. 두 사실은 새 계약의 근거이며, 그 효과 크기는 단계 2 전까지 미측정이다.

### 1.3 폴백·부호·영 극한

- 매핑 여부는 생산자의 권위 마스크로 정한다. `S_l>0` 여부로 매핑을 재분류하지 않는다.
- 기존 조립기가 명시적으로 사용한 B 폴백은 출처를 표시하여 보존할 수 있다. 이를 NLTE 인구 원천으로 표시하지 않는다.
- 미매핑 열 원천의 계약은 §1.1의 εB로 유지한다. 기존 조립기는 εS_l을 사용하므로, 기본 N이 실제 소비할 미매핑 선×셸에 양의 `line_source_S`가 하나라도 있으면 `FAILED(UNMAPPED_SOURCE_CONFLICT)`로 실패한다. 양의 값이 우연히 B와 같거나 ε=0인 경우도 이 구현의 지원 범위에는 포함하지 않는다. 성공 범위에서는 조립기가 실제 선택한 B 폴백을 소비하며, 매핑/미매핑 분류 자체는 계속 권위 마스크를 따른다.
- 이 검사는 양의 원천을 B로 덮어쓰거나 해당 선만 제외하는 수리가 아니다. 물질·조립기·선 집합을 변경하지 않고 기본 관측량을 X로 판정한다. signed·영 τ 추가 성분만의 미지원과 구분한다. 결손·비유한값을 새 B 폴백으로 숨기지 않는 기존 조건도 유지한다.
- 결손·NaN·무한값·세대 불일치를 새 B 폴백으로 숨기지 않는다.
- B-1은 (a)안을 채택한다. N의 기본 선 집합은 해당 최종 pass에서 코어스 조립기가 실제 소비한 선×셸 집합이다. `τ>10⁻¹²`뿐 아니라 주파수 범위·유효 빈 등 실제 선택 술어를 모두 보존하며, 매핑/미매핑 분류에는 권위 마스크를 사용한다. 매핑 마스크와 소비 집합을 같은 것으로 취급하지 않는다.
- 선택 근거는 이 계약의 목적이 조립기가 사용한 원천의 누락·중복을 고치는 것이기 때문이다. J-해가 소비하지 않은 signed·영 τ 선을 N에 합치면 작성기 효과에 새 선 집합의 추가가 섞인다. 코어스 선택 밖 집합은 별도 기록하고 전체 생산자 집합과의 일치를 주장하지 않는다.
- 코어스 소비 집합 밖의 signed·영 τ 선은 N에 포함하지 않고 별도 추가 성분으로 취급한다. 생산자 권위는 `line_net_sobolev_material`의 `emission_per_sr`와 `effective_integrated_opacity`이며, 같은 물질 세대의 실제 생산 경로와 지원 범위를 확인한다. 독립 방출·흡수 계수로 안정적인 formal 식을 사용하고 `η/χ`만 저장하여 χ=0에서 방출을 잃지 않는다.
- 추가 성분은 명시적 context의 별도 내부 스위치로 N과 분리하여 평가한다. 새 환경 키는 늘리지 않는다. 같은 고정 view에서 추가 성분을 끈 N과 켠 N+signed를 구분하고, 지원되는 경우 §5.1의 대역별 차이를 보고한다. signed·영 τ 이외의 코어스 선택 밖 선을 이 성분에 몰래 포함하지 않는다.
- 생산자가 적용한 `SRCE_CHK`의 raw/effective 계수와 적용 여부를 보존한다. 새 작성기가 raw τ를 다시 적용하거나 별도 clipping을 하지 않는다.
- 기본 N에 필요한 생산 계수·경계·세대의 연결을 구현·검증하지 못하면 기본 관측량은 X다. signed·영 τ 추가 성분만 연결·검증하지 못한 경우에는 그 성분에만 `UNSUPPORTED_SOURCE_DOMAIN`을 붙인다. 해당 부분 출력은 보존하되 추가 성분의 완전한 대역 차이로 사용하지 않으며, 그 사유만으로 적격한 N·L·W_X·Δ_N을 X로 바꾸지 않는다. 미지원 추가 성분을 0으로 보고하지 않는다.

일정 계수 구간의 검증 식은

\[
I_{\rm out}
=I_{\rm in}e^{-\tau}+(\eta\ell)\phi(\tau),\qquad
\phi(\tau)=\frac{-\operatorname{expm1}(-\tau)}{\tau},\quad
\phi(0)=1
\]

이다. 큰 음의 τ에서 수치 표현 범위를 넘는 경우 성공값으로 잘라내지 않고 명시적으로 실패한다.

## §2. 설계

### 2.1 단계 분리와 입력 수명

| 단계 | 목표 산출 | 종료 조건 |
|---|---|---|
| 단계 1 | 실제 작성기에 연결된 fixture 결과, OFF 무변경 증거, 코드 감사 처분, 비용 추정 | §4의 단계 1 조건 충족. GPU 실행 권한은 발생하지 않음 |
| 단계 2 | 먼저 R′의 새 스펙트럼·동일 상태 기존 작성기 출력·W_R′ 보고. E′는 별도 승인 시 추가 | 단계 1 통과와 등록 제출 조건 충족 뒤 R′ 1런 실행·판독·보고. 이후 user가 E′ 실행 여부 결정. E′ 전에는 두 상태 응답·FUV 분기 보류이며 전체 완료가 아님. §6 주장 상한 유지 |

새 입력 경로는 다음 순서로 구현한다.

1. 마지막 pass의 조립 과정에서 실제 소비 집합, 선 원천·매핑·ε와 순수 전자 산란·bf/ff 분자·η_dep의 권위와 세대를 확보한다. `used_nlte_asm`은 T0 `lumina_cmfgen.c:2417`에서 해제되는 지역 배열이므로 작성기 삽입점에서 빌리지 않는다. 해당 pass의 조립 중 최소 마스크를 확보하거나 같은 고정 입력과 술어로 재생성한다. uint8 전체 마스크를 소유하면 129,439,900 B이며 실제 소유량을 메모리 추정에 포함한다.
2. 그 pass의 복사장 계산 후 같은 물질 세대에 대응하는 `J_sc`를 연결한다.
3. signed·영 τ 추가 성분의 계수가 fine 생산자 내부의 임시 배열에만 존재하면, **해당 배열이 유효한 생산 지점에서 필요한 계수만 보존**한다. 다음 인구로 다시 계산하지 않는다. 새 키 ON인 최종 pass의 기존 조립 순회에서 선×셸 전수를 한 번 계수하여 코어스 소비/비소비와 τ<0, τ=0, 0<τ≤10⁻¹², τ>10⁻¹², 비유한값 및 주파수·빈 제외를 구분해 기록한다. 이 계수는 기존 승인 런에 붙이며 별도 런·전체 배열 덤프·추가 순회를 만들지 않는다. 역사적 `tau_sobolev` 덤프가 없으므로 구현 전 전수 실측을 했다고 쓰지 않는다. `[UNMAPPED-EPS]`의 소비 수와 전체 선 수의 차를 음의 τ 수로 간주하거나 fine 표본 원장의 비율을 전수로 외삽하지 않는다.
4. 최종 radiation commit이 성공한 뒤, **다음 물질 갱신 전**에 고정 view를 검증하고 두 작성기를 호출한다.
5. 호출·I/O 성공 또는 실패와 무관하게 임시 상태를 정리하고 전역 상태를 복구한다. 기본 N 또는 동일 상태 기존 작성기 어댑터가 실패하면 stderr에 `det_obs_state=FAILED(reason)` 한 행을 남기고 성공 `det_obs_manifest.json`은 쓰지 않는다. 실패·부분 파일은 삭제하지 않는다. 상태를 별도 런 출력 manifest인 `det_obs_status.json`에도 기록하고, 복구 후 R7·physics dump·최종 인구·기존 ④·footer를 생성하는 기존 실행 흐름을 계속한다. 진단 작성기 실패만으로 `CMFGEN_RUN_DONE(-1)`을 호출하거나 `model_rc`를 바꾸지 않는다. 생산 계산 자체의 오류와 반환 규약은 유지한다. 상태 파일까지 기록하지 못하면 stderr 증거를 보존하고 G-RUN은 상태 결손으로 X를 판정한다.

현재 구성의 기대 신원은 최종 call 7의 radiation/material/assembly 세대다. `physics_DET_iter0005`의 다음 인구 gen8을 이 view에 섞지 않는다. manifest에는 논리 반복, call, radiation·material·assembly 세대를 각각 기록한다. 서로 다른 종류의 카운터를 숫자가 같다는 이유만으로 같은 권위로 취급하지 않는다.

역사적 E/R의 `nlte_levels_final.csv`와 공개 `η_bb/χ_bb`는 새 작성기의 결손 입력 대용이 아니다.

### 2.2 기존 출력 보존과 동일 상태 짝 비교

새 키는 **`LUMINA_DET_OBS_WRITER` 하나**다.

- 부재 또는 문자열 `"0"`: OFF.
- 문자열 `"1"`: ON.
- 그 밖의 값: 명시적 설정 오류.
- 기본값은 OFF이며 `LUMINA_ENV_STRICT=1`의 등록 목록에도 추가한다.

ON일 때 각 새 런의 `work/` 아래에 다음 파일을 신설한다.

| 파일 | 의미 |
|---|---|
| `lumina_spectrum_det_obs.csv` | 새 작성기의 관측자계 출력 |
| `lumina_spectrum_det_obs_legacy.csv` | **같은 고정 view**를 받은 기존 작성기의 출력 |
| `det_obs_manifest.json` | 기본 N·L 성공 시 입력 신원·세대·소비 집합·지원 범위·출력 해시·호출 결과 |
| `det_obs_status.json` | 성공 manifest와 분리한 런 출력 상태. `det_obs_state=SUCCESS` 또는 `FAILED(reason)`, 추가 성분 상태와 실패 사유 |
| `lumina_spectrum_det_obs_signed.csv` | 추가 성분을 지원할 때 같은 view의 N+signed 출력. 기본 N·L과 분리하며 부분 파일은 적격 출력으로 사용하지 않음 |

기존 `lumina_spectrum.csv`와 `lumina_spectrum_comoving.csv`의 이름·기존 호출 위치·출력 형식은 유지한다. 새 파일이 이미 있으면 덮어쓰지 않고 실패한다.

새 행진은 명시적 context를 사용한다. 기존 작성기를 짝 비교용으로 호출하는 어댑터는 그 호출이 만지는 모든 `g_sob_*`와 관련 전역 상태를 저장·복구한다. `g_sob_sl_ptr`만 NULL로 되돌리는 방식으로 끝내지 않는다. 정상 종료뿐 아니라 할당 실패·파일 열기 실패·쓰기 실패에서도 복구해야 한다.

동일 view의 배열과 경계 신원은 두 호출 전후에 대조한다. 새 작성기는 J·인구·온도·불투명도·원장·난수 상태를 갱신하지 않는다.

L은 기존 `g_sob_taumin=10⁻⁶`을 유지하고 N은 코어스의 `τ>10⁻¹²` 및 나머지 실제 선택 조건을 따른다. 따라서 같은 view라도 두 작성기의 선 선택이 완전히 같지는 않다. 특히 10⁻¹²<τ≤10⁻⁶ 범위의 차이는 W_X에 포함되며, 그 총효과가 무시 가능하다고 미리 단정하지 않는다. L의 문턱을 바꿔 기존 작성기를 재정의하지 않는다.

순수 전자 산란의 수송 계수는 해당 pass의 조립기가 실제 사용한 국소 `chi_e`를 조립 지점에서 직접 포착한다. 별도 물리식이나 다음 세대의 상태로 재계산하지 않는다. 같은 조립 pass의 `cs->chi_es`와 `g_chi_line_sc_unmapped`도 확보하여 차감값과 직접 포착값을 대조한다.

각 셸·빈에서 A=`cs->chi_es`, S=`g_chi_line_sc_unmapped`, E=직접 포착 `chi_e`로 둔다. mode 1은 L=Σw와 H=Σ(w·el)을 각각 부동소수 누적한 뒤 A=fl(E+fl(L−H))를 만든다. S는 미매핑 선의 fl(w·fl(1−el))을 별도로 누적한다. A+S에 고정 상수 1e-12를 곱한 옛 상한은 L·H의 누적 반올림을 제한하지 못하므로 다음 절대오차 상한으로 대체한다.

fl은 이진64 최근접·짝수 반올림이며 점진적 언더플로를 포함한다. u=2^-53, a=2^-1074, ρ(x)=u·|x|/(1−u)+a로 둔다. ρ(x)는 유한한 기본 연산의 반올림 결과 x에 대한 절대 반올림 오차 상한이다. 실제 생산 연산 순서를 보존하며 이 전제를 깨는 재결합·flush-to-zero를 허용하지 않는다.

mode 1에서 n은 해당 셸·빈의 실제 소비 선 수, m은 그중 미매핑 선 수다. 같은 pass의 유한한 w≥0, 0≤el≤1, 매핑 el=1 및 0≤m≤n을 전제로 한다. 조건 밖의 값을 clipping하지 않는다. L·H·S는 실제 누적 결과이며 D=fl(L−H), U=fl(A−S), r=fl(U−E)로 둔다.

B0 = n·ρ(L) + 2n·ρ(H) + m·L·ρ(1) + 2m·ρ(S)
     + ρ(D) + ρ(A) + ρ(U)
B  = B0 + u·B0 + a

mode 2는 열 선 계수 H=L 복사와 S=0의 연결을 확인한 뒤 B0=ρ(A)+ρ(U), B=B0+u·B0+a를 사용한다. mode 1의 독립 누적 오차를 mode 2에 부여하지 않는다.

n·m은 기존 선 누적 루프에서 실제 선택 술어를 통과한 항만 같은 순회 중 계수한다. L·H는 χ_es 조립의 실제 `chi_ln`·`chi_ln_th`에서, A·S·E는 기존 `det_obs_capture_cell` 지점에서 같은 pass의 값으로 포착한다. D는 포착한 L·H의 같은 뺄셈으로 얻는다. 다음 pass나 physics CSV에서 역산하지 않는다. 추가 보존은 셸×빈 값·계수에 한정하며 선×셸 double 사본이나 별도 전수 순회를 만들지 않는다. 조립기의 기존 누적식·순서·수송 계수는 바꾸지 않는다.

상한 계산은 정수 변환과 중간 연산까지 바깥쪽 반올림하여 수학적 B 이상인 유한한 B_up을 만든다. 생산 계산의 반올림 모드를 변경하지 않는다. 최종 기준은 `|r|≤B_up`이며 위반 시 `FAILED(CHI_E_RECONCILE)`다. 피연산자·상한의 비유한값, 포착 결손, 세대·지원 범위 위반은 별도로 실패하며 무한 상한으로 통과시키지 않는다.

`chi_e_subtraction_max_dev`는 옛 A+S 척도의 비교용 진단으로 유지하되 1e-12 판정에는 사용하지 않는다. manifest에는 상한식 판본과 최대 `|r|/B_up`, 해당 셀의 셸·빈·mode·n·m·L·H·A·S·E·r·B_up을 기록한다. 실패 시에도 같은 최소 증거를 상태 파일 또는 stderr에 남긴다. run1 편차에 맞춘 경험적 배수는 추가하지 않는다.

총 선 불투명도와 열 몫의 누적·상쇄 때문에 차감값의 오차가 순수 전자 산란보다 커질 수 있으므로, 차감은 원천 연결 검증에 사용하고 수송에는 직접 포착값을 사용한다. 새 상한은 조립·대조 연산의 반올림 한계이며 E 자체의 상대정확도 보증이 아니다. 원본 배열의 수명·세대를 확인하고 원본을 차감 갱신하지 않는다.

per-line ε는 동일한 매핑 권위·ne·Te·τ로 `cmf_assemble_unmapped_el`을 재평가할 수 있으므로 보존을 위한 선×셸 double 사본을 요구하지 않는다. 재평가의 오류 상태는 작성기 context에 격리하거나 복구한다.

### 2.3 관측자계 수송과 적분 규약

- 관측 주파수 격자와 출력 파장 범위는 기존 coarse 관측자계 출력의 격자를 유지한다.
- 원판 광선 수는 기존 기본값 256, 연속체 구간의 최대 속도 간격은 기존 기본값 30 km/s를 사용한다. 결과를 보고 격자를 조정하지 않는다.
- 선은 실제 공명 위치 순서로 소비한다. 선 앞·뒤 연속체 구간을 나누며, 구간 경계의 공명은 반열린 구간 소유 규칙으로 한 번만 배정한다.
- 흡수·방출·강도 변환은 동일한 Doppler 인자를 사용한다. 정적 fixture 외에 계수 변환과 경계 변환의 일관성도 직접시험한다.
- 내경계는 기존 관측자계 레인의 `INNER_BB_SCALE`, `T_inner`, 기하와 \(D^3B_\nu\) 처방을 고정한다. 기존 coarse/fine 내부 경계와의 완전 동치를 주장하지 않는다.
- 새 CSV의 값은 double 왕복 보존 정밀도로 쓴다. 기존 CSV의 출력 정밀도는 변경하지 않는다.

### 2.4 E′·R′ 설정

먼저 R′를 R의 봉인 초기 입력에서 시작한다. E′는 별도 user 승인 시 E의 봉인 초기 입력에서 시작한다. 최종 인구 warm start를 사용하지 않는다. E′를 실행할 경우 R′와 같은 봉인 B1 바이너리를 사용한다. 아래 E′ 설정은 조건부 후속 실행의 등록이며 현재 실행 승인이 아니다.

입력·exports의 허용 변경은 새 바이너리 신원, 새 런 경로 이식, `LUMINA_DET_OBS_WRITER="1"`뿐이다. R→RP의 exports는 경로 이식 외에 이 키 하나만 추가하며 `LUMINA_CMF_FINE_MGPU_DEVICES="2"`를 유지한다. `GPU_PROFILE`은 러너 내부 상수이며 exports에 추가하지 않는다. 러너 변경은 §3의 별도 실행 변경집합으로 제한한다. 경로 이식은 선행 계약의 다음 키와 동일한 상대 대상에 한정한다.

```text
LUMINA_MODEL_DIR
LUMINA_CMFGEN_SIGMA_BF
LUMINA_DEPOSITION_FILE
LUMINA_FIXED_TE_PROFILE
LUMINA_IONIZATION_REFERENCE_FILE
LUMINA_TOPION_LEVELS_FILE
LUMINA_PHYSICS_COMPARISON_DIR
```

### 3.3 단계 2 자원과 시간 근거

현재 승인된 R′ 1런의 자원 상한은 다음으로 고정한다. E′는 별도 user 승인 시에만 같은 자원으로 1런 실행한다.

```text
--partition=h200
--nodes=1
--ntasks=1
--gres=gpu:H200:2
--cpus-per-task=16
--mem=64G
--time=30:00:00
--no-requeue
--exclude=syn102
```

user의 2026-10-05 결정에 따라 run2는 h200x2로 실행한다. 기대값은 `expected_partition=h200`, `expected_gpu_count=2`, `expected_kinds=H200`, `expected_min_memory=140000`이다. 최소 메모리는 GPU당 140000 MiB이며 기존 h200x1 기준을 따른다. 가시 GPU 두 장·서로 다른 UUID·동종·파티션과 종류의 일치·MGPU=2 검사를 유지한다. 모듈은 runner 안에서 `module purge` 후 선행 빌드와 일치하게 로드한다.

R의 Slurm 실측 경과는 **11:36:36**이며 모델 footer의 41,788초와 구분한다. R은 H100×2에서 약 11.61시간, R′ run1은 A100×2에서 약 12.91시간이었다(N·L 행진 미포함). 발주에 제시된 LTEUNMAP-EPS run5의 H200×1·5시간 01분은 다른 실행의 전례다. H200×2 실측은 없으며 GPU 수로 나누거나 임의 가속률을 적용해 run2 시간을 예측하지 않는다. CPU 작성기 실행 중에도 GPU 두 장의 할당 비용이 발생한다. 이번 추가 승인 상한은 **R′ run2 한 번, 경과 30시간, 60 GPU·시간**이다. 자원 사양과 `2T_R+T_add≤30`시간 조건을 유지한다. run1의 실제 지출은 별도 누적 비용으로 보존하며 지우거나 run2 비용으로 재명명하지 않는다. E′는 별도 승인 시 같은 자원과 경과 30시간·60 GPU·시간 상한을 적용한다. run2와 E′의 합계 120 GPU·시간은 E′까지 승인된 경우의 추가 지출 상한이며 현재 승인 지출이 아니다. run2 실패·시간 초과 뒤 자동 재제출은 허용하지 않는다.

새 행진 시간은 단계 1에서 다음 방식으로 추정하여 R′ 제출 전 보고에 싣고, 이후 E′ 승인 자료에도 사용한다. R′ 선행 결정은 시간·메모리 적합성 확인을 면제하지 않는다. L-1의 E 크기 격자 실측 1회로의 대체는 이번 개정에서 채택하지 않는다. 완전한 역사적 소비 view가 없어 그 실측은 합성 입력에 의존하며, 기존 ④의 파일 시각 간격에서 얻은 약 4.4분 상한은 새 원천 연결·추가 성분 처리의 상한을 보증하지 않는다. 아래 비용 추정을 유지하되 새 GPU 비용 측정 런은 추가하지 않는다.

1. 실제 컴파일된 새 작성기와 짝 비교용 기존 작성기를 작은 합성 격자에서 실행한다.
2. 주파수·광선·셸·선 밀도를 달리하여 구간 처리량, 공명 검색·소비량, I/O 시간을 측정한다.
3. E/R의 격자 크기·선 수·광선 수로 작업량을 환산한다. 전체 선 목록을 매 구간 순회하는 구현이면 그 비용도 포함한다.
4. 정상 대조와 고밀도 사례에서 얻은 보수적 추정 중 큰 값을 사용하고, 기본 N·L과 실제 실행할 signed·영 τ 추가 성분 평가·입력 확보·검사·I/O의 합에 2배 여유를 둔 \(T_{\rm add}\)를 제시한다. 추가 성분이 미지원이면 그 상태와 실제 수행 비용을 구분해 기재한다.
5. 제출 가능 조건은 \(2T_R+T_{\rm add}\le30\)시간으로 유지하되, 여기서 T_R은 R과 R′ run1의 Slurm 경과시간 중 큰 값(약 12.91시간)을 쓰는 계획 기준이다. 2배 여유는 기존 계약의 여유이며 H200×2 성능 실측이나 완주 보증이 아니다. T_add는 위 1–4의 전체 비용을 반영해 재확인하고 비용 판독기도 이 기준을 검사한다. H200×2에서 실제 시간은 run2 뒤 보고하며 별도 GPU 비용 시험은 추가하지 않는다.

이 조건을 넘으면 광선 수·대역·물리 설정을 몰래 줄이지 않고 자원 재결정 대상으로 보고한다. 시간 초과 시 재큐잉·자동 연장·자동 재제출하지 않는다.

메모리는 기존 R의 회계 자료와 새 소유 버퍼의 실제 크기로 추정한다. \(N_{\rm line}N_{\rm shell}=129{,}439{,}900\)이라면 double 배열 하나만 약 0.96 GiB이다. §2.2의 조립기 직접 포착·차감 대조와 ε 재평가를 사용하여 전자 산란·ε 보존용 전체 선×셸 double 사본을 추가하지 않는다. 직접 포착 및 차감 대조용 셸×빈 배열, 소유 마스크와 필요한 임시 생산 계수는 별도로 실제 크기를 합산한다. 유효 기간 안의 읽기 전용 배열은 빌려 쓰고, 임시 생산 계수 중 필요한 것만 보존한다. 64G 안의 여유를 입증하지 못하면 단계 2를 제출하지 않는다.

### 4.1 G-ID

제출 전에는 다음을 확인한다.

- B0의 build source manifest와 T0 실물, T1의 기준 사본·등록 patch·변경집합을 연결한다. 판독기의 `changeset_reasons`와 `lineage_reasons`는 B0 `source_sha_at_build.txt`에 등재된 T0 파일, T0 기준 manifest에 대한 T1의 변경 범위, `N/evidence/rev4/T1_changeset.sha256`의 등록 집합·T1 해시, `N/evidence/rev4/det_obs_writer.patch.sha256`에 대한 `N/evidence/rev4/det_obs_writer.patch`의 해시 및 대상 파일 집합을 검사한다. 새 patch는 T0에서 run2용 T1을 재구성하는 전체 등록 변경이며 run1의 patch·해시를 덮어쓰지 않는다.
- 등록 patch가 T0에서 등록된 T1 변경 파일을 산출한다는 연결도 유지한다. patch 해시·대상 파일명과 T1 해시를 각각 확인한 것만으로 이 연결이 증명되지는 않는다. 정확한 기준 파일과 patch 내용으로 적용 결과를 재구성하여 T1과 대조하거나 동등한 내용 검증을 수행하고, 그 불일치를 G-ID 실패로 연결한다. 원본 T0·T1에는 적용하지 않는다.
- B1의 바이너리·소스·빌드 명령·모듈을 봉인하고 현재 제출 대상의 입력 실물 및 runner 기록에 연결한다. 먼저 RP를 검사하며, EP는 별도 승인 후 E′ 제출 전에 검사한다.
- R→RP의 초기 입력·온도·침적·원자자료는 내용이 같아야 한다. E→EP도 E′ 제출 전에 같은 조건을 요구한다. exports 차이는 §2.4와 일치해야 한다. R′ 제출·단독 판독에 미실행 EP의 실물·출력·footer를 요구하지 않는다.
- 판독기·fixture·어댑터·동결 의존 파일의 해시와 시험 기록을 연결한다.
- 단계 1 통과 기록, user의 R′ 선행 1런 결정, §3.3의 시간·메모리 추정과 상한 충족 증거가 존재해야 한다. E′ 제출에는 R′ 판독·보고와 그 뒤의 별도 user 승인을 추가로 요구한다.

제출 전 G-ID는 §3의 러너 허용 diff, 시험된 러너 해시와 `STAGE_IDENTITY.txt`의 일치, 러너·저장한 제출 명령의 §3.3 자원 일치를 검사한다. 자기 해시 등록만으로 미등록 러너 변경을 허용하지 않는다. 실행 후에는 footer·실제 Slurm 자원·재시작 횟수·실제 출력 manifest로 연결을 완성한다. 실행 전 아직 없는 footer를 요구하지 않는다.

### 4.2 G-IMPL — fixture 세 묶음과 OFF 보존

검사 대상은 실제 생산 작성기·행진·입력 어댑터다. 해석해끼리의 비교나 시험 전용 별도 수송 함수만으로 PASS를 만들지 않는다.

R′가 사용하는 mode 1은 실제 `cmfgen_assemble`의 미매핑-ε 게이트, `LINE_EPS_PHYS`, radeq 표, 포착, ε 재평가, 행진과 `det_obs_write`까지 연결하여 시험한다. CPU fixture에서는 `lumina_line_used_nlte_fill_for_tau`의 반환 마스크만 링크 시점 `--wrap`으로 공급할 수 있다. 이는 시험 빌드에 한정하며 생산 B1의 매핑 생산자를 대체하지 않는다.

시험 마스크에 따른 매핑 분류와 실제 소비 원천을 독립 기대값으로 대조하고, 미매핑 양의 `line_source_S` 충돌이 실패함을 검사한다. 마스크를 공급한 시험은 그 마스크를 소비하는 mode 1 경로의 검증이며, NLTE 매핑 생산자 자체나 전체 생산 모형의 종단 검증으로 표시하지 않는다. 아래 정적 해석해와 필수 결함 주입은 그대로 유지한다.

정적 double fixture의 허용오차는 사전에

\[
|I_{\rm got}-I_{\rm exact}|
\le10^{-12}\max(1,|I_{\rm exact}|)
\]

로 고정한다. 이는 해석해 구현 오차의 기준이며 스펙트럼의 물리적 허용오차가 아니다. 원천 계수 합산 대조는 합산 절댓값 스케일과 double 누적 오차를 사용하며 근사 스펙트럼에 맞춰 완화하지 않는다.

| 시험 묶음 | 정상 대조·독립 기대값 | 필수 결함 주입 |
|---|---|---|
| 미매핑 열·산란 소비 | `I_in=1`, `τ=ln2`, `B=2`, `J_sc=5`. ε=0 → 3, ε=1 → 1.5, ε=0.25 → 2.625. 실제 입력 어댑터를 거쳐 선·연속체를 함께 행진 | 산란 누락, 연속체에 선 산란 재가산, τ에 ε 재승산 |
| 독립 방출·부호·영 극한 | `τ=−ln2`, `ηℓ=ln2` → 3; `τ=0`, `ηℓ=0.25` → 1.25. 작은 ±τ의 연속 극한. Milne 분자를 χB와 다르게 지정. 침적만 바꾼 해석해. 생산자의 effective 계수 연결 | Kirchhoff 재대체, 부호 clipping, 영 τ 방출 누락, η_dep 누락·중복 |
| 소비·신원·경계·보존 | 두 구간 경계의 선 소비 횟수 1. 같은 view의 짝 출력. 다른 세대 거부. 정상·오류 경로 전역 상태 복구. 기존 파일 보존 | 경계 중복·누락, stale view, 기존 파일 충돌, 할당·열기·쓰기 실패, `g_sob_faithful` 누출 |

정적 예제의 정답은 실제 출력 숫자로 기록하고, 의도적 결함은 지정 사유로 실패해야 한다. 둘째 묶음의 부호·영 극한 해석해와 결함 주입은 유지하되, signed·영 τ 처리는 추가 성분 경로의 시험으로 구분한다. 실제 생산 계수 연결이 미지원이면 그 사실을 기록하며 합성 fixture 통과를 생산 연결 완료로 표시하지 않는다. 기본 N에 추가 성분이 섞이는 결함과 추가 성분 미지원이 기본 N을 잘못 X로 만드는 결함도 기존 묶음 안에서 검사한다.

셋째 묶음의 작성기 할당·열기·쓰기 실패 주입은 실패 상태, 성공 manifest 부재, 전역 상태 복구 및 후속 기존 작성기 호출의 지속을 CPU fixture에서 검사한다. 상태 파일까지 기록할 수 없는 경우에는 §2.1의 stderr 실패 증거와 상태 결손 처리를 적용한다. 실패를 새 관측량 성공으로 판독하면 시험 실패다.

`cmfgen_run`의 R7·footer·`model_rc`까지 포함하는 실패 주입 종단 실행은 단계 1 CPU fixture의 검증 범위에서 제외한다. 대신 같은 변경 소스의 호출부가 작성기 반환값을 생산 반환값에 반영하지 않고, 작성기 실패를 이유로 `CMFGEN_RUN_DONE(-1)`을 호출하거나 후속 생산 흐름을 우회하지 않는지 코드로 확인한다. CPU의 실패 후 흐름 지속 시험과 이 구조 확인을 함께 단계 1 증거로 사용한다. 작성기 실패만으로 생산 `model_rc`를 변경하지 않는 §2.1의 동작 계약은 유지한다.

실제 R′에서는 기존 G-RUN으로 생산 `model_rc`·footer·실행 상태와 `det_obs_state`를 분리하여 판독한다. 정상 R′ 완주는 작성기 실패 주입 시의 R7·footer 도달을 실증하지 않는다. 따라서 이 대체는 검증 범위의 제한으로 판정문에 남기며, 생산 실패 주입 종단 검증을 완료했다고 표시하지 않는다. 이를 위해 새 GPU 시험 런을 추가하지 않는다.

**OFF 바이트 동일 증명**은 다음 피연산자로 수행한다.

- T0로 빌드한 기준 CPU 어댑터와 T1로 빌드한 CPU 어댑터. 기존 `cmf_obs_selftest()`의 합성 상태 구성을 재사용 후보로 먼저 검토한다. T0의 이 함수는 `cmfgen_fine_emergent_obs`를 호출해 `lumina_obs_selftest.csv`를 쓰므로, 그 호출만으로 아래 두 기존 CSV의 OFF 바이트 증명을 대신하지 않는다. 구현자는 실제 대상 작성기·파일에 도달하는 최소 어댑터를 구성하며 T0 원본과 기존 작성기 계산식은 변경하지 않는다.
- 동일 compiler·flags·fixture·기본 환경에서 새 키 부재 및 `"0"`.
- 양쪽의 기존 `lumina_spectrum.csv`, `lumina_spectrum_comoving.csv`, 기존 작성기에 전달되는 상태 배열.
- T1의 ON 호출 전후 기존 파일과 상태, 이어서 호출한 기존 작성기의 출력.

개정 4 비교 파일은 `N/stage1/rev4/base/`, `N/stage1/rev4/off_unset/`, `N/stage1/rev4/off_zero/`, `N/stage1/rev4/on_restore/`로 격리하고 정확한 파일 목록·해시·`cmp` 결과를 기록한다. 기존 비교 산출은 보존한다.

이 시험은 **동일 CPU fixture에서 기본 경로의 바이트 보존**을 증명한다. 과거 GPU 전체 런을 다시 실행하지 않고 역사적 ④와 새 GPU 런의 바이트 동일성을 증명했다고 쓰지 않는다. 기존 작성기 계산식의 무변경과 OFF 제어 흐름은 patch·코드 감사로 함께 확인한다.

χ_e 대조의 회귀 시험을 셋째 묶음에 추가한다. 시험 전용 판정식으로 대체하지 않고 실제 작성기가 사용하는 대조 함수를 호출한다. mode 1 생산 조립기 시험에서는 n·m·L·H의 같은 pass 포착도 독립 기대값과 대조한다.

정확한 반례 fixture는 한 셸·빈에서 n=2, m=1, E=2^-10으로 고정한다. 소비 순서대로 첫 선은 미매핑 w=2^-40, el=1/2, 둘째 선은 매핑 w=2^13, el=1이다. 생산과 같은 이진64 연산 순서로 누적하면 L=H=2^13, S=2^-41, A=2^-10, r=−2^-41이다. 옛 편차는 2^-31/(1+2^-31)>1e-12이므로 실패해야 한다. 새 상한은 `7·2^-40≤B_up<8·2^-40`이고 `|r|≤B_up`이므로 통과해야 한다. 이 dyadic 입력·독립 기대값을 고정하며 관측 run1 편차에 맞춰 바꾸지 않는다. 합성 누적 fixture의 실제 대조 함수 시험과 생산 조립기의 포착 연결 시험을 구분해 기록한다.

결함 17의 `U *= 1+1e-9`는 유지한다. mode 2 정상 대조 A=E=1, S=0에서 r=0으로 통과하고, 주입 뒤에는 `|r|>9e-10`, `B_up<1e-15`로 `FAILED(CHI_E_RECONCILE)`여야 한다. 기존 결함 17 경로에서도 실패 상태·성공 manifest 부재·후속 기존 작성기 호출 지속을 다시 확인한다. mode 1의 큰 상한 사례에서 같은 상대 변조가 항상 검출된다고 주장하지 않는다.

운전자는 grammar-debug에서 이 시험과 영향받은 생산 연결·OFF 보존·판독 시험을 수행하고 정확한 소스·명령·결과를 남긴다. 그 변경 코드와 증거를 `gpt-6-sol`이 감사한 뒤 차단 사항을 해소해야 run2를 제출할 수 있다. 코드 감사의 차단 사항은 수리와 해당 직접시험으로 해소한다. 운전자의 구현 자체시험을 독립 코드 감사로 표시하지 않는다.

러너 검증은 기존 단계 1에 합친다. 원본 selftest는 h200x1 기준 sed뿐 아니라 CPU=32·반복/TE 증인=2도 생산의 16·6과 어긋난다(저자 코드 판독, 미실행). `runner_selftest` 안에서 프로파일 선택을 기본값과 무관하게 정확히 한 번 치환하고 정상 fixture를 16·6에 맞춘다. Slurm·GPU 조회·모델은 mock으로 실행하며 생산 검사를 완화하지 않는다. 정상 대조는 h200x2와 기존 h200x1·H100×2·A100×2, 음성 대조는 h200x2의 잘못된 수량·종류·메모리·파티션·UUID·CPU·MGPU 및 기존 실패 사례다. 각 음성 대조는 의도한 실패 사유를 확인한다. `bash -n`과 CPU selftest, 최종 제출 명령의 `sbatch --test-only` 결과를 러너 해시와 함께 남긴다. test-only는 자원 요청 접수 검사이며 실제 할당·완주 증명이 아니다. GPU 사전 런이나 새 게이트를 만들지 않는다.

### 4.3 G-READOUT

`scripts/nrb_e_readout.py`의 대역 적분 함수 `band_integral`과 G-ID의 재사용 가능한 신원 검사 함수는 import하여 사용하고, G-RUN·NC·`REQUIRED_CASES` 구조도 선례로 삼는다. 기존 `gid()`는 W5 기준 경로·바이너리·승인 변경을 내장하므로 통째로 호출하여 새 계약의 G-ID를 대신하지 않는다. 새 판독기는 재사용 함수에 §4.1의 B1·등록 patch·입력 연결을 조합하며 기존 NRB 분기와 “바이너리 불변” 조건을 가져오지 않는다. 기존 판독기는 수정하지 않고 import 의존 파일의 해시도 시험·증거 신원에 포함한다. RP 및 승인된 EP에는 동결 `linkage_reasons(root, nm, False)`로 stage exports·runner 해시 검사를 재사용한다. 런 후 footer의 `effective_exports_sha256` 대조는 새 판독기가 그대로 수행하고, 동결 함수의 H100/A100 전용 자원 검사는 §4.4의 등록 h200x2 검사로 대체한다. 동결 함수를 수정하거나 실패 사유를 일괄 삭제하지 않는다. 역사적 E/R·run1의 판정은 소급 변경하지 않는다.

동결 import 의존 파일은 `nrb_e_readout.py`, `nt_eta_readout.py`, `w5_cont_readout.py`이며 `FROZEN_DEPS`의 등록 해시와 대조한다. 기준 소스·등록 T1·patch·동결 의존 파일의 불일치를 `lineage_reasons`에서 G-ID 실패로 연결하고, 해당 실패 검출을 G-READOUT 필수 사례에 포함한다. §4.1의 patch 적용 결과 연결도 검사하며, 서로 무관한 patch와 T1을 각각 해시 등록했을 때 통과하는 구현으로 대체하지 않는다.

## §5. 기대치·판정량·분기

### 5.1 새 관측량과 권위

새 관측량은 기존 ④와 구별하여 **⑤**로 부른다.

각 상태 \(X\in\{E',R'\}\), 작성기 \(w\in\{N,L\}\)에 대해 N은 §1.3의 코어스 실제 소비 집합을 사용하는 기본 새 작성기, L은 동일 view의 기존 작성기다. 아래 W_X·Δ_N·Δ_L과 주 분기에는 signed·영 τ 추가 성분을 포함하지 않는다.

| 대역 | 범위 Å | 용도 |
|---|---:|---|
| FUV0 | 912–1200 | 보고 |
| FUVa | 1200–1500 | FUV 분기 |
| FUVb | 1500–2000 | FUV 분기 |
| NUV | 2500–4000 | 독립 보고 |
| OPT | 4000–6000 | 색비 분모 |
| 출력 전 범위 | 실제 파일 양 끝 | 총 출력 적분 보고 |

파장을 오름차순 정렬하고 중복을 거부한다. 대역 경계는 인접 점의 선형 보간으로 삽입하고 사다리꼴 적분한다. 대역을 파일이 덮지 않으면 외삽하지 않는다.

\[
L_{X,w}(a,b)=\int_a^bL_{\lambda,X,w}\,d\lambda ,
\qquad
C_{X,w,j}=\frac{L_{X,w,j}}{L_{X,w,\rm OPT}}.
\]

보고할 값은 다음과 같다. R′ 단독 판독에서는 아래 1·2를 X=R′에 대해 산출하여 같은 view의 W_R′를 보고한다. 3·4 및 W_E′는 E′ 실행 뒤 두 상태 입력이 적격할 때 산출한다. 미실행 E′를 역사적 E, 기존 ④ 또는 R′로 대체하지 않는다.

1. 각 런·작성기의 대역 광도와 색비.
2. 동일 상태 작성기 효과:
   \[
   W_{X,j}=\log_{10}\frac{C_{X,N,j}}{C_{X,L,j}}.
   \]
3. 같은 새 작성기로 측정한 E′→R′ 응답:
   \[
   \Delta_{N,j}=\log_{10}\frac{C_{R',N,j}}{C_{E',N,j}}.
   \]
4. 동일 view 기존 작성기의 응답 \(\Delta_{L,j}\) 및
   \[
   \Delta_{N,j}-\Delta_{L,j}=W_{R',j}-W_{E',j}.
   \]

마지막 식은 E′·R′가 모두 적격할 때 수행하는 판독의 대수 확인이며 독립 물리 증거가 아니다. R′ 단독 판독에서는 이 식의 평가를 요구하지 않는다. 색비와 함께 분자·분모 광도 변화를 반드시 보고한다. R′ 단독에서는 같은 view의 N 대 L 변화, 두 상태 판독에서는 각 작성기의 E′ 대 R′ 변화를 구분한다. 아래 signed·영 τ 추가 성분 보고도 실제 실행한 상태에만 적용한다.

signed·영 τ 추가 성분이 완전히 지원되면 같은 view에서
\[
\delta L^{\rm signed}_{X,j}
=L_{X,N+\mathrm{signed},j}-L_{X,N,j}
\]
를 각 등록 대역에 보고한다. 이는 추가 성분을 켜고 끈 수송 결과의 차이이며 선별 방출의 단순 합이나 W_X의 일부로 표시하지 않는다. 미지원·실패·부분 출력이면 수치 대신 해당 상태와 범위를 기록한다. 추가 성분이 빈 집합임을 전수 계수로 확인한 경우에만 그 차이를 0으로 보고할 수 있다.

### 5.2 문턱과 분기

R′ 단독으로 판정 가능한 것은 R′ 관측량의 적격성, 등록 대역 광도·색비, 같은 view의 W_R′ 수치·부호·아래 cat 범주다. W_R′의 down/flat/up은 작성기 간 차이이며 E′→R′ 응답 분기가 아니다.

아래 X·O-MIX·O-DOWN·O-UP·O-FLAT 표는 **두 상태 판독에만** 적용한다. E′ 미실행 동안 Δ_N·Δ_L·두 상태 대수 확인과 이 FUV 분기는 보류한다. R′ 단독 결과를 표에 넣지 않으며 W_R′로 Δ_N을 대신하지 않는다. 별도 승인된 E′ 실행 뒤 주 분기는 **기본 새 작성기의 FUVa·FUVb 응답 \(\Delta_{N,a},\Delta_{N,b}\)**에만 적용한다. signed·영 τ 추가 성분의 결과는 주 분기를 바꾸지 않는다. FUVa·FUVb에는 직접 대조할 공개 CMFGEN 스펙트럼이 없으므로 이 분기는 NRB-E의 열린 FUV 질문을 다루며 CMFGEN 어긋남 지도 칸의 종결을 뜻하지 않는다. 공개 CMFGEN과의 직접 대조는 NUV/OPT의 독립 보고로 구분한다.

\[
{\rm cat}(x)=
\begin{cases}
{\rm down},&x\le-0.30\\
{\rm flat},&-0.30<x<0.30\\
{\rm up},&x\ge0.30.
\end{cases}
\]

0.30 dex는 이번 유한 응답의 보고 범주를 나누는 사전 문턱이다. 작성기 정확도·CMFGEN 일치·물리적 무변화의 문턱이 아니다.

| 분기 | 배타적 조건 | 해석 |
|---|---|---|
| **X** | 필수 게이트·관측량 부적격 | 새 FUV 판정 불가 |
| **O-MIX** | 한 대역 down, 다른 대역 up | 대역별 반대 응답 |
| **O-DOWN** | down이 있고 up은 없음 | 하나 이상 등록 문턱 이상의 FUV 색비 하강 |
| **O-UP** | up이 있고 down은 없음 | 하나 이상 등록 문턱 이상의 FUV 색비 상승 |
| **O-FLAT** | 두 대역 모두 flat | 등록 문턱 이상의 FUV 색비 변화 없음 |

X를 먼저 분리한다. 유효한 반대 방향은 실패가 아니라 O-MIX다.

R′ 단독에서는 R′의 NUV·FUV0·전 범위 광도 및 등록 대역 W_R′를 보고하고, W_R′의 수치·부호·같은 문턱 범주를 함께 제시한다. E′ 실행 뒤에는 E′의 대응 관측량과 W_E′도 보고한다. 이 보조 보고는 두 상태 주 분기를 바꾸지 않는다. NUV가 불리하다는 이유로 대역을 삭제하거나 FUV 판정을 바꾸지 않는다.

### 5.3 사전 기대

- 단계 1에서는 §4.2의 해석해·누락 및 중복 검출·OFF 보존을 기대한다.
- 기존 작성기가 직접 읽지 않던 매핑 선 원천·Milne 분자·η_dep의 소비와 선 산란 중복 제거로 ON 출력이 달라질 가능성이 있다.
- 이 변화들의 합에는 상쇄가 가능하므로 **전체 FUV·NUV 변화의 부호나 최소 크기는 합격 조건으로 예측하지 않는다.**
- NRB의 내부 선 원천 하강이 새 FUV 색비 하강으로 반드시 이어진다고 가정하지 않는다. O-DOWN·O-UP·O-FLAT·O-MIX가 모두 가능한 결과다.
- 새 작성기의 차이가 작아도 fixture가 통과하고 실제 입력 연결이 확인되면 작성기 계약 실패가 아니다.

새 판독기의 구현할 인터페이스는 다음이다. 아래는 selftest와 R′ 단독 preflight·readout이다. `--mode rprime`은 EP와 E′ 실행 산출물을 요구하지 않는다. 별도 승인된 E′ 제출 전에는 `--mode paired`, `--base-e "$E" --base-r "$R"`, `--eprime "$EP" --rprime "$RP"`로 preflight를 수행하며, 아직 실행하지 않은 E′의 출력·footer는 요구하지 않는다. E′ 실행 뒤 paired readout은 두 런 산출물을 모두 요구한다. paired 출력은 각각 `N/evidence/preflight_paired`, `N/readout/paired`에 보존하여 R′ 단독 기록을 덮어쓰지 않는다. 모드 구분은 기존 판독기 변경집합 안에서 구현하며 새 GPU 런이나 게이트를 추가하지 않는다.

```bash
python3 -B scripts/det_obs_readout.py selftest \
  --baseline-source "$T0" --source "$T1" \
  --out "$N/stage1/rev4"

python3 -B scripts/det_obs_readout.py preflight \
  --mode rprime \
  --base-r "$R" --rprime "$RP" \
  --source "$T1" --build "$B1" \
  --stage1 "$N/stage1/rev4" --evidence "$N/evidence/rev4" \
  --out "$N/evidence/rev4/preflight_rprime"

python3 -B scripts/det_obs_readout.py readout \
  --mode rprime --rprime "$RP" \
  --stage1 "$N/stage1/rev4" --evidence "$N/evidence/rev4" \
  --out "$N/Rprime/readout2"
```

현재 제출 대상은 R′ 한 번뿐이다. 단계 1 통과·등록 제출 조건 충족 뒤 아래 첫 명령만 실행한다. 두 번째 E′ 명령은 R′의 같은 view W_R′ 판독·보고 뒤 user가 별도 승인하고 E′ 제출 전 조건도 충족한 경우에만 한 번 실행한다. 두 명령을 연속 제출하는 스크립트로 사용하지 않는다.

### 선언 블록의 범위

PF-1은 명시된 변경 경로와 `det_obs_` 심볼의 정합을 검사한다. 신설 예정 파일은 `expected_extra`로 선언한다. 이것이 미구현 파일의 존재·시험 통과를 증명하지 않으며, 구현 후 실제 patch 검사는 G-ID가 맡는다.

아래 선언은 두 상태 판독의 FUV 분기에만 적용한다. 분기 입력 `v`는 판독기가 Δ_N에서 만든 **FUVa·FUVb 범주 두 값**이다. `−1/0/1`은 down/flat/up이며, 두 상태 판독에서의 부적격은 `9` 또는 불완전 입력으로 표현한다. R′ 단독 모드는 이 분류기를 호출하지 않고 두 상태 분기를 보류로 기록한다. E′ 미실행을 빈 `v`로 보내 X로 만들거나 W_R′ 범주를 `v`에 넣지 않는다. 아래 선언은 두 상태 분기의 배타성과 전체 덮음을 검사한다. 실제 대역 적분·문턱 경계·게이트 실패의 X 변환 및 R′ 단독 모드의 보류 처리는 G-READOUT이 검사한다.
