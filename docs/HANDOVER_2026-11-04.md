   전에 중단하도록 돼 있다. 원수리가 소실된 것이 아니라 실행기의 동적 라이브러리 연결이
   아직 갱신되지 않은 문제다. 기존`build_cmfgen_source_kernels.sh`를 재사용해 실행 시
   봉인 소스에서 새 격리 kernel을 빌드하고, ABI·입력 소스·binary hash를 기록하도록 했다.
   실제 소형 빌드와 보존/ABI 시험을 통과했다. Gaunt의`gff.f`와`set_kind_module.f`는
   기존 kernel의 보존 소스와 현재 설치 소스가 바이트 일치했다. Gaunt 물리를 바꾼 것이 아니다.
2. **성공한 산란 잔차 상태의 후속 거부:** 실제 feedback 코드는 source 잔차 통과 시
   `FIXED_MATERIAL_SOURCE_RESIDUAL_PASS`를 기록한다. 하지만 제출기와 물질응답 입력기는
   `COMPLETE_F_NOT_CONVERGENCE`만 허용해 정상 완성장을 거부할 수 있었다. 두 완성 상태를
   모두 받도록 수리했고 부분장 거부는 유지했다. 실제 과거 실행 실패를 새로 발견했다고
   주장하지 않으며, 합성2F 실행에서 이 경로를 재현·검증했다. source 통과는 입력 J에 대한
   인증이므로 출력 F(J)를 인증된 입력이라고 바꾸어 쓰지 않는다.
3. **계수 종료 후 무대기 연결:** source 제출 스크립트에 명시한 묶음 config와SHA가 함께
   있을 때만 완성 계수 이후 기존 dispatcher의`field`를 한 번 호출하도록 했다. 기본값은
   비활성이다. 계수가 실패하거나 config/SHA가 불완전하면 GPU를 제출하지 않는다. GPU
   완료 후 반환 응답은 기존 단회 callback을 사용한다. 계수 전에도 기존 SSH 경로 확인기를
   재사용해 실제 할당 노드에서 Syntax 제출 경로를 확인한다. 로그인 노드 사이 양방향
   접속은 확인했고, 실제 compute-node 경로는 작업 시작 후 확인한다. 실제 SSH/Slurm 없는 합성 호출로

## 공통 인쇄 격자 재생으로 열·Si/S 준위 순율 차이 분리

### 비교 방법과 바꾸지 않은 것

기존 `summarize_cmfgen_ir_grid_impact.py`의 선 열 대조에 선택 재생 경로를 연결했다.
고정 J를 새로 풀지 않고 native EDDFACTOR의1,115,020개 노드에서 읽어, h025 CONT_FREQ의
760,649개 인쇄 좌표에 주파수 선형 보간했다. `SourceModelLines`의 기존 이산 Gaussian
코드를 재사용해789,775선의 Jbar/Q를 얻었다. 원자 주소·A·선 중심·native full 인구·열
가중을 유지하고, fine 저장값 대신 이 Jbar/Q를 넣어 native ZNET와 대조했다. Jbar를 Q로
정규화하지 않았고, 알고리즘을 바꿔 CMFGEN 숫자에 맞추지 않았다.

새 경로의 외삽·미포함 선·미표본 상태는 조용히 보정하거나 선을 제외하지 않는다.
실제 모든 유지 선의 지지범위가 포함되고,789,775개의 주소 대응도 그대로 완료됐다.
입력 MODEL에서 복원한 고정 profile이 source 기록과 같은지 확인했고, 기존 `lines.so`
SHA256 `c76d0e46958c88e5830767de6416340956b2ecb1d288b0b1c2879674fee88652`를 재사용했다.
모든 입력은 시작/종료 hash를 확인했다. 보존된 수정 전 응답의 재생이므로 absorption의
occupation 보정은 기존 별도 영향 기록과 구분한다. 깊이36의 실제 native Si II/III·S II/III
유지 전이에서는 `w_upper/w_lower-1`이 모두 정확히0임도 별도로 확인했다. 따라서 이 점의
잔여 블록 차이는 해당 occupation 비 누락으로 설명되지 않는다.

Lageunha CPU1에서 열만 집계한 첫 재생은90.73초·peak RSS2,233,524 KiB였다. 이어 같은
재생에 Si/S 준위별 유입−유출을 함께 집계한 결과는94.61초·2,320,488 KiB다. 새 실행은

## 전 선 대응과 J 적분 차이의 상쇄 증폭

### 전체 선의 공통 계수·인구 재조립

이전 절들의 원자료를 그대로 사용했다. 새 BF/SE/RE/수송이나 native 실행 없이,
Lageunha CPU1에서 약80초·최대 약1.8GiB로 기존 NETRATE를 한 번 읽었다.
원자 주소 `(Z,stage,lower full,upper full)`로 789,775개가 모두 대응됐으며, 알려진 IR
경계 제외718개와 혼동하지 않았다. 두 쪽 모두 같은 A, 같은 native full 인구와 같은
ModelThermalEnergy의 열 가중을 사용했다. 저장된 수정 전 응답을 재생하는 것이므로,
흡수 occupation 비의 별도 반사실은 기존 정본을 따른다(영향 최대1.45e-10 cgs).

재조립 식은 다음과 같다. `J_fine`은 Q로 나누지 않은 저장 profile 적분이다.

```text
H_native_common = -n_upper * A * ZNET * (h_Planck*nu) * thermal_factor
H_fine_common   = [n_lower*B_lu*J_fine
                   - n_upper*(A*Q_fine+B_ul*J_fine)] * (h_Planck*nu) * thermal_factor
delta = H_native_common-H_fine_common     # 양수=가열
```

선택 깊이는1/36/52/85/86/89/90이다. native 재조립 총합과 실제 LINEHEAT의 차이는
이 점들에서 최대2.12e-6 cgs로 기존 선 인쇄 오차 상한 안이다. 같은 native 인구를
사용한 fine 총합과 저장 Lumina 총합의 차이는 최대6.56e-8 cgs다. 깊은 층의 약5e-3
차이에 비해 작다. 따라서 이 상태에서 큰 차이를 전체 선 주소 누락·공통 A의 크기·full
인구 전달·SL 열 가중만으로 설명하는 가설은 지지되지 않는다. 원 native A와 인쇄된
ZNET의 정밀도까지 비트 일치했다는 주장은 아니다.

깊이86의 이온별 `delta`는 다음과 같다(erg cm^-3 s^-1).

| 이온 | 공통 상태의 native−fine 선 열 |

### 같은 입력에서도 적분 격자가 다른 점의 확인

native full index의 두 `edge_native` 차이를 사용하고 NETRATE의 반올림된 선 중심은
사용하지 않아 대표12셀을 재적분했다. 원 EDDFACTOR의 fine J를 native 격자에 주파수
선형 보간하고, 각 격자에 같은 Gaussian·사다리꼴 적분을 적용했다. fine 직접 적분과 저장
Jbar의 상대차는 약1e-12 이하였다. native CONT_FREQ는8유효숫자의 인쇄값이므로 binary
Q 직접 포획과 구분했다. 각 좌표의 반올림 범위로 Q의 보수적 하한·상한을 계산했다.

```text
D = c^2/(2*h_Planck*nu^3) * [n_lower*(w_upper/w_lower)/(g_ratio*n_upper)-1]
ZNET = Q_native * (1-D*Jmean_native)
Jmean_native = (1-ZNET/Q_native)/D
Jmean_fine = saved_Jbar/Q_fine
```

| 깊이·선 | native/fine 정규화 J 평균차 | Q 좌표 반올림만 고려한 범위 |
|---|---:|---:|
| 86・Co IV 77224 | -1.9761 ppm | -2.0220 ～ -1.9303 ppm |
| 86・Co IV 77199 | +1.7661 ppm | +1.6474 ～ +1.8850 ppm |
| 36・Si III 335439 | -237.037 ppm | -238.157 ～ -235.909 ppm |
| 36・S III 215057 | +296.263 ppm | +286.774 ～ +305.716 ppm |

ppm은1e-6이다. 깊이86의 두 Co IV 선에서는 native 인쇄 격자의 직접 적분 J 평균과
ZNET에서 역산한 평균이 상대차 약3.1e-11 이내로 맞는다. Si III/S III의 두 선에서는
약1.03e-6/2.78e-7 이내이며 인쇄 격자의 한계가 남는다. Co IV 77224는 J가 약2 ppm만
달라도 순선 가열은 약5% 달라진다. 흡수·방출이 거의 상쇄되기 때문이며, Q를1로 만드는
것만으로 정규화 J 평균차는 없어지지 않는다. 기존 Si III 비단조 변화 설명과도 부합한다.

결과는 `h025_dominant_line_profile_diagnosis.json`, SHA256
`4f2524fb665679cd2026f4022961dff3f2c6937b82a15b2283fbcbe45fc30ab0` 로 고정했다.
CONT_FREQ SHA256은 `abc2d368d4f69542a29becb8c910e434a017389fcca65c5a329b15ca44561ab2`다.

이는 native ZNET 반올림·모든 선 구간·모든 물리량의 불확실성을 포함한 통계적 신뢰구간이
아니다. 이12셀의 결과를 전체789,775선·90점의 적분 일치로 확대하지 않는다.

## 붕괴열 비교 정책 정정과 전90점 선 열차이 귀속

### 운전자 해석 오류와 실제 호출 경로

이전 판단에서 caller의 직접 대입`STEQ_T_EHB += dE_RAD_DECAY`만 보고 실제 RE에는
붕괴가열이 없다고 단정했다. 그러나 활성`TRT_NON_TE=F`의 열화 분기는
`CALL EVAL_RAD_DECAY_V1`을 거치며, 이 함수가 다음을 수행한다.

```text
SCALE = 1e10/(4*pi)
STEQ_T += SCALE * RADIOACTIVE_DECAY_ENERGY
STEQ_T_EHB += RADIOACTIVE_DECAY_ENERGY
dE_RAD_DECAY = RADIOACTIVE_DECAY_ENERGY
```

이는 이미 적용된 순간 붕괴 수리가 소실된 문제가 아니다. 그 수리는 유지됐고 **운전자의
비교 정책 해석이 틀렸다.** 따라서 「저장0 비교가 더 가깝다」는 과거 일반 판단을 철회한다.
더 작은 잔차를 주는 비교를 골라 물리적으로 같은 열원이라고 해석해서는 안 된다.
옛 sign/unit 정정은 유지하지만, 그때 함께 쓴「RE에는 직접 붕괴열이 없다」는 설명은 정정한다.

설치 소스만 본 추정이 아니라 실제 실행 계보도 대조했다.

- `eval_rad_decay_v1.f` 소스 SHA256:
  `3b030a800321484b8689c397a25c2c71f05c21e643288b60ab9a1c94b023d540`.
- 실제 링크 archive는 기존 봉인`libsubs.a`, SHA256
  `e4d5ec0df548d9e98e50b1d3ebfc17e35f5e6bc582c1ce12ab7da97f8d49c4f7`.
  여기서 추출한`eval_rad_decay_v1.o` SHA256은
  `40342a5b140ef6916e99b2a25e18e2bc0b49064720b47681c84c7b5343c31cdb`다.
  객체의 relocation/역어셈블리에서`radioactive_decay_energy`를 읽어`steq_t`에 곱해
  더하고, 이어`steq_t_ehb`에도 더하는 연산을 확인했다.
- 수정 observer 빌드의`link.map` SHA256
  `244f89c1db2c411b43e1b1d3af278620ac5175cc52c96c4e8f834a491d4f6ffd`도 같은 객체를 가리킨다.
- h1/h05/h025 모두 실제 VADAT가`TRT_NON_TE=F`이며, 각 GENCOOL의 반경/T/ne는 native
  열행과 인쇄 정밀도 안에서 맞는다. h025의 실측 붕괴가열은 깊이52/85/89/90에서
  `6.1339e-6/4.2967e-3/4.5896e-3/4.5973e-3 cgs`로 저장0이 아니라 Lumina 순간 열원과

## 선 흡수의 점유확률 비 수리와 주원인 분리

### 누락한 항과 연결한 경로

native`SET_LINE_OPAC`는 lower FL/SL 비율에 추가로`w_upper/w_lower`를 곱해 흡수
인구를 만든다. 상위 인구의 유도방출/자발방출에 이 비를 곱하는 것은 아니다.
LTE 분율 자체가 점유확률을 포함하더라도 이 별도 인자가 필요하다. 실제로 용해를 포함한
LTE에서`n_u/n_l=(g_u/g_l)*(w_u/w_l)*exp(-hν/kT)`이므로 이 흡수 인자가 없으면 선원함수가
Planck 값에 맞지 않는다. 설치 source SHA256은
`961076e7d17aa1832ef83e2b2c436f3047967f72060774376fea2db39017d290`다.

운전자 변경은 다음 세 경로를 함께 맞춘다.

- `src/model_source_kernels.c`와`cmfgen_model_sources.SourceKernels.lines`: 흡수 인구에만
  해당 비를 적용한다. 기존 무용해 C ABI는 유지하고, 점유확률을 받는 새 진입점을 추가했다.
  실제 source producer는 같은 상태의 occupation을 명시 전달한다. 새 ABI가 없는 옛
  라이브러리는 **비싼 BF 적분 전에** 발견하도록 했다. GFF만 쓰는 기존 소비자는 유지한다.
- `src/nlte_model_bb.c`: caller가 공급하는 원 FL 흡수율에는 occupation을 미리 넣지 않는다.
  조립 시 현재 candidate의 occupation 비와 within-SL 분율을 각각 한 번 적용한다.
  population generator·광자 열·native 가중 열은 같은 forward 흐름을 공유한다.
- `lumina_model_response_balance.py`: 독립 열장부에도 같은 흡수 비를 적용한다.
  자발/유도 역율, 선폭, Jbar, SCL_LN, BF·충돌·외부열은 이 수리로 바꾸지 않는다.

새 source와 물질응답 기록에는`BB_occupation_contract=ABSORPTION_TIMES_W_UPPER_OVER_W_LOWER_V1`
를 명시한다. 기존 완료 결과를 새 계약으로 소급 표기하거나 덮어쓰지 않는다.
과거 P08의 stale occupation/fraction 검사는 **배열이 같은 물질에서 최신인가**를 다뤘다.
이번 건은 **그 배열로부터 필요한 흡수 인자를 실제 연산에 넣었는가**로 다른 문제다.

## 동일-state BF 수 흐름과 FF 열의 전90점 대조

### PRRR 수밀도 역할 오독 수리

`WRRECOMCHK_V5`는 `Ion Density`라는 제목으로 인수`DHYD`를 쓰며, 봉인 caller
`cmfgen_sub.f`의 호출은 여기에`ATM(ID)%DXzV`를 전달한다. 이것은 **재결합 대상인
상위 이온의 바닥 superlevel 수밀도**다. 선택한 하위 이온의 총수가 아니다. 같은 writer의
명시준위 재결합 계수도`TOTRR/(ED*DHYD)`이므로 상위 이온 총수 정규화 계수와 다르다.

옛`scripts/oracle_compare_cmfgen.py:parse_prrr`는 `sum(PR)/DHYD`를 하위 이온의
Gamma로 반환하고 DHYD를 선택 이온 총수로도 비교했다. 이 비교 오류를 수리했다.
이제 원 체적 photo/RR 흐름과`parent_ground_density`를 명시적으로 반환하고,
Gamma는 독립 대응된 **하위 이온 총수**를 받은 경우에만 계산한다. 해당 총수가 없는 옛
CLI 비교는 값을 꾸미지 않고 unavailable로 남긴다. 명시준위·parent-ground alpha도
전체 alpha와의 동일 비교로 표시하지 않는다. 이 함수의 네 기존 소비자는 새 명시 이름으로
연결했으며 기존 SCRTEMP 상태 대응의 parent-ground 의미는 유지한다. 순수 파서 import가
과거 validation 모듈을 실행하지 않도록 그 import는 CLI main 안으로 옮겼다.

근거 caller SHA는 앞서 봉인한`84e3b5ae…7fd17d54c`와 현재도 정확히 같다.
설치된 writer 소스 SHA256은
`d1449a28f06fe636f53bd377d7d053aaff8822e0227be77406358cbb80336b84`다.
설치 소스를 컴파일 당시 객체의 완전한 소스 신원으로 대신 주장하지 않는다. 추가로 실제
PRRR의 DHYD를 같은 native 이진 인구의 다음 이온/full-level1 주소에 대응해 전90점에서
확인했다. 네 이온의 최대 상대차는`4.46e-5/4.35e-5/4.18e-5/3.72e-5`로 인쇄 정밀도 안이다.
독립적인 하위 이온 총수는 native eq_sl 고유 주소 합과 저장 응답·BF 장부에서 정확히 같다.

처음 만든 탐색 결과`h025_prrr_vs_stored_BF_ion_flows.json`은 **잘못된 DHYD 분모로
만든 Gamma 비율이므로 과학 해석에 사용하지 않는다.** 삭제하거나 덮어쓰지 않았다.
선택 깊이만 바로잡은`…_v2.json`도 보존하되 최신 정본은 아래 전90점 재현 결과다.
이 오독은 비교 도구에서 발견됐으며 현 C 물질 해법이 이 분모를 사용한다는 증거는 없다.

### 공통 상태에서의 실제 수 흐름

추가 계산 없이 완료 job1268424의 h025 PRRR 네 파일을 읽고, 저장 generation14/evaluation4의

### FF 및 비채택 가설

같은 실행이 새로 출력한`GENCOOL`의27개 ion FF 순냉각을 합산하고 가열 양수로
뒤집어 Lumina의`ff_native_upper_ions[H-C]`와 비교했다. GENCOOL SHA256은
`29d98078e1716c79835a89d799578f2d8745173e8cf827a4f412d1368a8bfdcf`다.
반경/T/ne는 native 열행과 전90점에서 인쇄 정밀도 안에서 대응한다. 최대 FF 열 차이는
`5.99082e-8 erg cm^-3 s^-1`이며 깊이85/89/90은 각각
`5.897e-8/4.580e-8/4.180e-8`다. 앞서 남은`~4e-3` 장부 차이의 주원인으로 FF는
지지되지 않는다. GENCOOL의 BF 값은 excess/electron 냉각이므로 full-photon RE BF와
직접 비교하지 않았다. 수 흐름과 에너지 흐름의 비교 범위를 혼동하지 않는다.

추가 소스 추적으로 다음 가설도 구분했다.

- `STEQ_T` 미초기화: 봉인 caller에서 반복 시작 시0으로 설정하므로 비채택.
- 선 열 이중 합산: 옛 주석과 달리 연속 적분은`CHI_NOSCAT/ETA_NOSCAT`를 쓰고,
  공명 선은`CHI/ETA`에만 더해진다. 명시 BB 열을 제거하는 수리는 하지 않는다.
- 두 광자 누락: 현 원자모형에 해당 H/He 과정이 없다는 기존 소스 조건을 재확인했다.
- BF 문턱 에너지 누락·SCL_LN 생산 누락·직접 붕괴열의 RE/EHB 정책 차이는 기존 기록을
  재사용한다. 이미 수리한 사실이나 별도 정책을 새 회귀로 선언하지 않는다.
- 고정49,227개 continuum 계수 평가점에서의 constant-cross 보정과 Lumina fine 직접
  평가의 차이는 남은 후보다. 아직 BF 열 불일치의 단독 원인으로 확인하지 않았다.

- h025 `OUTGEN`의 직접 원인은 `Error in COMP_OBS --- NST_CMF too small`이다.

  Slurm 메모리·시간 한도 때문에 종료한 것은 아니다.

### Si III 비단조 변화의 전이별 추적

추가 승인 답변을 기다리는 동안 같은 완료 출력만 Lageunha CPU1에서 읽었다. 기존 IR
격자지원 선택을 그대로 적용해 공통 Si III 전이1,414개를 맞췄고 깊이36/52의 각 전이에
`F_native=n_upper*A*ZNET`,
`F_fine=n_upper*A*Q_fine+(n_upper-n_lower/g_ratio)*B_ul*Jbar_fine`을 적용했다.
양수는 순하향이다. 각 SL에는 lower에`+F`, upper에`-F`를 합산했다. 여기서 `g_ratio`는
`g_lower/g_upper`이며 이온 내부 원자수 보존과 다른 전체 SE 잔차를 혼동하지 않는다.
동일 native 인구·A·fine Jbar를 썼고 전이별 합이 앞선 Si III 블록 결과를 재현했다
(깊이36 L1 h1`1.513063e6`, h05`1.739654e6 cm^-3 s^-1`).

가장 큰 h05 오차는 full-level1↔3, SL1↔2의 약1892.030 Å 전이, native line335439
`SkIII(3s3p3Po[1]-3s21Se[0])`에 있다. 깊이36에서 동일 상태의 순하향 율은 다음과 같다.

| 항목 | h1 native | h05 native | fine Jbar 기준 |
|---|---:|---:|---:|
| 순하향 율 `cm^-3 s^-1` | -1.229145e6 | +2.552596e5 | -4.825497e5 |
| fine 기준과 차이 | -7.465952e5 | +7.378094e5 | 0 |
| 저장 ZNET | -1.401180e-3 | +2.909866e-4 | 재구성 -5.500890e-4 |

이 선의 절대오차는 약1.2% 감소했지만 부호가 바뀌었다. 그에 따라 다른 전이의 오차와
상쇄되는 방식도 바뀌어 전체 SL 블록 L1이 증가했다. 이 선 오차만 두 SL에서 빼면 남은
블록 L1은 h1`3.11153e5`→h05`2.66172e5`로 오히려 줄어든다. 이는 원자 전이를 빠뜨린
새 버그라기보다 이 특정 준안정/바닥 상태 연결선이 수치 적분에 민감하다는 근거다.
다만 실제 준위 인구를 다시 푼 것은 아니므로 이온화 병목의 원인이 확정된 것은 아니다.

보존 `CONT_FREQ`와 `EDDFACTOR`를 기존 함수 `parse_native_cont_freq_text`,
`native_trapuneq_weights`, `read_eddfactor_depths`, `profile_slice`로 직접 재구성했다.
중심 주파수는 원 선 catalogue, 폭은 기존 `4.506845517e-5`를 사용했다.

| 1892 Å·깊이36 | h1 | h05 | fine |
|---|---:|---:|---:|
| 재구성 Gaussian 면적 Q | 1.000031755 | 1.000001201 | 1.000000000021 |
| Q로 정규화한 Jbar | 3.6752630e-4 | 3.6690163e-4 | 3.6721135e-4 |
| fine 대비 Jbar 변화 | +0.08577% | -0.08434% | 0 |
| 위 면적·Jbar로 예측한 순하향 율 | -1.235373e6 | +2.577394e5 | -4.825497e5 |

재구성은 관측한 큰 부호 변화를 설명하지만 native 내부 qsum의 직접 측정은 아니다.
native 출력과의 율 차이는 h1 약`-6.23e3`, h05 약`+2.48e3`이며, 중심 주파수 출력
반올림 범위`±5e8 Hz`에 대한 민감도를 별도 보존했다. 특히 h05의 중심 민감도 율 범위는
약`-3.83e4`~`+5.60e5`로 커서 재구성의 정확한 native parity를 주장하지 않는다.
저장 ZNET 자체의 부호 변화는 직접 출력이며 이 재구성 오차와 구분한다.

핵심은 **Q가 거의1이어도 선 평균 J의 약0.085% 변화가 흡수/방출 상쇄 후의 작은 순율을
크게 바꿀 수 있다**는 점이다. Q로만 나누면 양의 배율만 바뀌므로 같은 Jbar에서 부호를
고칠 수 없다. 과거 Si IV의 큰 Q 면적오차 설명을 이 Si III 선에 그대로 적용하지 않는다.
별도의 새 원인으로 모든 항을 재분석하거나 새 계측기를 붙이는 대신, 제안된 h025 완료
포획에서 이 선의 ZNET/Jbar·SL 블록 및 전체 열행을 함께 대조한다. 실제 SE/RE·이온분포·
스펙트럼 동질성은 계속`NOT_MET`다.

증거는 같은 격자 묶음 루트의 `siIII_transition_h1_h05.json`
(SHA256 `9180ab4db336a4325eee6e4dc9892cca6c3cb0cefb67c25ca5d39100ed6953e0`)와
`siIII_profile_h1_h05.json`
(`6814e17a34101d837969e33641bb796c0ec3a42560a98345ebfeda7c4cca6983`)이다.
첫 파일은 전이/SL 대응·상위 차이·블록 합, 둘째는 상위5개 전이의 Q/Jbar·native 예측·
중심 민감도와 입력 SHA를 담는다. 원 NETRATE SHA는 h1`70966b74…`, h05`12a38242…`이며
이전 부분 비교와 같다. 읽기 전후 해시가 일치했고 원 출력은 변경하지 않았다.

### 버퍼 문제의 한정 수리 준비와 남은 권한

공통-J 열 포획에는 관측자계 스펙트럼이 필요하지 않다. 준비기에 선택 옵션
`--skip-observer-spectrum`을 추가해 `COMP_OBS_V2` 호출과 `OBSFLUX` 출력만 함께
생략하도록 했다. 출력만 남겨 초기화되지 않은 배열을 스펙트럼으로 내보내지 않는다.
기존 기본 빌드는 변경하지 않는다. `LUMINA_FIXEDJ_HEAT_GUARD`는 고정-J 전용 실행을
강제하고 기존 `CHECK_SPEC_CONV`도 고정-J에서는 비활성이다. 율/열 적분·고정J 주입·
전체 인구 포획·STOP96 경로는 이 선택 옵션으로 바뀌지 않는다.

봉인 원 caller SHA `84e3b5ae…`에 실제 적용했고 기본 패치 SHA `0d494c06…`를 재현했다.
선택 패치 SHA는 `518786df2d21895561a7550dce20a90e48e2bc79093c4eb4d86cca3582e6cf78`이며
실제 native module/include를 사용한 `gfortran -fsyntax-only`가 exit0으로 통과했다.
옵션 외 바이트 보존·중복/누락 거부 및 관련 열행/비교 직접시험65개와 제출/포획 실행기
시험8개, 합계73개가 통과했다. 재현 명령은 다음과 같다.

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m pytest -q \
  tests/test_cmfgen_fixedj_heat.py tests/test_cmfgen_grid_result_comparison.py \

  tests/test_run_cmfgen_fixedj_heat_capture.py
```

이는 문법/구현 검증이며 실제 열·율 불변성은 아직 측정하지 않았다. 이 초기 준비 당시에는
새 실행파일이나 새 물리 계산을 만들지 않았다. 이후의 빌드 준비는 다음 절에 구분했다.

기존 포획 묶음은 재시도0회로 소진됐다. 새로 발견한 h025 실패는 이전 일괄 승인 당시
대기 제안이 아니었으므로 자동 재실행하지 않는다. 다음 제안은 수정 실행파일로 별도 격리
출력의 h05 기준 재현 및 h025 포획을 순차 수행하는 새 묶음이다. Grammar CPU16·32GiB·
묶음최대6시간·포획2회·재시도/requeue0·GPU0·새 수송0·물질수용0으로, h05의 열행과 BB
결과가 보존 기준과 일치하는지 먼저 확인해 옵션의 물리 결과 불변성을 검증한다. 일치하지
않으면 h025로 진행하지 않는다. 실측19.7분과 격자점수 비례로 계산 자체는 합계 약1시간을
예상하지만 h025는 미완료였으므로 보장하지 않으며 큐 대기는 별도다. h025가 성공해도
세 격자 비교 결과로만 해석한다.
현재 이 교정 묶음은 제안/승인 대기이며, 기존 실행·원자료는 덮어쓰지 않는다.

## 교정 포획 실행 준비 완료

최신 사용자 응답: **「이 교정 묶음 승인」**. 아래 과거 승인 대기 상태는 해소됐다.
동일한 Grammar CPU16·32GiB·최대6시간·2포획·재시도/requeue0·GPU0·새 수송0·물질수용0
한도로 새 격리 입력을 준비하고 제출한다. h05의 네 물리 출력 재현 뒤에만 h025로 이어진다.
실제 입력 루트·제출 식별자는 후속 실행 기록으로 구분한다.

추가 포획 승인을 기다리는 동안 기존 코드 구현·직접시험 범위에서 준비를 마무리했다.
실제 Slurm 제출, CMFGEN 물리 실행, 새 수송, 물질 갱신은 모두0회다. 기존1267906은
종료 상태로 보존했고, 새 격자 입력 staging도 아직 생성하지 않았다.

`run_cmfgen_fixedj_grid_bundle.py`에 준비 전용 `--replacement-build`와
`--bridge-reference`를 함께 지정하는 경로를 추가했다. 두 인자 중 하나만 지정하면
거부한다. 수정 빌드가 원 caller·물리 객체·원자 모형 라이브러리·붕괴 구현을 유지하고
관측 스펙트럼 호출/출력 두 구간만 제외했는지 대조한다. 각 포획은 같은 새 실행파일로
진행하고, 완료 h05 기준과 같은 물질/J·격자/control을 요구한다.

새 h05 포획 뒤 `LINEHEAT`, `NETRATE`, `TOTRATE`, `NATIVE_HEAT_ROW.bin` 네 출력의
SHA가 보존 h05와 모두 일치할 때만 h025로 이어진다. 차이가 있으면 그 자리에서 종료하고
출력을 보존한다. 허용오차를 자동 완화하거나 자동 재시도하지 않는다. 이는 관측 경로
생략이 물리 출력에 영향을 주지 않는지 확인하는 제안된 h05 대조 조건을 실행기에 연결한
것이며, 물리 목표의 새로운 합격 판정은 아니다.

후처리 비교기도 수정 실행파일을 무조건 원 실행파일과 같은 것으로 취급하지 않는다.
보존 h05와의 실제 출력 일치 및 관측 경로만 바뀐 빌드 근거를 확인한 경우에 한해,
원 h1과 수정 빌드의 h05/h025를 하나의 격자 비교로 연결한다. 두 포획이 모두 완료되지
않았거나 J/물질/빌드 근거가 다르면 전체 비교로 발행하지 않는다.

### 실제 컴파일·링크 증거

Lageunha GNU Fortran13.2.0·CPU1·빌드 한도600초로 기존 봉인 객체를 재사용해 빌드했다.
첫 준비물 `lumina_fixedj_observer_off_build_20261104_wyzltil9/build`는 순간 붕괴 옵션을
지정하지 않아 원 기준본과 다른 붕괴 객체를 골랐다. 계보 대조가 이를 거부했고 **계산에
사용하지 않았다**. 이 준비물은 원자료와 함께 보존했으며 수정하거나 삭제하지 않았다.
이는 물리 실행 실패/재시도가 아니라, 실행 전 빌드 준비에서 걸러낸 다른 옵션 조합이다.

기준본 manifest의 `EXPLICIT_VERIFIED_INSTANTANEOUS_DT0_OBJECT`를 확인한 뒤
`prepare_cmfgen_fixedj_heat.prepare(..., instantaneous_decay=True,
skip_observer_spectrum=True)`로 새 격리 빌드를 생성했다. 사용할 수 있는 준비물은
`lumina_fixedj_observer_off_dt0_build_20261104_kh36jx32/build`이다.

- 실행파일 SHA256: `b6e4f15e8af5a1bac8e586d180c1a95a25e9a8e54c792a693343953294e1fc15`.
- 생성 caller SHA256: `518786df2d21895561a7550dce20a90e48e2bc79093c4eb4d86cca3582e6cf78`.
- build manifest SHA256: `f43e1cbcee47ab653f2f766a32624d3dc94c2b9d6cd4ddbf527d78b5260ba23a`.
- 순간 붕괴 수리 source SHA256는 원 기준본과 동일한

### 전이별 근접 원인분해

같은 보존 출력의 `LINEHEAT`/`NETRATE`를 한 번 순차 대조해 789,775개 선쌍의
ID·라벨·주파수·준위 일치를 확인했다. 깊이36 Si IV/S III와 깊이85 Co IV/Ni IV의 상위
기여선 14개에 대해 `NETRATE` full-level 인덱스를 원 OSC 전이와 맞췄고, 14개 모두 현재
Lumina 선 선택에도 포함된다. 승인 고정 상태의 native full population/index SHA는 각각
`112471f1…acfdfb` / `71bf6dc8…af56d6`; comparison JSON이 이 신원을 봉인한다.

처음에는 CMFGEN `NETRATE.ZNET`에서 유효 선 프로파일 평균장 `Jbar`를 역산했다. 부호를
가열 양수로 둘 때 사용한 Einstein 관계는
`ZNET = 1 + (c^2/(2 h nu^3)) * (1 - n_lower/(g_ratio*n_upper)) * Jbar`이며
`g_ratio=g_lower/g_upper`다. 동일 전이의 `LINEHEAT`, 재구성 population, oscillator
strength/A, `SCL_LN`으로 예측한 ZNET은 14개 모두 출력 정밀도 내에서 저장 `NETRATE`와
일치(최대 상대차 `<4e-5`)했다. 다만 이 초기 역산은 line profile quadrature의 합이 1이라고
가정했으므로 native `Jbar` 자체를 직접 분리한 값은 아니다.

이후 read-only CMFGEN 소스 추적으로 실제 누적식을 확인했다. 보존 build의 `cmfgen_sub.f`
입력 SHA는 `84e3b5ae…7fd17d54c`, build manifest의 `libsubs.a` SHA는
`e4d5ec0d…8f49c4f7`다. 주파수별 `q_i=LINE_PROF_SIM(i)*Δν_i`에 대해 native는
`ZNET=Σ q_i*(1-RJ_i*CHIL_MAT/ETAL_MAT)`, `JBAR_SIM=Σq_i*RJ_i`,
`LINE_QW_SUM=Σq_i`를 따로 누적한다. `set_line_opac.f`의 `Δν_i`는 native 격자
사다리꼴 가중치다. `FIX_DOP` profile은 `TDOP=2 K`, Doppler 원자질량4, 난류속도
`10 km/s`로 계산되며 Lumina profile의 폭 `4.5068455e-5`와 일치한다. 단, VADAT의 공명대
격자 간격은 Doppler 폭 `1.0`이고, `INS_LINE_V6` 호출은 line center 삽입을 끈다.
`LINE_QW_SUM`은 line-rate 미분에 사용되지만 `LINEHEAT`/`NETRATE` 파일에는 직접
기록되지 않는다.

### 동일-state BB 순율 블록 대조

`summarize_cmfgen_ir_grid_impact.py`의 선택적 NETRATE 대조를 이용해 Si II/III·S II/III

### 실제 native 격자 수렴 비교 준비 — 2026-11-04 사용자 승인

### 고정상태 profile-mass-only 반사실

같은 포획의 `NETRATE`/`LINEHEAT` 789,775개 쌍을 line ID와 전이 라벨로 대조하고,
기존 native signed `LINEHEAT`를 그대로 사용해 `H_Q=1≈H_native/Q`를 계산했다. 이는
재구성한 Q만 1로 바꾸고 normalized profile `Jbar`, T/ne, 인구, 나머지 연산자를 고정한
반사실이다. Q는 `Σq/(√πσ)`로 정규화하고 저장된 line ledger 값을 그대로 합산했다.
새 solver·수송·물질응답은 없다. 깊이36 S III Q-only 합은 기존 분석값을 재현한다.

차이는 그대로 남는다. 깊이85에서는 Q 정규화가 전체 line heat를 `1.09e-4`만 바꾼다.
native line-vs-Lumina BB 차이 약`5.88e-3`의 약`1.9%`이므로, 해당 깊이의 주 열 불일치나
Si/S 분포 차이를 Q 하나로 설명하지 못한다. 이는 Q 근사와 고정 Jbar의 국소 반사실이지,
새 native 실행·완전한 물리 보정·공동수렴 증거는 아니다.

### 고정상태 Q=1 + fine-grid J 주요 이온 전 선 반사실

같은 789,775개 전이 쌍을 재사용해 주요 이온의 모든 해당 선에 대해 Q와 profile-weighted
Jbar를 함께 바꿨다. 출력식 `ZNET=Q(1−αJbar)`에서 `α`를 native 재구성값으로 역산하고,
`LINEHEAT/ZNET`을 고정한 채 `Q=1`과 EDDFACTOR fine-grid J의 profile 평균을 대입했다.
따라서 이 결과는 native 산출값 자체가 아니라 인쇄 `CONT_FREQ`/선 중심으로 재구성한
고정 T/ne·인구·원 J의 line-operator counterfactual이다. 새 수송·SE·물질응답은 없다.
재현기는 [reconstruct_cmfgen_lineheat_fine_j.py](../scripts/reconstruct_cmfgen_lineheat_fine_j.py)이며,
수식 단위시험 6개를 통과했다. 기존 포획에서 깊이36·85를 재실행해 앞서 기록한 이온별
Q-only 및 Q+fine-J 값과 반올림 범위 내에서 재현했다. 이 확인 출력은 파일로 저장하지
않았으며, 원 입력 신원과 해시는 이 문서 상단에 기록한 포획 manifest를 따른다.

아래 값은 `erg cm^-3 s^-1`, 양수=냉각으로 통일했다. Lumina 목표는 앞 표의 BB 열을
부호 반전해 비교했다.

깊이36 S III 3,678개 전이 전체의 Q=1+fine-J 값은 Lumina와 `3.75e-8`(3.1%) 차이다.

이는 동일한 native source 식에서 coarse profile quadrature를 Q=1·fine-J 적분으로
바꾸면 관측된 주 이온별 열 차이가 대부분 사라진다는 강한 고정상태 증거다. 따라서
현재 가장 지지되는 원인은 물질/J의 총 배열 배선 누락이 아니라 선 profile의 주파수
적분 해상도 차이다. 다만 F10.6 중심과 출력 NCF의 유한 정밀도, 포획본의 exact native

100% 일치나 exact native qsum을 뜻하지 않는다. 무엇보다 T/ne/인구를 갱신하지 않았으므로
Si/S 이온화 분포, 에너지-전하 공동수렴 또는 최종 스펙트럼의 해결 판정이 아니다.

그러므로 profile-area 차이가 실제 물질응답 계약에 들어간다는 점은 확인됐지만, 전 선의
exact native `Q`와 profile-weighted `Jbar`를 같은 원자모형 전이로 짝지은 비교는 아직 없다.
현재 보존 포획에는 `TRANS_INFO`와 `fort.77`이 없어 exact native interval mapping을
복원할 수 없고, `CONT_FREQ` 재적분은 native 격자를 근사하는 별도 진단일 뿐 exact
`LINE_QW_SUM` 대체가 아니다. 이번 이온별 합은 SE 영향이나 39/90 열 부호 불일치,
이온분율 공동수렴을 증명하지 않는다.

### S III 정규화 Jbar 차이의 격자 분해 (read-only, 2026-11-04)

같은 고정 상태 깊이36에서 대표 S III 두 선의 차이를 세 항으로 나눴다. `J_NCF`는
인쇄된 `CONT_FREQ`에 EDDFACTOR의 fine-grid J를 선형 보간한 뒤 native `TRAPUNEQ`
가중으로 직접 합산한 값이다. `J_PL-HO`는 같은 NCF 노드의 J를 구간별 선형으로 두고
Gaussian 선 profile을 12점 Gauss 적분한 값이며, `J_fine`은 원 EDDFACTOR fine-grid J를
같은 profile로 직접 사다리꼴 적분한 값이다. Gaussian 폭은 고정 `4.506845517e-5`다.

| 전이 ID | `Q_NCF` | `J_NCF/J_fine−1` | `J_PL-HO/J_fine−1` | `J_NCF/J_PL-HO−1` |
|---:|---:|---:|---:|---:|
| S III 313702 | `0.9998142` | `−0.4250%` | `−1.9715%` | `+1.5777%` |
| S III 315920 | `0.9997054` | `+0.06514%` | `−0.4658%` | `+0.5334%` |

따라서 겉으로 관측된 native/fine `Jbar` 차이가 작은 것은 native NCF의 직접 합산 오차와
NCF 사이 J 변화를 선형 보간으로 대표할 때의 차이가 반대 부호로 상당 부분 상쇄되기
때문이다. 이 두 선에서는 profile 면적 `Q`가 거의1이어도 J 적분은 격자 해상도에
민감하다. NETRATE 선 중심 출력의 반올림 한계 `±5e8 Hz`를 이동시켜도 각각
`J_NCF/J_PL-HO−1 = 1.566–1.589%`, `0.531–0.536%`이고 최종 native/fine 차이는
`−0.431–−0.419%`, `+0.0627–+0.0676%`로 유지된다. 중심 반올림만으로 생긴 결과는 아니다.
각 선의 `±3σ` 안 fine grid에는 24점이 있지만 NCF에는 6점뿐이며, 중앙 NCF 간격은
`1.000σ`다. 같은 구간에서 fine J와 NCF 선형보간 J의 profile-weighted RMS 잔차를
국소 profile 평균 J로 나누면 313702는 `4.123%`(최대 절대 잔차 `7.616%`), 315920은
`0.8140%`(`1.457%`)다. 따라서 두 선 모두 native NCF가 line-profile 내부 J 구조를
충분히 직접 표본화하지 못한다. 이 잔차는 fine grid 대비 보간 재구성 진단이며, native
내부 J의 독립 정답이나 물리 오차 상한은 아니다.

이는 근사 격자 진단이지 CMFGEN 내부 `LINE_QW_SUM`의 정확 재현은 아니다. 출력 주파수
정밀도와 exact native interval map 부재가 남고, 고차 적분은 NCF 노드 사이를 선형으로
연결한다. 특히 `J_PL-HO`와 fine-grid 값 차이는 실제 고주파 구조를 포함한 원 J를
선형 보간이 복원하지 못하는 정도까지 포함한다. 그러므로 두 오차를 물리적으로 완전히
독립인 항으로 단정하지 않으며, 이 결과만으로 어떤 격자를 수정하거나 이온화 분포를
수용하지 않는다. 다만 작은 native/fine 잔차가 정확도 증거가 아니며 profile quadrature와
J 해상도 모두를 살펴야 한다는 점은 강하게 지지한다.

이번 분해는 동일-state 고정-J에서 특정 열 전이의 원인을 강하게 좁힌 것이지, 이온화율이나
열/복사장 공동수렴을 증명하지 않는다. 상위 14개 roster, 저장 열합, 일반 `SCL_LN` 연결은
주원인으로 지지되지 않는다. 과거 `CONT_FREQ` 단순 Gaussian 재적분은 native qsum과 고유
격자 보간을 분리하지 못했으므로 원인 판정으로 채택하지 않는다. S III 정규화 `Jbar`의
격자 민감도와 깊이85 주요 Co/Fe/Ni line-operator 차이는 위 고정상태 반사실로 좁혔다.
다음 read-only 단계는 동일 식을 90점 열잔차에 확장해 전체 shell에서 profile 보정이
어느 범위까지 작동하는지 확인하는 것이다. 이는 line heat 비교이지 full `STEQ_T`, 이온율,
자기일관 수렴 판정이 아니다. 새 CMFGEN 실행·수송·물질응답은 기존 승인 범위에 포함되지

## Si/S 비교 해석

비교 기준 `CMFGEN70`은 수렴한 released-T 기준해가 아니라 고정-T 비수렴 진단해다.
아래 값은 활성 shell에서의 절대 log10 분율비 중앙값/95백분위(dex)이며, 목표 동질성
판정이 아니다. `accepted`는 보정 전 입력 분율, `새 J 응답`은 보정 후보 T/ne에서
J를 고정한 응답이다.

| 이온 | accepted 대 CMFGEN70 | 새 J 응답 대 CMFGEN70 | 활성 shell 수 |
|---|---:|---:|---:|
| Si II | 0.0369 / 0.1077 | 0.0649 / 0.1586 | 30 |
| Si III | 0.0110 / 0.0730 | 0.0986 / 0.2800 | 90 |
| S II | 0.0187 / 0.0623 | 0.0239 / 0.0777 | 40 |
| S III | 0.0082 / 0.1100 | 0.0455 / 0.1710 | 90 |

이 고정-J 보정 뒤 네 이온 모두의 해당 진단 차이는 보정 전보다 커졌다. 그러나 새
응답은 수정된 T/ne와 오래된 J를 섞은 상태이고 CMFGEN70도 비수렴 기준이므로, 이를
물리적 악화나 CMFGEN parity 실패로 단정할 수 없다. 다만 “작은 열잔차/수치 수용”만으로
이온 분포 일치가 따라오지 않는다는 점은 실물 결과로 확인됐다.

## 선택 상태의 BB 열장부와 SCL_LN 민감도

해시가 고정된 `evaluation-4/balance.npz`(SHA256
`bcc48de1e6372b0510ea28c39c6487ccfeb2342f6da1dd6b62ded6510a68f604`)의 90점 열장부를
독립 재조립했다. `balance()`의 부호(가열 양수)와 같은 방식으로 BF·BB·FF 순열,
단열항, 순간붕괴 가열을 다시 합한 결과는 저장 `native_instantaneous_scenario_net`과
최대 절대차 `1.36e-20`으로 일치했다. 이는 저장 장부 산술의 재현이지 CMFGEN 일치 증거는
아니다.

node36에서 native SCL 보정 BB 순열은 `+3.31414e-6 erg cm^-3 s^-1`이고 전체 native
잔차도 `+3.31385e-6`이다. BF 순열은 `+2.44943e-9`, FF는 `-3.65568e-10`, 단열 냉각은
`+2.37519e-9`, 순간가열은 거의0이어서 net process 사이의 상쇄는 거의 없다. 그럼에도
gross line 흐름 `9.83050`으로 나눈 잔차는 `3.37e-7`이고 channel-normalized 값은
`0.99835`다. gross 기준 수용치가 매우 작은 절대 잔차를 뜻할 수는 있지만, 독립 BB
항들이 열평형을 서로 상쇄했다는 뜻은 아니다.

같은 저장값의 미보정 BB 순열은 node36에서 `-1.35680e-5`여서 SCL_LN 적용 뒤 부호가
바뀐다. 90점 중 36점에서 미보정/보정 BB 순열 부호가 다르고 최대 보정 차이는 node90의
`5.59100e-2`다. node89/90의 보정 BB 순열은 각각 `-4.84596e-3`/`-4.83182e-3`이고,
동일점의 순간가열 `+4.58963e-3`/`+4.59731e-3`와 거의 상쇄되어 전체 잔차는
`-3.01e-8`/`-1.27e-7`이다. 따라서 SCL_LN 연결은 열장부의 핵심 민감항이다. 이 값은
CMFGEN 제어와 기존 구현을 재대조한 것이며, line-resolved `LINEHEAT`/`NETRATE` 부재로
현재 입력에서 보정된 BB 성분의 native parity는 아직 미검증이다. 부호 차이만으로
구현 오류나 새 회귀라고 판정하지 않는다.

## 신원과 미해결 비교 공백

선택 응답에는 `population` (1798×90) 및 `occupation` (24542×90)이 보존돼 있어 새
고정장 native 비교의 입력 상태를 특정할 수 있다. J SHA256은
`40a48d9aedaafa4d8f6f8adb0fdb6ea191bd152ed3f55de38e8862fe445232a6`, 선택 응답 SHA256은
`252993d3da03dd43ede0d02908c5134896aea8df902b9a54f947027b9556436e`, 장부 SHA256은
`bcc48de1e6372b0510ea28c39c6487ccfeb2342f6da1dd6b62ded6510a68f604`다.
`Si-S-comparison.csv` SHA256은
`1ae7732da87b3eef017143f38a46ac23f920100bfd9490b33cd790076c8a2348`,
`physical-profiles.npz`는
`0ef0ec19e2edcf6ea69e1ce441a40e210a75be7d5885dd1d9d55a1acdcbf2b35`이며 원격 파일의
실제 SHA256을 결과 manifest와 대조했다.

job `1264295` 제출 전까지 재사용 가능했던 같은 상태의 CMFGEN 보존본에는
`LINEHEAT`/`NETRATE`/`TOTRATE`가 없었다. 기존 입력은 `WRITE_RATES=F`였고, 합산
`STEQ_T`만으로 native 선별 에너지 교환을 복원할 수 없었다. 이 공백을 닫기 위해 선택
T/ne·인구·J를 함께 고정한 격리 CMFGEN 실행에서 `WRITE_RATES=T`로 열항을 포획하고
물질 갱신 전 `STOP96`에서 멈추는 단회 실행을 승인받았다. 첫 job `1264146`은 실행
래퍼가 필수 활성화 환경변수
`LUMINA_FIXEDJ_HEAT_ONLY=1`을 전달하지 않아 `STOP94`로 실패했고, 필요한 출력은
생성되지 않았다. 이후 동일 입력·자원 범위의 교정 단회 재제출을 승인받아 전용 실행기를
추가하고, 해시·제어·산출물 사전/사후 확인을 직접 시험했다(관련 57개 시험 통과).
새 격리 출력으로 제출한 job `1264261`은 3초 만에 batch exit2로 실패했다. Slurm이
스크립트를 spool 위치에 복사해 실행하는데 실행기가 `BASH_SOURCE[0]`에서 저장소 위치를
추정해 Python 파일을 찾지 못했다. `srun`과 CMFGEN은 시작하지 않았고 물리 출력은 없다.
이 launcher 오류를 고쳐 spool 경로를 흉내 낸 통합시험과 관련 57개 시험을 통과했다.
그때까지 승인된 교정 1회는 이후 job `1264295` 제출에 사용됐다. 새 staging과 실패
로그는 보존한다. 과거 유사 출력의 추가 저장량 추정은 약4.75 GiB다.

그 뒤 실제 자기일관성을 닫으려면 같은 수용 물질로 새 J를 계산하고 물질응답을 다시
구해야 한다. 새 transport는 Syntax GPU Slurm에서 실행할 단계지만, `1262975` 계약은
새 transport 0회였고 이 후속 수송도 현재 승인되지 않았다. 최종 스펙트럼·물리량 비교,
Si II/III·S 이온화 동질성 및 공동수렴은 모두 **미달/미입증 (`NOT_MET`)**이다.

## 선택 물질의 native 고정상태 입력 검증

완료 result SHA256 `be3bf940802800c7df94396e1fbd6a8828aa444a9c444082582179349f1eaf47`을
입력으로 `prepare_lumina_accepted_material.py`를 실행해 evaluation4의 마지막 실제 수용
상태만 별도 export했다. source kind는 `FINITE_NEW_FIELD_TNE_ACCEPTED_STEP`; 90점,
1,798개 SL/terminal 열과 24,542개 full level이다. 후보의 전하 상대오차 최대
`2.20e-15`, 핵종수 상대오차 최대 `1.49e-15`, 정상 SE 잔차 최대 `1.03e-16`이다.
저장 occupation 복원은 정확 일치, full-level 재구성 상대오차 최대 `8.64e-16`이다.
이 export는 새 BF/BB 적분·SE·수송을 수행하지 않는다.

이 물질을 native 고정상태 입력 `NATIVE_HEAT_INPUT.bin`으로 직렬화했다. 파일 크기는
1,296,752 byte, SHA256은
`a5603029f30c7fa2335e6efcf6dbb6c86e973e7bf3fcf6d7a17f28e1f73c09c4`이며 manifest SHA256은
`13c150bfea860f160eb3a4593e601936759b5fbe2e330bc935cf68fd6c98cf47`이다. 별도 readback에서
native 입력 1,800행(1,798 population + ne + T), 90개 반경점, 반경/T/ne 및 모든 population
행이 exporter의 예상 배열과 정확히 일치했다(최대 절대차 `0`). 이는 현재 선택 상태의
native 입력 배선·직렬화 증거이지 CMFGEN이 이 상태를 실제 평가했다는 증거는 아니다.

state-only manifest에는 `radiation_input=NOT_PREPARED`, `actual_native_evaluation=false`,
`heat_policy=NOT_YET_MATCHED`로 기록돼 있다. 이후 같은 F-1 J를 native EDD 입력으로
직렬화했다. `fixedj-field-input.json` SHA256은
`4e768b008fbc00c256d64fc88bc07bf59148e24dbc8f3840fb9441f1569672d2`이며 입력 J SHA256은
`40a48d9aedaafa4d8f6f8adb0fdb6ea191bd152ed3f55de38e8862fe445232a6`다. 생성된
`EDDFACTOR` SHA256 `47f78fb98810704e9b0dcf4f664e8e2a38170e5d2b68d644879fb6b447b5692d`는
이전 fixed-J 포획에서 확인한 같은 J의 native EDD와 일치하고, `EDDFACTOR_INFO` SHA256은
`2c032445a9483d5154c15cdac5c0f14dfbb3f45dbb628e2d4936c29b3efabd42`다. 90점·1,115,020
주파수 값을 보존했으며 native quadrature가 Lumina 격자와 같다고 주장하지 않는다.

job `1264295` 제출 직전에는 수용 T/ne·population 입력과 고정 J 입력이 준비됐지만,
유효한 native `LINEHEAT`/`NETRATE` 포획은 아직 0회였다. 첫 Grammar 제출
`1264146`은 CPU16·32GiB·최대4시간·GPU0·재시도0이었으나 21초 뒤 실패했다. Slurm step은
`94:0`, batch는 `31:0`이며 네 필수 출력은 생성되지 않았다. 동일 범위로 승인된 교정
제출 `1264261`은 CPU16·32GiB 할당 3초 뒤 batch `2:0`으로 실패했으며 Slurm step과
CMFGEN 실행은 없었다. 이 두 시도는 native line/heat output을 만들지 못했다. 이후
승인된 `1264295` 포획 결과와 별도 비교는 문서 첫 절에 기록했다. 새 수송·최종 물질
수용은 여전히 0회다.

원인은 제출 래퍼가 실행파일의 필수 활성화 환경변수
`LUMINA_FIXEDJ_HEAT_ONLY=1`을 전달하지 않아 `cmfgen_fixedj_heat.f90`의 fail-closed
가드가 `STOP 94`를 낸 것이다. 물리 입력/해시 오류나 다른 프로젝트의 취소가 원인은
아니다. 두 실패의 staging·로그는 보존했다. 전용 실행기는 배치와 `srun` 양쪽에서
활성화 변수를 지정하고, sealed 입력 해시와 `WRITE_RATES=T`를 확인한다. Slurm이 배치
스크립트를 spool 위치에서 실행한다는 점을 반영해 저장소 루트를 명시 인자로 전달하도록
고쳤으며, spool 모의 통합시험과 관련 57개 시험이 통과했다. 그러나 교정 단회 승인은
이미 사용했으므로 추가 제출에는 새 승인이 필요하다. 새 자기일관 수송은 이후 Syntax GPU
Slurm 단계지만 별도 승인 전에는 시작하지 않는다.

같은 날 계정의 Grammar·Syntax Slurm 회계에서 11월1일 이후 Lumina/CMFGEN 작업을
대조했다. 해당 범위에는 `CANCELLED` 기록이 없었다. Grammar의 관련 과거 작업은
완료 또는 별도 원인의 실패이며, Syntax에는 현재 실행 중인 Lumina/CMFGEN 작업이 없고
과거 `444706`, `447806`은 이미 기록된 DNS 실패다. 따라서 타 프로젝트 취소로 사라진
기존 관련 작업은 확인되지 않았다. `1264146`은 별개의 래퍼 설정 오류로 실패했으며,
그 교정 제출 `1264261`도 저장소 루트 탐색 오류로 srun 전 실패했다. 이는 타 프로젝트
취소와 무관하며, 추가 제출은 새 승인 대기다.

## fixed-J 실행파일 신원 대조 정정

기존 fixed-J 실행파일 SHA `a51c7e5c90b94b7d6e56cd586b426c73b2f3813d9096f894f0f4f776072812d9`를
보존 build들과 대조했다. 이전 인계에서 source `0d494…`와 `84e3…`를 서로 다른 upstream
판본으로 해석한 것은 부정확했다. 실제 job manifest는 input source `84e3…`, 패치 생성된
`cmfgen_sub.f` output `0d494…`, 실행파일 `a51c…`를 기록하며, 동일한 세 값이 보존된
Lageunha build manifest에서도 일치한다. 즉 `0d494…`는 fixed-J observer 패치 결과이고
`84e3…`는 패치 전 입력이다. 기존 실행파일/원본 자료는 수정하지 않았다. 이 신원 정정은
실행 권한을 새로 부여하지 않는다. `WRITE_RATES=T` capture의 첫 승인 실행은 job
`1264146`에서 래퍼 환경변수 누락으로 실패했다. 사용자가 동일 범위의 교정 단회를 승인해
`1264261`을 제출했으나, Slurm spool 위치에서 저장소 루트를 잘못 추정해 srun 전에
실패했다. 같은 단회 승인 범위의 재시도는 소진됐고 추가 제출은 새 승인 대기다.
