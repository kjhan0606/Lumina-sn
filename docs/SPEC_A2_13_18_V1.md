## 1. 공통 경계와 네 계약의 원자성

- A2-13~15는 A2-12의 `READY` GPU mirror만 소비한다. CPU 정본과 별개인 GPU owner,
  setter, generation increment 또는 raw-pointer 공개 API를 만들지 않는다.
- A2-16은 seed의 시간적 자격만 바꾼다. GPU 물리식, scalar owner lifecycle 및 출력
  철거는 각각 A2-13~15와 A2-17의 소유다.
- A2-17은 A2-08~16이 모두 폐합된 뒤에만 시작한다. 아직 살아 있는 물리 소비를 이름만
  바꾸거나 진단으로 재분류해 철거를 선행하지 않는다.
- A2-18은 물리식과 소유권을 고치지 않는다. 전량 재실행, 원장 감사, 상태 집계 및
  `docs/LAYER1_ENTRY_PREP.md` §6 갱신 절차만 소유한다.
- 한 계약의 allowlist에는 다른 계약의 observable을 넣지 않는다. 앞 단계의
  `BLOCKED`, `OUT_OF_ORACLE`, `NOT_RUN`은 그대로 계승한다.
- 구현 중 새 소비자가 나오면 `DISCOVERED_OUTSIDE_CENSUS`로 현재 파일·줄·call graph와
  처분을 추가한다. 목록 밖 발견이 0이어도 실행 명령과 0건 결과를 남긴다.

각 계약의 결과는 `INTERNAL`, `CHAIN`, `ORACLE_INPUT`, `NEGATIVE` lane을 분리한다.
내부 selftest PASS와 물리 L-gate PASS를 한 상태로 합치지 않는다. 공통 종료코드는
`0=요청 lane PASS`, `2=사용법/I/O/schema/hash/census`, `3=정직한 BLOCKED`,
`4=계산된 metric FAIL`, `5=금지 fallback/raw/stale/partial publish`로 한다.

## 2. 계약 I — A2-13~15 GPU 물리 이관

### 2.1 성공 정의와 선행조건

A2-13~15의 단일 계약은 다음과 같다.

> A2-12가 원자적으로 게시한 동일 generation의 GPU `RadiationField` mirror와
> `LineJbarCache` mirror만으로 GPU rate, signed opacity, emissivity·redistribution을
> 계산한다. BF는 A2-02가 선택한 전역 grid를 유지하고 BB는 A2-06의 checked
> `LineJbarCache` view를 그대로 소비한다. 각 하위 단계는 같은 입력으로 얻은 CPU
> oracle과 독립 비교하며, 한 하위 단계의 PASS로 다른 하위 단계의 FAIL/BLOCKED를
> 가리지 않는다.

필수 선행조건은 A2-12의 lifecycle 논리곱 전체 PASS다. `READY`, CPU/GPU/cache
generation, line ID, Q-set/profile hash, edge hash, frame, units, validity, upload byte
원장이 하나라도 맞지 않으면 kernel enqueue 전에 실패한다. A2-12가
`BLOCKED_GPU_UNAVAILABLE`이면 A2-13~15도 같은 사유를 계승하며 mock, CPU fallback 또는
A40으로 PASS할 수 없다.

하위 단계 경계는 유지한다.

| 단계 | 소유하는 물리 변경 | 독립 최종 gate |
|---|---|---|
| A2-13 | BF `Gamma`와 BB `Jbar/R_lu/R_ul` GPU 계산·SE rate assembly | L-1bf + L-1bb CPU/GPU oracle parity |
| A2-14 | signed ES/BB/BF/FF/total `chi_nu`와 event-measure 분리 | L-4 CPU/GPU parity |
| A2-15 | `eta_nu`, transition probability, redistribution CDF와 packet sampling | L-3 + L-5 CPU/GPU parity |

### 2.2 A2-13 BF와 BB의 서로 다른 정본 입력

BF는 선택된 전역 빈 경계와 공이동 bin-average `J_nu`를 그대로 사용한다.

\[
\Gamma_i=4\pi\int_{\nu_{0,i}}^\infty
 {J_\nu\sigma_i(\nu)\over h\nu}\,d\nu .
\]

CPU A2-05와 동일한 threshold partial-bin, 보간, 합산 순서와 validity 규약을 GPU에
이식한다. line-domain 제외 목록으로 BF coverage를 줄이거나 GPU 전용 grid, edge 이동,
단면적 보정계수를 만들면 FAIL이다.

BB의 유일한 복사 입력은 A2-06 `LineJbarCache`의 GPU mirror다.

\[
R_{lu}=B_{lu}\widehat{\bar J}_{lu},\qquad
R_{ul}^{stim}=B_{ul}\widehat{\bar J}_{lu},\qquad
R_{ul}^{sp}=A_{ul}.
\]

GPU는 `(generation,shell_id,line_id,profile_id,q_set_hash)`가 일치하는 cache cell을
checked descriptor로 조회한다. 다음은 절대 금지다.

- 선택된 coarse `J_nu`를 `sum(phi_b J_b Delta_nu)`로 다시 적분
- 192,922-bin fine 진단 histogram 또는 다른 fine grid를 runtime GPU 정본으로 도입
- legacy `d_jbar_line`, `j_blue`, `nlte->J_nu`, `d_W`를 cache 대용으로 사용
- cache miss, `UNSAMPLED`, stale, profile/Q-set mismatch를 0, floor, 이전 generation,
  Planck 또는 CPU 계산으로 대체
- net rate만 맞춰 큰 상·하향률 오류를 상쇄

cache count와 standard error는 수치 입력이 아니라 validity/진단 증거다. 이 값을 보고
active line을 사후 pruning하거나 `UNSAMPLED`를 `EXACT_ZERO`로 승격하지 않는다.

### 2.3 A2-14와 A2-15의 단계별 이관

A2-14는 A2-08의 signed publication 의미를 GPU에서 보존한다. signed net opacity와
nonnegative packet event measure를 다른 field/API로 유지하고, 음의 `chi/tau`를 abs,
zero 또는 floor로 바꾸지 않는다. A2-13의 rate kernel을 opacity 수정 명분으로 다시
고치지 않는다. CPU truth가 현재 `BLOCKED_MISSING_CHI_DATA`라면 GPU 내부/CPU parity는
기록하되 L-4는 같은 BLOCKED다.

A2-15는 A2-09의 component `eta_nu`, transition block, 유일 CDF와 RNG draw-count 계약을
GPU에 이식한다. `d_T_rad` Planck 재방출은 checked emissivity/CDF 또는 물질 `T_e`가
명시적으로 소유한 열 과정으로만 환원하며, scalar Planck 표본 fallback은 0이다.
line/free-bound/free-free component 합, 확률합, 에너지 closure와 packet histogram을
CPU와 각각 비교한다. `ETA_DATA`가 없으면 L-3/L-5는
`BLOCKED_MISSING_ETA_DATA`이며 internal parity PASS와 합치지 않는다.

### 2.5 validity, fallback 금지와 카운터

GPU descriptor는 `VALID`, `EXACT_ZERO`, `UNSAMPLED`, `STALE`, `OOG`, `MISS`,
`PROFILE_MISMATCH`, `QSET_MISMATCH`, `NONFINITE`를 손실 없이 표현한다. `EXACT_ZERO`만

### 2.6 3층 인수 프로토콜과 CPU oracle

각 하위 단계는 다음 세 층을 순서대로 통과한다.

1. **마이크로 fixture:** 100 packet 이하 또는 analytic deterministic cell/line으로 식,
   status, partial-bin, sign, CDF와 poison을 검사한다.
2. **변경파일 선별 회귀:** 같은 frozen input과 generation으로 CPU와 GPU component를
   1:1 replay한다. BF와 BB는 별도 report/status를 가진다.
3. **전량 마디:** A2-13~15에서는 full-NLTE GPU integration을 실행하되 캠페인 전량
   회귀는 A2-18에서 다시 실행한다.

A2-13 최종식은 다음과 같다.

```text
A2_13_PASS =
  bf_cpu_oracle_PASS
  AND bb_cpu_oracle_PASS
  AND bf_negative_controls_PASS
  AND bb_negative_controls_PASS
  AND no_fallback_static_and_runtime_PASS
  AND A2_12_lifecycle_still_PASS
  AND eligible_gpu_evidence_PASS
```

BF 또는 BB 중 한쪽만 맞는데 A2-13 전체를 PASS시키는 verifier 자체가 반드시 음성대조에서
FAIL해야 한다. 이는 개정서 §5.4-7의 직접 인수조건이다.

CPU/GPU 내부 parity는 bitwise가 가능한 integer/status/hash/count는 bitwise, double
합산은 CPU 식과 같은 정밀도·순서를 우선한다. 하드웨어 순서가 달라지면 구현 전에 analytic
bound를 등록하고 절대+상대 오차를 함께 쓴다. 이 허용치는 L-gate 과학 합격선을 완화하지
않는다.

물리 truth gate는 truth 쪽 절대 flow/기여로 99.9% 사전등록 활성집합을 만들고 다음을
사용한다.

- L-1bf: truth-side `f_cov>=0.95`, flow `E1<=0.10`, active `E_sym` P95 `<=0.25`,
  photoionization/stimulated/spontaneous 각 합계 오차 `<=0.10`.
- L-1bb: truth-side flow coverage `>=0.95`, `Jbar`, upward, stimulated downward 각각
  `E1<=0.10`, active `E_sym` P95 `<=0.25`, `A_ul` 상대오차 `<=1e-10`.
- L-4: truth-side `f_cov>=0.95`, shell `E1<=0.15`, 다섯 대역 `EB<=0.15`, component
  closure `<=1e-10`, negative-active 부호 mismatch 0.
- L-3/L-5: 확률합 CPU `1+-1e-10`, GPU `1+-5e-5`, 음수/NaN 0, L-3 CPU energy
  closure `<=1e-8`; L-5 `f_cov>=0.95`, shell/대역 오차 `<=0.15`, MC 95% CI 양립.

unmatched, stale, unsampled, OOG는 truth 분모에서 빼지 않는다. CPU 결과를 분모로 쓰거나
두 구현의 공통 교집합만 택해 `f_cov`를 높이면 FAIL이다. truth가 없으면 정확한
`BLOCKED_MISSING_*` 상태와 rc 3을 남긴다.

### 2.8 changed-output allowlist와 봉인

A2-13, A2-14, A2-15는 서로 다른 allowlist를 **각 하위 단계 첫 source 수정 전에**
canonical JSON으로 만든다. JSON과 GNU sha256 sidecar만 담은 seal commit을 먼저 만들고,
implementation-start manifest에 seal commit id와 JSON blob id를 기록한다. 모든 gate는
현재 JSON SHA-256, sidecar SHA-256, seal commit blob SHA-256의 3중 일치를 검사한다.

- A2-13: exact `(route-or-line,shell,component,direction)`의 BF/BB rate와 SE matrix cell.
- A2-14: exact `(component,route-or-line,shell,bin,event-measure-kind)`의 signed opacity.
- A2-15: exact `(channel,line-or-route,shell,bin,event-kind)`의 eta/CDF/fate/RNG draw.

identity는 금지다. CPU 값 자체, A2-16 seed, A2-17 lifecycle/output, A2-18 판정문은 이

## 3. 계약 II — A2-16 scalar seed를 generation 0에 격리

### 3.1 성공 정의

A2-16의 단일 계약은 다음과 같다.

> `W`와 `T_rad` scalar의 마지막 합법 용도는 generation 0의 초기 bootstrap seed를
> 만드는 일뿐이다. 런타임은 native `J_nu` seed만 읽고, legacy `(W,T_rad)` 덱은
> 오프라인 converter가 명시적 `J_nu` 배열로 변환한다. 첫 정식 field commit 뒤인
> generation `g>0`에서 scalar seed, seed 파일 또는 seed-derived pointer를 한 번이라도
> 읽으면 값과 무관하게 실패한다.

`src/lumina_atomic.c:826-829`의 `T_e/T_rad` ratio와 `:915`의
`opacity->t_electrons[i]=plasma->T_rad[i]`가 직접 표적이다. 후자는 원장 ID 156이며
generation-0 `T_e` 초기값으로만 격리한다. generation 0에도 rate, population, opacity,
emissivity 또는 transport의 물리 입력으로 scalar를 공개하지 않는다.

native seed schema는 shell boundary/ID, frequency edges, bin-average `J_nu`, units, comoving
frame, epoch, provenance, source hashes, per-cell validity를 가진다. shape/edge hash가 A2-02
선택 grid와 다르거나 `s44~s49` CMFGEN coverage가 없으면 해당 cell은 `valid=false`다.
이를 hold, extrapolation, neighbor copy 또는 zero로 채우지 않는다. 50-shell CMFGEN seed를
요구하면 `BLOCKED_INCOMPLETE_SEED_COVERAGE`다.

legacy converter는 runtime binary/library와 분리된 offline 도구다. 입력 `(W,T_rad)`에서
`J_nu=W B_nu(T_rad)` bin average를 실제 배열로 직렬화하고 provenance를
`DILUTE_PLANCK_LEGACY_APPROXIMATION`으로 기록한다. runtime loader에 legacy column parser,
scalar owner 또는 converter fallback을 남기지 않는다. `LUMINA_TRAD_COLOR_FIX`와
`LUMINA_TE_TRAD_RATIO`를 production에서 설정하면 무시하지 않고 obsolete-option 오류다.

### 3.2 generation state machine과 seed capability

구현 이름은 달라도 되지만 다음 capability/state가 명시적이어야 한다.

```text
SEED_UNOPENED -> SEED_G0_ACTIVE -> FIRST_FIELD_COMMITTED -> SEED_REVOKED

seed_read_allowed iff
  owner.required_generation == 0
  AND owner.computed_generation == 0
  AND no field commit has succeeded
  AND seed capability epoch/hash matches the loader manifest
```

첫 `RadiationField` dual-view commit이 성공하는 순간 capability를 먼저 revoke하고 seed
buffer를 zero/free한다. cleanup의 zero는 validity `EXACT_ZERO`가 아니다. commit 실패 시
generation을 1로 게시하지 않으며 seed를 무한 재사용하지 않는다. 재시도 정책은 manifest에
등록한 횟수 안에서만 가능하고 각 attempt를 기록한다.

generation `g>0`에서는 다음 모두 같은 금지 read다.

- `plasma->W`, `plasma->T_rad`, `T_e_T_rad_ratio`, `opacity->t_electrons` seed alias
- native seed mmap/file reopen, cached scalar/array, converter output의 seed handle
- `W B_nu(T_rad)` 재구성, fixed profile/TRAD-FIX, previous-generation seed
- `T_e` invalid/no-root 시 seed temperature fallback

진단은 generation-0 provenance/hash와 seed-vs-final 비교만 읽을 수 있다. 진단이 seed
pointer를 보유하거나 production call graph로 값을 반환하면 실패다.

### 3.4 static read-trace, validity와 카운터

static checker는 전체 `src`의 정의, allocation, assignment, argument, return, field access,
environment variable과 alias를 token/AST 또는 보수적 lexical+callgraph 조합으로 전수한다.
`src/lumina_main.c`와 `src/lumina_element_wide.c`를 파일 목록에 명시하고, glob 결과에서
두 파일이 빠지면 결과 수와 무관하게 실패한다. comments/string/diagnostic도 별도 category로
남겨 삭제한 production hit와 섞지 않는다.

필수 counter는 다음과 같다.

```text
seed_files_opened, seed_cells_loaded, seed_invalid_cells
legacy_converter_rows, legacy_converter_invalid_rows
g0_seed_reads, g0_te_seed_writes, first_commit_successes
```

### 3.6 allowlist, 회귀와 구현 순서

A2-17에서 zero-consumer 증명 뒤 수행한다. A2-17이나 Layer 1 문서를 미리 수정하지 않는다.

## 4. 계약 III — A2-17 scalar 생산자와 잔여 소비 철거

### 4.1 성공 정의와 시작 장벽

A2-17의 단일 계약은 다음과 같다.

> A2-08, A2-09, A2-10, A2-11, A2-12, A2-13, A2-14, A2-15, A2-16이 각각 자기
> 계약과 회귀를 폐합한 뒤, runtime `W/T_rad` production consumer를 0으로 만들고 scalar
> owner의 loader, producer/update, allocation/free, GPU mirror, output과 환경변수를
> 강등 또는 철거한다. 진단·비교 shadow는 정본 generation에서 즉석 파생한
> output-only 값만 허용하며 production call graph로 되돌아가는 API가 없어야 한다.

선행 단계 하나라도 `NOT_RUN`, `BLOCKED` 또는 미폐합이면 A2-17 source 철거를 시작하지
않고 `BLOCKED_UPSTREAM_NOT_CLOSED`다. 특히 A2-16의 generation-0 capability가 첫 commit
뒤 revoke된 증거와 A2-13~15 GPU read-trace가 필요하다. scalar 소비를 먼저 삭제해 upstream
gate가 실행 불능이 되게 하는 것은 폐합이 아니다.

최종 상태에서 `PlasmaState.W`, `PlasmaState.T_rad`, `d_W`, `d_T_rad`, scalar seed
array와 그 allocation/free/update/upload는 존재하지 않는다. 이름만
`color_temperature`, `dilution`, `radiation_fit`, `T_R`로 바꿔 같은 압축을
재도입해도 FAIL이다.

### 4.2 zero-consumer의 기계적 정의

다음 네 집합을 분리한다.

1. `PRODUCTION_READ`: rate/population/opacity/emissivity/thermal/transfer/packet/commit에
   값이 도달한다. 최종 허용 수 **0**.
2. `DIAGNOSTIC_DERIVATION`: checked `RadiationField`에서 generation-bound scalar
   summary를 즉석 계산해 출력한다. scalar owner 저장, 다음 호출 반환, cache 보존 금지.
3. `LEGACY_OFFLINE_CONVERTER`: A2-16 offline executable 안의 입력 token. runtime link
   graph와 분리되어야 한다.
4. `COMMENT_STRING_TEST`: 주석, schema label, poison fixture. 위치·이유를 전량 보존한다.

static proof는 lexical grep 하나의 0건에 의존하지 않는다. source inventory를 먼저
동결하고 field/alias assignment, parameter/return, function pointer, macro, environment,
serialization, allocation/free와 device symbol을 추적한다. 각 raw hit는 위 네 집합 중

### 4.5 producer downgrade/removal과 output 규약

철거 순서는 consumer 0 증명 뒤 producer다.

- runtime legacy loader와 fixed-profile/TRAD-FIX/ratio environment option을 제거하고
  설정 시 obsolete-option nonzero rc를 낸다.
- scalar fit/update/damping은 삭제한다. 비교용 `W_fit/T_fit`이 필요하면 checked field
  generation에서 local automatic 값으로 계산해 같은 statement에서 출력하고 폐기한다.
- CPU/GPU struct field, host/device allocation, upload/reset/free와 serialization column을
  제거한다.
- 기존 출력 소비자가 scalar 열을 요구하면 schema version을 올리고 canonical
  `J_nu` summary/provenance 또는 `T_e`로 의미를 명시한다. 빈 열, 0, NaN sentinel로
  열 이름만 보존하지 않는다.
- offline converter는 별도 executable/source manifest에 남길 수 있으나 production
  binary link map에는 없어야 한다.

diagnostic shadow는 물리 결과를 바꾸거나 RNG를 소비하지 않는다. output OFF 전후와 진단
ON/OFF에서 production artifact가 byte-identical이어야 한다.

allowlist는 첫 source 수정 전에 seal commit+JSON blob+sidecar 3중 SHA-256으로 봉인한다.
허용 변화는 exact struct field/symbol/link object 제거, obsolete-option error, output
schema에서 exact scalar column 제거, diagnostic provenance와 A2-17 counters뿐이다.
rate/population/opacity/eta/Te/spectrum/packet fate/RNG는 허용하지 않는다.

구현 순서는 다음과 같다.

1. A2-08~16 closure와 regression ledger 행을 검증하고 하나라도 미폐합이면 중단한다.
2. 전체 source inventory, 원장 157 ID와 raw/static callgraph census를 동결한다.
3. allowlist를 봉인하고 production read 0을 먼저 증명한다.
4. diagnostic을 canonical local derivation으로 바꾸고 escape/cache를 차단한다.
5. loader/update/env/output을 강등·제거한다.
6. CPU/GPU owner field와 allocation/upload/reset/free를 제거한다.
7. 157행 checker, zero-consumer/link-map/read-trace와 N17-1~8을 통과한다.
8. 신규 TU가 있으면 Z 네 build와 Z runner 별도 case를 배선한다.
9. A2-02~16, 모든 selftest, battery serial/parallel 전판을 재실행한다.
10. A2-17 대장 한 행과 구현 보고를 확정하고 계약-III commit 하나를 만든다.

A2-17은 L-gate 허용치, physics formula, seed converter 수식, Layer 1 문서 또는 A2-18
최종 판정문을 바꾸지 않는다.

## 5. 계약 IV — A2-18 통합 마디와 캠페인 종결 판정

### 5.1 A2-18이 하는 일과 하지 않는 일

A2-18의 단일 계약은 다음과 같다.

> A2-00~17의 frozen source/input/oracle manifest로 3층 인수 프로토콜의 전량 마디를
> 실행하고, canonical 157행과 단계 회귀 대장의 완전성을 감사하며, L-0~L-8 각 gate를
> `PASS` 또는 구체적 `BLOCKED_*`로 독립 집계한다. 그 사실을 바탕으로 A-2 최종 상태와
> 층 1 진입 조건을 서로 다른 필드로 판정하고 `docs/LAYER1_ENTRY_PREP.md` §6을 채운다.

A2-18은 rate, opacity, emissivity, transfer, seed, scalar owner 또는 허용치를 고치지
않는다. 전량 실행 중 발견한 결함은 해당 owning stage를 FAIL/BLOCKED로 되돌리고 수정은
별도 커밋으로 한다. A2-18 report만 고쳐 PASS를 만들 수 없다.

### 5.2 3층 인수 프로토콜의 전량 마디

마이크로 fixture와 변경파일 선별 회귀는 각 단계에서 이미 통과한 frozen artifact/hash를
재검증한다. A2-18은 다음 순서로 세 층을 하나의 DAG로 다시 실행한다.

1. **층 A — 마이크로/정적:** 원장, owner/read-trace, units/frame/generation/validity,
   analytic fixtures와 모든 poison marker/rc를 재실행한다.
2. **층 B — 변경파일 선별:** CPU replay, CPU/GPU component parity, two-seed transition,

다음 11개 gate를 정확히 이 순서와 이름으로 집계한다.

| L-0 | canonical field, O-PHYS field, scalar negative | `PASS` 또는 구체적 `BLOCKED_*` |
| L-1bf | PRRR 채널, truth-side flow `f_cov` | 동상 |
| L-1bb | NETRATE/TOTRATE 분리 상·하향률 | 동상 |
| L-2ion | POP/RVTJ 공통 shell·원소 이온분율 | 동상 |
| L-2level | level/superlevel crosswalk와 population | 동상 |
| L-3 | transition/energy closure와 ETA 연계 | 동상 |
| L-4 | signed CHI_DATA component/total | 동상 |
| L-5 | ETA_DATA component/total와 MC CI | 동상 |
| L-6 | free-T, LINEHEAT, heat residual | 동상 |
| L-7 | 내부 공이동 moment/flux | 동상 |
| L-8 | observer spectrum 단위/거리/적분 | 동상 |

각 행은 `status`, `reason_code`, `CHAIN`, `ORACLE_INPUT`, truth manifest/hash,
truth-side `f_cov`, metric/threshold, CI, negative marker/rc, source commit, artifact hash와
driver signoff를 가진다. `PASS`와 `BLOCKED_*` 외 `UNKNOWN`, 빈 문자열, `SKIP`,
`ASSUMED_PASS`는 최종 report schema FAIL이다. `OUT_OF_ORACLE`과 `NOT_RUN`은 원인에 맞는
`BLOCKED_*`로 정규화하되 원 상태도 보존한다.

현 준비 문서가 명시한 알려진 blockers는 다음과 같다. 실행 시 실제 truth가 도착하면
gate로 재판정하며 문구만 보고 PASS/BLOCKED를 복사하지 않는다.

- L-1bb `BLOCKED_MISSING_RATE_EXPORT`
- L-3/L-5 `BLOCKED_MISSING_ETA_DATA`
- L-4 `BLOCKED_MISSING_CHI_DATA`
- L-6 `BLOCKED_FIXED_T_AND_MISSING_LINEHEAT`
- A2-08 후속 maser arm `BLOCKED_NEGATIVE_OPACITY_SEMANTICS`

### 5.5 A-2 종결식과 BLOCKED 세탁 금지

```text
A2_18_PASS =
  all_A2_00_through_A2_17_contracts_closed
  AND ledger_157_complete
  AND regression_rows_19_complete
  AND all_micro_and_selective_regressions_PASS
  AND full_node_regression_PASS
  AND every_L0_through_L8_status_PASS
  AND seed_independence_PASS
  AND cpu_gpu_equivalence_PASS
  AND scalar_zero_consumer_PASS
  AND all_negative_controls_PASS
  AND no_forbidden_fallback_or_guard_hits
```

하나라도 `BLOCKED`, `NOT_RUN`, `OUT_OF_ORACLE`, missing artifact/signoff, invalid eligibility,
truth coverage 미달 또는 음성대조 미실행이면 `A2_18_PASS=false`다. `BLOCKED`는 실패가
아니라 외부 조건 미충족 상태일 수 있지만 PASS도 아니다. 다음 세탁은 verifier 위반 rc 5다.

- internal PASS와 truth BLOCKED를 AND가 아닌 OR/최선 상태로 집계
- 하류 spectrum PASS로 상류 L-gate FAIL/BLOCKED를 덮음
- 11개 gate를 평균/총점으로 합쳐 한 gate FAIL을 상쇄
- BF/BB, CPU/GPU, seed A/B 중 한쪽만 실행하고 전체 PASS
- missing/unsampled/unmatched를 truth 분모에서 제거해 `f_cov`를 높임
- scheduler/fixture 미확보를 `SKIP`, `NOT_APPLICABLE`, `PASS_WITH_WARNING`으로 변경

최종 status는 `PASS`, `FAIL_<reason>`, `BLOCKED_<reason>` 중 하나다. report process rc는
PASS 0, schema/I/O 2, BLOCKED 3, metric FAIL 4, 세탁/fallback 5다.

### 5.6 층 1 진입 조건 판정

A2-18 물리 PASS와 층 1 진입 결정은 같은 boolean이 아니다. 두 필드를 반드시 분리한다.
`docs/LAYER1_ENTRY_PREP.md` §7이 열거한 고리 안쪽 blocker는 정직하게 BLOCKED로 남아도
입력축 감사인 층 1의 `_ftos` 재측정을 막지 않는다. 그렇다고 A2-18을 PASS로 바꾸지는
않는다.

```text
layer1_entry = READY_FOR_FTOS_REMEASUREMENT iff
  A2 structural ownership migration A2-00..17 is closed
  AND ledger/read-trace/regression infrastructure is complete
  AND canonical J/grid/Jbar/rate/population interfaces needed by Layer 1 are usable
  AND every remaining BLOCKED item is explicitly listed with owner and reason
  AND no remaining blocker invalidates the _ftos input-data census itself

layer1_entry = BLOCKED_A2_STRUCTURAL_INCOMPLETE
  if any ownership/zero-consumer/generation/ledger contract is incomplete

layer1_target_judgment = FORBIDDEN_PENDING_FTOS_REMEASUREMENT
  until docs/LAYER1_ENTRY_PREP.md §3의 _ftos 전면 재측정이 완료
```

즉 `READY_FOR_FTOS_REMEASUREMENT`는 A2-18 PASS의 별명도, L-gate BLOCKED의 세탁도 아니다.
층 1에서 I1~I17의 새 판정을 내릴 자격은 `_ftos` 전면 재측정 뒤에만 생긴다. 구 덱
`_sivcaiv` 수치를 재사용하면 Layer 1 entry audit FAIL이다.

### 5.7 `docs/LAYER1_ENTRY_PREP.md` §6을 채우는 절차

A2-18 구현자는 대상 문서를 먼저 SHA-256으로 동결하고 §1~§5, §7~§8을 수정하지 않는다.

2. L-0~L-8 11행 표: §5.4 필드 전부와 PASS/BLOCKED 이유.
3. scalar 종결 요약: canonical 157/157, production reads 0, diagnostic/offline counts,
   `lumina_main.c`/`lumina_element_wide.c` 포함 scan hash.
4. GPU 요약: h200/h100 job 종결 상태, GPU UUID/memory, CPU/GPU gate status 또는

7. 마지막 machine-readable 한 줄과 운전석 서명/시각.


`PASS`, `N/A`, em dash로 채우지 않는다. §6 갱신 diff 자체가 물리 source 변경과 섞이면
