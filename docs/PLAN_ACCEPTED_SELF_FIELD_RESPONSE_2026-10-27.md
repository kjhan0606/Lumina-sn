# 새 복사장·물질응답·CMFGEN 비교 묶음

사용자의 2026-10-27 「새 복사장 계산과 물질응답, CMFGEN 비교까지 하나의 묶음으로 계속 진행」 지시를 실행한다. 운전자가 구현·시험·실행·재현을 맡고, 직전 Astra 계획을 이어 사용한다. 목표는 수용 물질1224249에서 만든 자체 복사장이 Si/S 및 열·전하 응답을 어떻게 바꾸는지 확인하는 것이다. 입력 연결이나 단위시험만으로 묶음을 종료하지 않는다.

## 입력과 범위

- 수용된 evaluation-3, 응답 SHA256 `d0933f1884f3aaca940f1874cf4fbf02c9394bb3f09601a9211ba2757b042146`.
- 별도 새 물질 manifest SHA256 `61e3090a8550bffb6e6f030a84be811407634299eefba93036d1fad30d492c1b`, 실제 C full 출력 SHA256 `2ce239bd5d39e994e2cca0a46b283d8ccb68fc17a60bbaabcc58c9291de22ea6`.
- 원90점 반경·밀도·epoch·원자모형·1115020개 주파수를 유지한다. 계수와 내부 경계는 새 T/ne/SL에서 생산한다. 이전70 계수의 이름·header만 바꾸지 않는다.
- 같은 물질에서 완성 F1의 J를 F2에 전달하며 전자산란과 외부대기를 다시 결합한다. 이전 광선 checkpoint는 넘기지 않는다.
- 마지막 완성 J로 BF·BB·FF를 다시 계산하고, 수용 T 고정의 전원소 SE/공통 전하 응답, physical/native 열장부와 Si/S 분포를 비교한다. 이전 J70 율은 새 응답에 재사용하지 않는다.
- 새 native CMFGEN 재실행, released-T 기준해 확보, observer 스펙트럼, 무제한 물질/수송 반복은 포함하지 않는다.

## 자원과 보존

이번 지시로 진행하는 새 묶음의 상한을 다음처럼 제한한다. 이전 완료 작업을 중복 제출하지 않는다.

자원 상한은 시간 내 완료 보장이 아니다. 후속 소비 코드와 실행시간 적합성 검토를 마친 뒤 각 실제 계산을 제출한다. 한도 밖 연장·중복 재실행은 하지 않는다. 새 디렉터리와 봉인 소스로 실행하며 원70·수용 후보·부분 출력은 보존한다. 단일 상태 계수의 알려진 메모리 할당 상계는16.72GiB, 출력 예약량은12.99GiB이며 실제 RSS 측정치는 아니다. GPU 원출력과 후속 Jbar/율 출력도 별도 새 디렉터리에 둔다.

## 결과 판단

1. 실제 새 계수·경계·완성장·물질응답의 계보가 이어지고 전90점·전원소가 빠지지 않아야 한다.
2. 전하와 SE 잔차, 두 열장부, F1/F2 변화, native 끝점 flux, Si II/III 및 S II/III와 전체 이온 분포의 절대값·차이를 함께 낸다.
3. CMFGEN70은 고정T 미수렴 참조임을 표시한다. 같은 좌표 비교와 주파수 연산자 차이를 구분하고, 새 장의 변화와 최종 동등성 판정을 혼동하지 않는다.
4. 유한2F는 산란 수렴이 아니며 그 뒤 물질응답도 새 물질과 복사장의 공동수렴이 아니다. native 끝점 flux를 observer 스펙트럼으로 부르지 않는다. 최종 v2 목표는 미달성 상태로 유지한다.

재현 진입점은 `submit_lumina_accepted_sources.slurm NEW_PARENT EXACT_COMMIT`, `run_lumina_resident_field.sh NEW_GPU_ROOT 43200 --feedback ...` 및 후속 새 J 소비기다. 후속 소비기는 구현·직접시험 후 정확한 명령과 입력 해시를 실행 기록에 추가한다. 이 문서의 예시를 완료 증거로 쓰지 않는다.

## Astra 후속 소비 계약과 운전자 반영

기존 Astra 세션 `01a17b0c-eb28-7500-9a0c-fdd824e20a8d`에 새 J 소비 계약과 후처리 비용만 한 번 문의했다. 최초 호출 요청 모델은 `gpt-6-astra`이며 실제 배포 ID는 응답자가 확인할 수 없다고 밝혔다. 코드 변경이나 계산 실행을 위임하지 않았다.

- 새 BF/FF는 원1115020ν의 trapezoid 가중치와 `evaluation=frequency`를 사용한다. BB는 같은 J의 선형ν 표현을 원 프로파일과 적분한다. 이전 CONT_FREQ 대응·old J·재빈닝·범위 밖0 채움은 사용하지 않는다.
- CMFGEN70과의 차이는 장·격자·연속흡수 평가 방식이 함께 바뀐 총차이다. 이를 순수 장 변화나 격자오차로 분해한 측정이라고 하지 않는다.
- 최초 전체 BF 적분1회 뒤에도 매 trial의 필수 pseudo 적분과 인수분해 불가능 경로의 직접 재적분은 수행한다. 이것도 총2시간·최대8평가에 포함한다. 정확성에 필요한 적분을 생략해 한도를 맞추지 않는다.
- 후속 BF/FF의 J 소유 복사본·Jbar·율·SE 작업공간은 계수 생산 재고와 별도로 산정한다. 2시간은 실측 완료 보장이 아니며, 한도 도달 시 부분 증거를 보존하고 묶음 미완료로 남긴다.

사용자가 후속 물질응답에 한해서 최대4시간을 명시적으로 승인했다. 기존19.7만ν BF 약27분을 새111.5만ν에 단순 비례하면 약2.5시간이므로, 최초2시간 계획을 위 표처럼 수정한다. 이는 완료시각 보장이 아니며 CPU16/32GiB·단회·최대8평가·재시도0은 유지한다. 계수2시간과 GPU총12시간은 확대하지 않는다. 위 Astra 자문의 2시간 표현은 변경 전 검토 이력이다.

## 대기 없는 단회 작업 연결

서로 다른 Slurm 클러스터이므로 계수 완료의 `afterok` 제출 작업 하나가
syntax GPU 작업을 제출하고 종료한다. 이 제어 작업은 grammar CPU1·1GiB·
최대2분·GPU0이며 과학 계산을 하지 않는다. polling/background 대기 루프는
없다. GPU 실행 종료 후 마지막 완성 J가 있으면 grammar 물질응답을 한 번
제출한다. 완성장이 없으면 제출하지 않는다. 제출 전에 시도 기록을 독점
생성하므로 SSH 응답이 유실돼도 자동으로 재제출하지 않는다. 코드·인수는
별도 고정 구성과 해시로 보존하며 기존 단회/시간 상한을 늘리지 않는다.
