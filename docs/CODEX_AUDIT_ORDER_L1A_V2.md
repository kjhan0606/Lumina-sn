| **6. 완성 후 L1-B 발주 가능 여부** | **반박** | v1의 7개 선행조건과 v2를 `rg` 대조했다. `canonical current specimen`, component별 epoch matrix, `source_tree_sha`, build command/toolchain/env manifest, current collision SKIP policy는 모두 `NO MATCH`. §4b–d에는 golden manifest·음성대조·자원 요구가 있고, §4e에는 R1 검증기가 있으나 첫 검증기 이름이 틀렸고 stale 로그가 남았다.<br><br>실행한 R1 검증기는 level/rank identity와 line bit identity를 PASS했으므로 I12 level/line gate의 실체는 존재한다. 그러나 §3의 “등록 18개”에는 I12가 없고 그 PASS를 I12 record/B gate에 결속하는 계약도 없다. | v1 선행조건별 피복은 다음과 같다.<br><br>① canonical current specimen 선언 — **안 덮음**.<br>② component별 epoch matrix — **안 덮음**; 좌·우당 단일 `epoch`뿐.<br>③ I12 level/line identity gate — **부분**; 실제 R1 gate는 PASS하지만 I12 레코드·인수조건 결속과 macro topology가 없다.<br>④ I15 build attestation — **안 덮음**; 발주서도 별건임을 인정한다.<br>⑤ current collision `SKIP` 정책 — **안 덮음**; census만 내고 처분은 별건이다.<br>⑥ golden/음성대조/자원 게이트 — **의도상 덮음**, 그러나 §3 필드·교차제약과 1%/full benchmark가 빠져 부분이다.<br>⑦ I17 두 verifier 실행계약 — **부분**; R1은 실재하고 PASS하나 R4 이름·필수 인자·stale 갱신이 틀렸다.<br><br>따라서 계측기 완성만으로 L1-B를 발주할 수 없다. 최소한 I15 별건 attestation 완료, canonical specimen/epoch matrix, I19 SKIP 정책, I12 gate 결속, 수정된 I17 R4 PASS가 선행돼야 한다. |
| **7. v1 권고 누락 여부** | **반박** | `rg` 대조 결과 v2가 채택한 것은 3엔진 분리, typed per-metric record, 13종 이름, memmap/chunk, golden manifest의 command/version/expected denominator/checksum, 엔진별 음성대조, I5a/b·I6·I9 분해, I15 왜곡 철회, I16 부분해소 선언이다.<br><br>반면 `rg -ni 'NOT_APPLICABLE|evidence_status|NOT-ASSESSED|INCOMPARABLE|1% fixture|full-run benchmark|endianness|ULP distance|canonical current specimen|current collision.*SKIP' docs/ORDER_L1A_INSTRUMENT.md` → 전부 `NO MATCH`.<br><br>또한 §3에는 v1이 요구한 component epoch, build/source/toolchain/env, 실제 소비파일 allowlist manifest, per-entity presence/evaluator 상태가 없고, §4e는 존재하지 않는 CLI 이름을 다시 적었다. `precision.threshold`와 `dtype`은 필드 없이 제약에서만 참조된다. | v1 권고 중 다음을 복구해야 한다.<br><br>① component별 epoch와 build attestation.<br>② `UNKNOWN/NOT_APPLICABLE` 및 `evidence_status=VALID/STALE/FAILED/MISSING/MIXED`.<br>③ ID×specimen별 독립 상태와 실제 소비파일 allowlist/manifest SHA.<br>④ `ion_present/quantity_present/counterpart_present/evaluator_supported`.<br>⑤ I1의 “구 tabulated 수치”와 “현 NO-COUNTERPART/fallback” 별도 metric.<br>⑥ PHOT type 2/3/8 unsupported 분모의 명시적 계약.<br>⑦ `NOT-ASSESSED/INCOMPARABLE`, `CLOSE/NONE` 등 사후 판정 어휘와 cardinality.<br>⑧ 1% fixture와 full-run benchmark.<br>⑨ dtype·endianness·ULP distance 및 실제 threshold 필드.<br>⑩ canonical specimen, collision SKIP 정책, I12 identity PASS의 B-gate 결속.<br>⑪ 실제 R4 검증기 이름·필수 인자와 stale 로그 갱신.<br><br>방향 전환 자체는 타당하지만, 계측기가 오늘의 잣대 사고를 기계적으로 차단하려면 위 항목은 명세 팽창이 아니라 실행 가능한 schema/gate 계약으로 남아야 한다. |
