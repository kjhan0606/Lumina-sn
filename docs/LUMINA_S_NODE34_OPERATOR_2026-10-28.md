# 원34점 S 동일 입력 SE 연산자 비교 — 2026-10-28

## 목적과 범위

Si/S 분포의 CMFGEN 불일치 원인을 좁히기 위해 원70의 같은 인구·T/ne·J에서
원34점 S의 C 입력 잔차와 기존 native raw SE를 준위별로 대조한다. 새 온도·
인구 solve, BF/BB 적분, 수송, native 실행, 전역 물리 판정은 하지 않는다.
실제 생산 C roster와 native의 이산 BB roster가 완전히 같다고 가정하지 않는다.

기존 완료 BF90·선율90·원자/물질 snapshot과 원70 native witness를 재사용한다.
운전자가 C 조립기의 기존 행렬에서 초기 인구에 작용한 raw 잔차 및 BF복사,
BF충돌, BB복사, 전체 충돌과 용해 충돌의 유입·유출만 비교 전용 API로
추출한다. 용해는 전체 충돌의 부분집합이다. 기본 생산 API나 물리식을
바꾸지 않고 비교 전용 매크로로만 빌드한다.

원자주소·원70 인구·T/ne·복사장·기존 입력 SHA와 전 경로 완결성, 행별
raw와 과정 흐름의 합, 기존 원34점 C ledger의 최대 정규화 잔차 재현을
확인한다. native와 C가 다른 BB 계약을 사용할 수 있으므로 우선 차이와
과정 범위를 밝히며 차이가 특정 구현의 오류라는 판정은 하지 않는다.
결과에는 정확한 입력·소스·바이너리 신원과 재현 명령을 포함한다.

Lageunha 수동 CPU1·4GiB·외부180초·GPU0·단회·재시도0으로 새 전용 root에만
빌드와 평가를 수행한다. 기존 결과·원본·진행 중인 다른 작업은 보존한다.
미완료면 부분 출력만 보존하고 자동 재시도하지 않는다. 이미 계산된 native
witness는 다시 생성하지 않는다. 최종 Si/S·RE·수송·observer 목표는 NOT_MET다.

## 해석과 다음 확인

이 결과는 원34점에서 차이가 주로 이온 단계 내부의 준위별 균형에 나타남을
보여준다. 다만 서로 다른 BB 선 목록·선 프로파일 계약이 결과에 포함되며,
native의 과정별 고정밀 분해가 아직 없으므로 BB 구현 오류나 특정 충돌
기작을 원인으로 확정할 수 없다. 단계 순유입이 거의 같다는 사실도
정상 이온화 분포가 같다는 증거가 아니다. 다음에는 동일 native BB 계약을
사용해 같은 원34점의 잔차를 비교하고 남는 차이를 과정별로 좁힌다.

재현은 고정 실행 디렉터리의 `source`와 `build/bridge-probe.so`,
`source-sha256.txt` 및 결과 JSON의 입력 SHA를 사용한다. 생성된 결과는
덮어쓰지 않고 새 출력 경로를 지정한다. 위 수치는 진단의 완료이지 CMFGEN
분포나 최종 스펙트럼의 목표 달성이 아니다.
