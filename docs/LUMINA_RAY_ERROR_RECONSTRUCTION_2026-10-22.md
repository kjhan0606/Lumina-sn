# 최종 J·생산 Si/S율을 위한 경로 오차와 재구성 조사

## 목적·범위

원 묶음의 산출물은 native90 자체J1/J2·J1 실제잔차·생산Si/S율이며, 최종목표는 CMFGEN과 이온분포/스펙트럼/물리량 동질성이다. 현재434043은 원13003 구간의 새 적분 후보를 실행중이다. 그 계산을 중단·변경·중복하지 않고, 뒤따를 전체장·생산율 단계가 국소오차 통과를 최종오차로 오해하지 않도록 실제 코드와 작은 합성 반례를 조사했다. 이 문서는 원묶음 완료 기록이나 새 실행 승인/감사 게이트가 아니다.

코드/실행/재현은 운전자 Codex, 의미 있는 기획·평가는 Astra 담당이다. Astra `01a161e4-570d-77c0-8f33-a29ed21acf73`의 공개추상수학 자문은 완료·종료했다. 소스/원자료/도구 접근은 의뢰하지 않았으며 아래는 자문 요지의 한국어 정리다. 원 응답을 실제코드감사·실행승인·수치수용으로 표시하지 않는다.

## 확인된 현재 연결과 한계

`lumina_native90_rates.py`와 `compare_lumina_checkpoint_rates.py`의 생산율은 순χ가 아닌 실제 `chi_abs`, `chi_stim`, `eta_spont`를 분리하고, 같은 native90 물질·전체준위인구/PHOT route·같은주파수에서 `4πΔν/(hν)` 양의가중합을 사용한다. 고정물질의 BF율비교이며 SE_RE/이온분포/스펙트럼 합격으로 표시하지 않는다. 이 소비 경로 자체는 이미 존재한다. CPU native90 캠페인은완성J1/J2를이경로에연결하지만 새선택GPU후보의전체장캠페인연결/검증은아직미완이다.

`cmf_linear_cuda.cu`의 `forward`는 각 구간을 시작할 때 수치오차를0으로 두고 **그 구간 안**의 공간잎들을T상계로 합성한다. `backward`는 그 구간 출력별추정오차를 `frequency_errors`에 쓴다. `lumina_gpu_linear.py`의 다음구간 재구성은 이전ray값만넘기며 이전구간오차를 입사불확실성으로받지않는다. `cmf_linear_cuda_aux.cu`의 각도관측누적은JHK값만쌓는다. 따라서 `field`의 `maximum_estimated_error_ratio`는 구간별추정량의최대일뿐 전체광선/J/PHOT의오차상계가아니다. 기존이름도전역인증을주장하지않으며 이를새로인증으로해석하면안된다.

기존8점재구성은7차Lagrange→Bernstein이다. 음의control이있으면양끝선형control과의공통혼합계수θ를최소비율로정하고,전체control을함께낮춘다. θ의nextafter와선형fallback이있지만 작은반올림에대한분기안정성이나연속성을보장하지않는다.

## 원 구현의 합성 반례 — 물리데이터 원인과 구별

CPU root `/gpfs/kjhan/cmfgen_runs/lumina_reconstruction_condition_20261022-x0BgnX`에서 원헤더를바꾸지않고 같은산술을호출했다. CPU1/1GiB/90초상한이며실제조사0.399초/171입력, GPU0·물리수송0이다. 독립기준은Fraction으로Lagrange기저와Bernsteincontrol/정확한limiter를유리수계산한다. 실제자료나CMFGEN장은사용하지않았다.

`p(x)=x²(1-x)²`의8개표본(x=-3..4)은 `[144,36,4,0,0,4,36,144]`이며 비음수다. x=0.5의 원래 다항식 및 정확한limiter값은0.0625다.

| 입력 | 원binary64 구현 | 정확한limiter 기준 |
| --- | ---: | ---: |
| 위 표본 그대로 | 0 | 0.0625 |
| 세 번째4를3.9999999999999996으로(차4.44e-16) | 0.06250000000000033 | 0.06250000000000006 |
| 세 번째4를4.000000000000001로(차8.88e-16) | 0 | 0 |

첫입력에서정확히0인인접control이-2.7755575616e-17로계산돼θ=0이되고유한한양의내부값까지모두0이됐다. 이는원binary64산술의잘못된분기다. 한편마지막행은정확한limiter도0이므로 **계수정밀도만높여도수학적제한자자체의불연속까지해소되는것은아니다**. `2^-500/1/2^500` 스케일에서도정규화출력이0~0.0625로갈렸다. 이는재구성알고리즘의합성조건민감도이며 **실제native90에서발생빈도/현재13003실패/Si-S 또는CMFGEN불일치의원인을입증한것은아니다**. 현재13003은J0=I0=0인단일구간으로,후속전체광선의재구성문제와같다고단정하지않는다.

관측JSON SHA256 `4a9e114ac96d74e58e5f2b82cfebec45b4e393629f207297f7e93e8981d2524e`, probe바이너리 `dd2e70f203a7bbdc9d68e2685014d8cc11d1eb759906e6e2e625c57418a4e7aa`다. 입력헤더·probe·실행기해시는JSON에저장했고조사전후불변을확인했다.

## 다구간 오차 반례

`test_lumina_ray_error_contract.py`는 기존양의Map대수로 다음논리적반례를 확인했다. 참T=1/source=0인데근사T=1+5e-6,logT불확실성=log(1+5e-6)인30개구간을쌓는다. 참T는각불확실성안에있고각구간의반환오차는출력의1e-5이하다. 그래도최종편차는약1.5e-4로1e-4를넘는다. T상계와오차를경로전체에합성하면이편차를감싼다. 세크기 `1e-80/1/1e80`에서 **3통과/0.02초**다. 이는현재생산광선오차의실측이아니라 국소통과→최종PHOT통과의추론이성립하지않음을보이는작은해석적반례다. 로그SHA256 `bf22e88f0e3a0e89eddb09d252b1661a48c9dfc4bd5aa177b5efca41f2700a18`.

## Astra 요지·다음 실제 구현 범위

1. 현재주장가능한것은고정입사장/현오차추정기범위에서의구간별결과다. 최종J오차가있어야고정실흡수계수의 `Σw E_J + 축약반올림`으로PHOT오차를계산할수있다. SE/물질/κ갱신오차나독립물리기준동질성까지자동포함하지않는다.
2. 구간간최소상태는광선의입사불확실성이다. 원천/투과율의같은양의스케일을유지하며 `E_out <= T_upper E_remap + e_local`로전파한다. E_remap은이전구간오차·주파수재구성결함·반올림·도달가능한limiter분기를포함해야한다. 고정분기의절댓값가중합을다른분기까지그대로적용하면안된다. 이퇴화점에서오차포락선이큰것을임의의floor/tolerance로작게표시하지않는다. geometry가추정이면전파후에도추정이며인증으로격상하지않는다.
3. 광선O(NF)오차상태와관측점에서의실제고정PHOT가중축약을활용하면큰90×NF추가배열을피할여지가있다. J/K는양의가중합이지만H는상쇄가있어절댓값기여/반올림까지따로다뤄야한다. 상대오차저장은I=0/E>0,약한출력,gain을숨기면안된다. 실제16GiB/활성1GiB동시버퍼검증전에는자원적합을보장하지않는다.

**다음수리목표는측정기추가가아니라, 안정적인양수재구성과광선오차전파를자체J1/J2·실제Si/S율까지연결하는것**이다. 현광학깊이수리의전주파수결과를우선확인하고,원수학적limiter의불연속과binary64오판정을구별한수리안을한묶음으로정한다. 단순epsilon허용·물리값clamp·더높은정밀도만으로두문제를모두해결했다고하지않는다. 현재수송은그대로마무리하고,새물리기준/자원확대/완성장실행을이조사만으로추가하지않는다. 작은단계별감사나새PASS게이트도추가하지않는다.

재현은새격리root에서 `lumina_reconstruction_condition.py <root>`(원헤더+probe필요) 및 `pytest tests/test_lumina_ray_error_contract.py`를lageunha CPU1에서수행한다. 원헤더/생산수송은이조사에서변경하지않았다. 원묶음·최종목표는active/NOT_MET다.
