# S III 대역 흐름을 같은 native49 인구로 비교 — 2026-10-28

## 결과와 한계

과거 대역 비교는 native49 복사장에 물질 셀39의 인구 가중치를 공통으로 썼다.
그 조건부 수송 대조는 보존하되, 그 부피 흐름을 native49 이온당율로 읽을 수는
없었다. 이번에는 **같은 원래점의 물질·복사장**을 연결했다. 전 주파수 적분이나
새 이온분포/SE/RE/수송 계산으로 범위를 바꾸지 않았다. 최종 목표는 **NOT_MET**다.

- 원 물질70, 참조장71의 native49(0기준,50번째 점), 반경 `2.082979299729e15 cm`.
- 정확한 C full population을 소비했다. 전체2,208,780값의 독립 재구성과 최대차0.
- S III 수밀도 `6.229242051001367e7 cm^-3`, PHOT256경로·600–750Å의5196점.
- 양의 광흡수 계수로 수축한다. 유도 방출을 빼는 순χ를 사용하지 않는다.
- 실제 원 주파수에서 평가하며, 용해항은 과거 비교와 같은 opacity 소비 규약이다.
  native-SE의 CONT_FREQ cache 규약이나 전주파수 순이온화율의 동등성을 주장하지 않는다.
- 같은 식으로 과거 셀39 가중치를 재생산한 최대 상대차0. 주소 외의 식 변경을
  섞은 비교가 아니다. legacy F는 당시 물질70의 저장장이며 최근 F2가 아니다.

| 저장 복사장 | 과거 셀39 가중 흐름(cm⁻³s⁻¹) | 같은 native49 인구의 흐름(cm⁻³s⁻¹) | native49 S III당 부분대역 광흡수율(s⁻¹) |
|---|---:|---:|---:|
| 원 CMFGEN SC | 225.350055 | 178.196083 | 2.860638282e-6 |
| 기존 공간128 조건부 CMFGEN | 368.476226 | 292.084044 | 4.688917875e-6 |
| legacy Lumina F | 393.550723 | 312.252332 | 5.012685811e-6 |

같은 native49 인구에서 F/원SC=`1.7522963`, F/공간128=`1.0690496`이다.
F와의 signed 흐름 차이는 `134.056250 → 20.168288 cm^-3 s^-1`로 줄어들며,
원 차이의84.955%에 해당한다. 이는 **선택한 부분대역·고정 물질·조건부 계산의
차이 감소**이지 전체 물리 오차의85%를 수리했다는 뜻이 아니다.

주소를 맞춰도 공간128 대비 약6.9% 차이는 남는다. 따라서 잘못된 위치의 인구
분모만이 원인이라는 설명은 지지되지 않고, 급변하는 셀 내부 재구성의 큰 영향은
유지된다. 기존 F와 원 SC의 각도·외부층·공간/주파수 이산화 차이는 여전히 남는다.
공간128 하나를 연속 한계나 수렴 기준해로 선언하지 않으며, 부분대역 비가10% 안에
들었다고 v2의 전주파수 Γ·활성집합·스펙트럼 기준을 통과시킨 것도 아니다.

## 실행·재현

동시에 변경 중이던 대역 수송 파일은 수정하거나 중복 실행하지 않았다.
대신 `reweight_cmfgen_native_band.py`와 작은 직접시험만 추가했다. 계획 범위는
기존 완료 스펙트럼을 실제 native49 인구에 재가중하는 것이다. 입력/원본·과거
셀39 결과를 보존하고 새 전용 root에만 쓴다. CPU1·4GiB·180초·단회·재시도0이다.
대역 양끝에서도 잘라낸 격자의 폭을 새로 만들지 않고 **전 원격자의 사다리꼴 폭**을
유지한다. 잘못된 이온 분모·장 크기·음의 계수와 이 끝점 규약의 직접시험3개가
lageunha에서 통과했다.
관련 PHOT/Milne·저장장 소비·재가중 회귀는 같은 서버의 CPU1 스레드 환경·
4GiB·120초 한도에서 **84 passed/9.03초**였다.

lageunha에서 수동 실행은 exit0·11.255초였다. 새 수송0회·SE/RE 갱신0회·전역 BF
적분0회이며, 같은 native49의 부분대역 흡수 가중치만1회 만들었다. 실행 root는
`lumina_native_siii_weight_20261028-oV548b`이며 `driver.py`에 실행 코드를 보존했다.
필요한 정확한 원자료 경로·해시는 `result/native-band-rates.json`에 들어 있다.

| 실행 root의 상대 경로 | SHA256 |
|---|---|
| `result/native-band-rates.json` | `6f9505e3f0e0c37edd45fad7ba4e598a2871bd11764d2e4ecab413be3acb24e9` |
| `result/native-band-weights.npz` | `4e7c219d0fedf4dc12f505407aecfc9ef8918596428d8784b322baaeead99f8b` |
| `driver.py` | `15449ccf7203e9cc1f60934f4c124fcb10220ac4cf1b58e3a25e1440dfa61869` |

저장된 새 가중치를 별도 `np.dot`으로 재수축한 최대 상대차는 `9.57e-16`이었고,
같은 이온 수밀도로 나눈 세 이온당율도 재현했다. 이것은 저장율 집계 재현이지
외부 독립 감사나 물리 정상해 판정이 아니다.

재현은 존재하지 않는 새 출력 경로에서만 수행한다. `BASE`는 기존 원70 native
계수 계획, `OLD_WEIGHTS`는 과거 `reference-weights.npz`, `REFINED128`은 완료
`full-band-sub128.json`이다. 세 입력 SHA는 생산자와 본 결과에 고정돼 있다.

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  python3 scripts/reweight_cmfgen_native_band.py \
  --base "$BASE" --weights "$OLD_WEIGHTS" --refined "$REFINED128" --out NEW
```

다음 대역 수송의 전5196점이 완성되면 이 native49 가중치를 재사용한다. 부분
prefix만 있는 장에 전체 대역율을 붙이지 않고, 완료장 하나를 얻기 위해 같은
원자 가중치를 다시 만들지도 않는다. 이 비교를 새로운 F2 물질응답이나 최종
Si II/III·S 이온분포/observer 동질성으로 표시하지 않는다.
