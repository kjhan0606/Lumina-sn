# 원자데이터 덱 재생성 설계 (I17 수리)

캠페인 「고리 밖 감사」 A부류 수리 1호. 정본 `docs/OUTSIDE_LOOP_POOL.md`.
작성 2026-08-03.

## 1. 무엇이 문제인가 (실측)

캡처가 소비한 덱 `data/tardis_reference_toy06_19p48d_sivcaiv/`의 커버리지:

```
CMFGEN 활성선   1,703,064  →  Lumina 공통  881,085   51.74%
CMFGEN 활성준위    20,749  →  Lumina 커버   10,986   52.95%
```

**누락선이 남은 선보다 강하다**: `f_lu` 중앙값 `1.769e-4`로 존재선의 **3.88배**,
전체 `Σf_lu`의 **38.10%**, **`ΣA_ul`의 83.37%**를 누락선이 들고 있다.

**대역이 하필 EUV/FUV다**: 대역 내 선 누락률 UV **60.6%** / FUV **68.5%** /
EUV **72.0%**, FUV `Σf_lu` 누락 몫 **92.67%**. 누락 팽창불투명도 상한
UV 0.465 / FUV 1.302 / EUV 1.395 cm²g⁻¹ (CMFGEN population 기반).

**같은 캡처에서 `u`가 CMFGEN 대비 EUV 5.13× · FUV 2.53× 초과**로 실측돼 있다
(대장 0j). 해당 대역 불투명도의 70%가 없으면 밝아지는 것이 자연스럽다.

## 2. 원인 (코드에서 폐합)

`scripts/expand_atomic_data_cmfgen.py`의 세 규칙이 누락 **821,979선을 정확히 폐합**한다.

| # | 규칙 | 위치 |
|---|---|---|
| 1 | 하드 준위 캡 `ION_LEVEL_CAPS` — Ca III/V, Fe IV/V, Co IV, Ni IV 제한 | `:62`, `:422` |
| 2 | **이온 목록 누락** — Si V·Fe VI·Co V/VI·Ni V/VI 6이온이 기본 목록에 부재. `CMFGEN_FULL_LEVELS` 게이트 필요. **덱에 0행 = 게이트 OFF로 생성됨** | `:133` |
| 3 | **`gf` 임계 없음** — 필터는 준위 rank와 `lambda != 0`만 본다 | `:431` |

**3번이 핵심이다.** 절단이 세기가 아니라 **준위 번호**로 이뤄져 강한 선이 통째로 잘렸다.
⟹ 설계 의도가 아니라 **게이트 OFF 상태 생성물**. **A부류(버그) 확정.**

## 3. 수리안

1. `CMFGEN_FULL_LEVELS` 게이트 ON
2. `ION_LEVEL_CAPS` 해제 또는 CMFGEN `NF`까지 상향
3. 덱 **재생성**: `levels.csv`, `line_list.csv`, `cmfgen_sigma_bf.bin`, 충돌표,
   macro-atom topology 일괄
4. **새 디렉터리에 생성.** 기존 `_sivcaiv` 덱을 덮어쓰지 않는다 — 캡처 188932를 비롯한
   전 계보의 provenance가 거기 걸려 있다. 신규명 예: `..._sivcaiv_fullcov`

## 4. 자원 파급 (착수 전 확인 필요)

| 양 | 현재 | 예상 | 배수 |
|---|---|---|---|
| 선 | 881,085 | 1,703,064 | 1.93× |
| 준위(활성) | 10,986 | 20,749 | 1.89× |
| macro-atom 준위 | 26,592 | ? | ? |
| **macro-atom edge** | **7,752,396** | **?** | edge는 준위²로 스케일 가능 ⟹ **최대 3.6×** |

**GPU 메모리가 관문이다.** full-NLTE가 이미 80GB를 요구한다(a40 제외 규약).
edge가 3.6배면 **재생성 전에 메모리 산정이 필요**하다. 산정 없이 던지면 OOM으로
런 하나를 통째로 버린다.

**⟹ 착수 순서: 자원 산정 → 덱 생성 → 소규모 검증런 → 판정런.**

## 5. 검증 게이트 (재생성 직후, 런 이전)

1. **이온별 커버리지 비 → 1.0** — 전 이온 전수. 1.0이 아닌 이온은 사유를 남긴다.
2. **기존 덱과의 관계** — 새 덱이 기존 881,085선을 **전부 포함**해야 한다(진부분집합
   아님). 빠진 선이 있으면 재생성이 뭔가를 잃은 것이다.
3. **값 무변경** — 공통 881,085선의 `A_ul`·`f_lu`·λ가 기존 덱과 **비트 동일**해야
   한다. 달라지면 재생성이 값까지 바꾼 것이므로 단일변수 원칙 위반이다.
4. **σ·Υ 동반 확대** — 준위가 늘면 σ와 충돌표도 같이 늘어야 한다. 선만 늘고 σ가
   안 늘면 반쪽이다.

## 6. 런 규율

- **한 번에 하나.** 레버 가산성이 기각됐다(대장 D2) — 여러 변경의 효과는 사후에
  쪼갤 수 없다. 덱 교체와 다른 수리를 같이 넣지 않는다.
- **회귀 대장 전후 1행씩.** 스키마 v2가 이미 서 있다. 지표 8종의 이동을 기록한다.
- **기대 변경집합 사전등록**: EUV/FUV `u`가 **내려가야** 한다(불투명도 증가 →
  그 대역이 어두워짐). 방향이 반대면 기전 이해가 틀린 것이다.
- 바이너리는 신규 문자(`withParityAK` 이후)로 배포하고 **기존 문자를 덮지 않는다.**

## 7. 알려진 미결

- I14/I15(미설정 게이트 기본값·바이너리 소스 계보)가 `UNRESOLVED`이므로 이 수리
  이후에도 열거 완전성은 닫히지 않는다. **별건.**
- 슈퍼레벨 투영(`min(level,100)`, I4)은 이 수리의 범위가 아니다. full level이 늘어도
  투영 규칙이 그대로면 NLTE 해가 얼마나 달라지는지는 별도 문제다.
- 덱 재생성이 `I1`(Co IV Υ = Fe III 대용)을 고치는지는 **미확인**. 충돌표 생성 경로가
  다르면 별도 수리가 필요하다.
