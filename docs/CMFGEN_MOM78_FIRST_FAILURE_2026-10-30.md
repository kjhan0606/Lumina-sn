# CMFGEN 78회 실패: 첫 보정과 이전 주파수 항

## 결과와 범위

78회 외부 반복의 실패 스냅샷을 원본 그대로 읽어 **90점·단일 주파수의
MOM 호출만** 재생했다. 기존 parent/native와 같은 산술을 확인한 선택형
빌드로 첫 J/H 보정 직전의 정적 계수와 사건을 포착했다. 이 작업은 전체
CMFGEN, 온도·인구 갱신, 새 Lumina 수송을 실행하지 않았다. 자기일관 기준해와
최종 Si/S·스펙트럼 동질성은 여전히 미달이다.

- 주파수 `6.107329683700495e15 Hz`(490.873 Å), 외부 반복78, 주파수
  index35626, 90점. 최초 보정은 **내부 반복1의 H 제한**, 1기준 네 번째
  경계에서 발생했다. 나중에 관찰된 내부 반복25의 음수 J보다 앞선다.
- 해당 경계에서 raw `γr²H=-2189.25515`, 인접 raw `γr²J=36.61460`,
  `1474.16613`이다. `H_CHK_OPTION=MAX_VAL`은 절댓값을 인접 J의 최댓값
  이하로 제한하며, 이 조건에서는 H를 `−1474.01871`로 바꾸게 된다.
- 재생의 입력 snapshot은 원본과 SHA256이 완전히 같고, 첫 반복의 행렬과
  raw 해도 원래 100회 trace의 첫 반복과 배열 원소별 완전히 일치했다.
  STOP95는 첫 보정의 의도된 포착이며 수렴 성공이 아니다.

## 이전 주파수 항

네 번째 원점의 우변을 보존된 실제 계수로 재구성했다. 각 항의 합은
`−776.7239742`이며 원래 우변의 상대 재구성 오차는 전체 점에서
`2.22e-16`이다.

| 항 | 네 번째 원점의 기여 |
| --- | ---: |
| 국소 방출 | +0.00003282 |
| 이전 주파수 H | −1814.57441043 |
| 이전 주파수 J | +1012.89896442 |
| 이전 주파수 N 하측 / 상측 | −9.33386559 / +34.28530459 |

사용된 이전 주파수는 `6.107497416899375e15 Hz`다. 이번 계산의
`H_PREV`/`J_PREV`는 각각 진입 snapshot의 이전 주파수 저장 H/J와 배열
원소별 동일하다. 이전 H의 3·4번 경계는 각각 `−481.42321347`,
`−2296.14894607`이며, 두 값 모두 인접 저장 J 최댓값의 **정확히
`−0.9999`배**다. 즉 이전 H가 현재의 음수 우변에 직접 전달됐고, 수치상
native H 제한값에 놓여 있다. 이전 호출의 제한 전 H나 실행 분기는 직접
저장되지 않았으므로 아래의 계수 재구성과 진행 중인 재생으로 확인한다.

### 저장 계수에서 이전 H 제한 전후 재구성

실패 호출에 진입하기 직전 snapshot에는 이전 완료 MOM 호출의 J/H SAVE,
그 호출에서 사용한 `HU`, `HL`, `HS`, `EPS`, `EPS_PREV`, 그리고 그보다
한 주파수 앞의 J/H가 남아 있다. 원래 소스의 H 식에 **이전 완료 J와
이 저장 계수**를 넣어 제한 전 H를 재구성하고, `MAX_VAL` 규칙을 적용한
결과를 이전 H SAVE의 89개 경계 전체와 대조했다.

| 이전 호출 경계 | 재구성한 제한 전 H | 제한 후 / 저장 H | 인접 J 최댓값 |
| ---: | ---: | ---: | ---: |
| 3 | −1542.18408 | −481.42321 | 481.47136 |
| 4 | −3034.51671 | −2296.14895 | 2296.37858 |

제한 전 절댓값은 각각 한도의 `3.2031`배와 `1.3214`배다. 이 두 경계에서만
재구성 H가 한도를 초과하며, 제한을 적용한 89개 H는 저장 H와 최대 상대차
`6.0e-15`로 일치한다. 따라서 **저장된 원 MOM 계수와 J가 직전 호출의 최종
계수라는 전제**에서 이전 주파수에도 해당 두 H 제한이 실제 적용된 경로가
강하게 뒷받침된다. 현재 호출 우변의 큰 이전 H 항은 이 저장된 제한 후
값을 쓴다. 독립적인 이전 호출 실행 trace가 아니므로, 진행 중인 `1245331`의
진입 snapshot을 재생해 제한 전·후와 최종 SAVE를 직접 대조한다. 이것만으로
음수 J의 최초 원인이나 물리적으로 올바른 H를 판정하지 않는다.

재현은 원 snapshot과 위 빌드의 상태 목록을 `capture()`로 읽고
`solve_cmfgen_mom_kernel.previous_state_audit()`의 `raw_H` 원래 식을 사용한다.
각 경계에서 `limit=max(J_left,J_right)`이며 `abs(raw_H)>limit`인 경우만
`sign(raw_H)*0.9999*limit`로 제한한다. 기존의 원 snapshot·소스는 바꾸지
않았으며 별도 주파수 수송이나 물질 갱신은 없다.

### 이전 주파수의 J/H/K 모멘트는 같은 각도 분포로 실현되지 않음

위 이전 주파수 상태의 저장 `KMID_ON_J_SAVE`를 함께 사용했다. native
주석과 동일하게 경계의 `γr²K`는 이 계수에 양쪽 `γr²J`의 합을 곱한
값이다. 비음수 광선 강도로 만들어진 같은 위치의 모멘트는 필연적으로
`H²≤J*K`를 만족해야 한다. 중간 J를 인접 두 J 사이의 어떤 값으로
선택하더라도 `H² > max(J_left,J_right)*K`이면 이 조건은 불가능하다.

원래점 3–4 경계에서는 이 보수적인 비가 `5.8556`, 4–5 경계에서는
`7.5988`이다. 같은 조건을 위반하는 경계는 1기준 `3,4,5,6,7`이다.
`J`와 `K`는 이들 경계에서 양수다. 따라서 기존 `MAX_VAL`의
`abs(H)≤max(J_left,J_right)`를 만족하는 것만으로는 J/H/K가 함께
물리적으로 가능한 모멘트라는 보장이 없다.

기존 native `MON_INTERP` 재현으로 중간 J를 직접 계산하면 4–5 경계의
`γr²(J,H,K,N)=(1209.29800, −2296.14895, 302.14182, −168.82855)`이고,
`H²/(J*K)=14.4297`, `H/J=−1.89875`다. 이 동일 위치·동일 정규화의 네
모멘트를 사용하는 각도 지지 행렬의 최소 고유값은 `−2.11860`이다.
이는 보존된 **이전 주파수 MOM J/H와 저장 closure를 결합한 상태**가
비음수 각강도에서 나올 수 없음을 보여준다. 다만 raw formal 광선 전체나
실제 이전 호출 trace를 새로 복원한 결과는 아니다. 저장 closure의 생성과
MOM 사이에 어떤 처리나 근사가 최초 불일치를 만들었는지는 `1245331`의
앞 호출 재생으로 추적한다. 이 발견을 곧바로 Lumina의 오류나 CMFGEN 전체
해의 실패 원인으로 일반화하지 않는다.

재현은 같은 원 snapshot에서 `GAM_RSQJNU_SAVE`, `GAM_RSQHNU_SAVE`,
`KMID_ON_J_SAVE`, `NMID_ON_J_SAVE`, `R`을 읽고 기존 `native_mid`와
`analyze_cmfgen_initial_closure.angular_support()`를 적용한다. 다섯 경계의
보수적인 부등식은 중간 J의 구체적인 보간값 없이도 재현된다.

### 직전 저장 J의 원래 방정식 잔차

현재 실패 주파수 진입에 보존된 **직전 주파수 SAVE와 계수**로 기존
`completed_operator()`의 삼중대각 방정식을 재구성했다. 각 행의 잔차는
`|Ax-b|/(|A||x|+|b|)`로 정규화한다. 직전 주파수 `6.107497416899375`에서
전90점 최대는 **0.92738463**, 원점3이다. 해당 행의 좌변과 우변은 각각
`−8489.40254`와 `+275.81383`이다. 원점1·2·3의 정규화 잔차는 각각
`5.3923e-4`, `1.2041e-2`, `0.92738`이며, 원점4·5는 각각
`1.67e-16`, `2.02e-16`이다. `1e-8`을 초과한 점은 1·2·3뿐이다.
저장된 공간미분 계수를 저장 J에서 다시 평가해도 최대 잔차는 같다.

이는 **이 snapshot에 남은 계수가 직전 MOM 호출의 최종 계수이고 재조립된
경계가 그 호출과 같다는 전제**에서, 다음 주파수에 전달된 직전 J가 직전
이산 방정식에도 맞지 않는다는 증거다. 위 음수 J의 `FORM_VAL` 대체와
연관될 수 있지만, 이 수치만으로 대체가 최초 원인인지 또는 재구성 계수가
마지막 실제 호출과 정확히 같은지 증명하지 않는다. 진행 중인 `1245331`의
이전 호출 진입 및 재생으로 해당 전제와 대체 순서를 확인한다. 원점3의 큰
잔차를 Lumina 불일치나 CMFGEN 전체 해의 오차로 일반화하지 않는다.

입력 `MOM_CAPTURE.bin` SHA256은
`72803ecf9b45e7ebe6c9d12bee16bc6a26532ea0bbc079720422b429a3c5ed43`,
`state_inventory.json` SHA256은
`2c5cada170a9731c2870ae66f71c67ccb698a181731d9c3d6effb82a70610d83`다.
재현은 grammar `debug`의 CPU1·2GiB에서 프로젝트 루트의 `scripts`를
`PYTHONPATH`에 넣고 다음을 실행한다. 새 수송이나 물질 갱신은 없다.

```python
import json, os
from pathlib import Path
from analyze_cmfgen_mom_capture import capture
from solve_cmfgen_mom_kernel import previous_state_audit
root = Path(os.environ['MOM78_ROOT'])  # 위에 기록한 전용 결과 디렉터리
state = capture(root/'replay/MOM_CAPTURE.bin',
```

#### 음수 해에 들어간 한 단계 더 앞의 플럭스

같은 진입 snapshot에서 `GAM_RSQJNU_PREV`, `GAM_RSQHNU_PREV`,
`KMID_ON_J_PREV`는 위에서 역산한 직전 주파수 방정식이 사용한 **그보다
한 주파수 더 앞의 상태**다. 새 주파수 진입에서 SAVE를 PREV로 덮어쓰기
전의 값이므로, 현재 호출의 바로 앞 SAVE와 혼동하지 않는다. 원점2 우변의
원래 항을 재구성하면 아래와 같다.

| 항 | 원점2 우변 기여 |
| --- | ---: |
| 국소 방출 | `+0.000033` |
| 앞선 주파수 J | `+356.827958` |
| 앞선 주파수 H | `−449.443811` |
| 앞선 주파수 N 하측 / 상측 | `−25.693264 / +25.603250` |
| 합 | `−92.705833` |

따라서 이 음수 우변에서는 이전 H 항이 큰 음의 기여를 한다. 외곽 경계행을
포함해 나머지 깊이와 결합된 원래 삼중대각계를 풀어야 하므로, 음수 우변
하나만으로 두 음수 J의 유일한 원인을 증명하지는 않는다.

같은 앞선 상태에서 경계2의 `H=−985.01704`, 양 인접 J 최댓값
`1043.56783`, 저장 closure를 결합한 경계 K는 `225.43729`다. 그러므로
`H²/(max(J_left,J_right)*K)=4.12421`이다. 두 J와 K가 양수이며 중간 J가
두 값 사이에 있다면, 이 보수적인 필요조건 위반은 비음수 각강도로부터
같은 위치의 J/H/K를 만들 수 없다는 뜻이다. 같은 조건 위반은 경계1–7에
나타난다. 경계2는 `|H|/max(J_left,J_right)=0.94389`이어서 기존 MAX_VAL
제한을 통과하지만, 이것이 물리적인 J/H/K 조합을 보장하지 않는다. 경계3·4는
각각 `−0.9999*max(J_left,J_right)`에 놓여 있다.

방정식 계수와 다른 입력은 고정한 **가상 선형 민감도**에서, 앞선 경계2 H를
0 쪽으로 1% 움직이고 그 경계가 연결하는 원점2·3 우변을 양쪽 모두 보존형으로
변경하면, 앞 절의 raw J1/J2는 각각 `−4.9876/−6.1832`에서
`+9.7772/+8.5997`로 바뀐다. 이때 90점 음수 J는 없다. 그러나 계수·closure는
고정되어 있고 앞선 수송해를 다시 푼 것이 아니다. 특히 다른 경계의 필요조건
위반이 남는다. 이는 **플럭스 경로가 음수 해에 민감하다는 증거**이지 H를
임의로 1% 조정하는 수리법이나 물리해가 아니다. 위 결론은 snapshot의 PREV
배열과 마지막 선형계의 계보가 정확하다는 전제를 가지며, 진행 중인 실제
호출 재생과 전체 수송으로 확인해야 한다. 최초의 비물리 상태가 어느 더 앞선
주파수에서 만들어졌는지는 아직 미확정이다.

재현은 위 `state`를 사용하며, 결과를 입력 자료에 쓰지 않는다.

```python
import numpy as np
j = state['modules']['jrel']
q = state['modules']['ray']
from solve_cmfgen_mom_kernel import completed_operator, tri_matrix
A = completed_operator(state)
matrix = tri_matrix(A)
v = lambda name: j[name]['values']
jp, hp, hs = v('GAM_RSQJNU_PREV'), v('GAM_RSQHNU_PREV'), v('HS')
k = q['KMID_ON_J_PREV']['values'][:-1] * (jp[:-1] + jp[1:])
jm = np.maximum(jp[:-1], jp[1:])
print('edge2 H²/(maxJ K)', hp[1]**2/(jm[1]*k[1]))
delta = np.zeros_like(jp)
delta[1] += hs[1] * (-hp[1])
delta[2] -= hs[1] * (-hp[1])
candidate = np.linalg.solve(matrix, A[3] + .01*delta)
print('J1,J2', candidate[:2], 'negative depths', np.flatnonzero(candidate < 0) + 1)
```

#### 앞선 H를 필요조건에 맞춰도 다음 상태는 여전히 불가능

단순 H 제한이 수리가 될 수 있는지 같은 저장 선형계에서 반증했다. 앞선
주파수 각 경계의 H만 `±sqrt(max(J_left,J_right)*K)` 범위에 넣고,
변화량은 연결된 두 내부 우변에 반대 부호로 반영했다. 앞선 J와 K, 이번
주파수의 선형계·closure 및 다른 입력은 그대로다. 원본을 변경하거나 실제
주파수 수송을 다시 풀지는 않았다.

이 가상 계의 해는 90점 모두 양수이고 선형계 최대 정규화 잔차는
`1.14e-16`이다. 그러나 원래 H 식으로 계산한 **이번 주파수 raw H**와
저장 closure를 결합하면, 기존 `|H|≤max(J_left,J_right)`를 모든 경계에서
만족하면서도 경계1–4에서 `H²≤max(J_left,J_right)*K`를 위반한다.
각 비율은 `1.10036, 1.22492, 1.16756, 1.00746`이다. J와 K는 양수다.

따라서 이 동결 계에서는 앞선 H를 필요조건에 맞춰 음수 J를 제거하더라도
다음 J/H/K가 실제 각강도에서 가능한 조합이라는 보장은 없다. 이는 H를
제한한 값을 실제 ray 해나 물리적 수리로 취급하지 말아야 할 직접적인
사례다. 이전 주파수의 각강도·closure와 현재 공간·주파수 수송을 함께
다뤄야 하며, 실제 재생 및 공동수렴 없이 전주파수 결과로 일반화하지 않는다.

재현은 앞 블록의 `jp`, `hp`, `hs`, `jm`, `k`, `A`, `matrix`에 이어 실행한다.

```python
limit = np.sqrt(jm*k)
dh = np.clip(hp[:-1], -limit, limit) - hp[:-1]
b = A[3].copy()
b[1:-1] += -hs[:-2]*dh[:-1] + hs[1:-1]*dh[1:]
new_j = np.linalg.solve(matrix, b)
new_h = (v('HU')[:-1]*new_j[1:] - v('HL')[:-1]*new_j[:-1]
         + hs[:-1]*(hp[:-1]+dh)
         + v('EPS_PREV')[:-1]*(jp[:-1]+jp[1:])
         - v('EPS')[:-1]*(new_j[:-1]+new_j[1:]))
new_k = q['KMID_ON_J_SAVE']['values'][:-1]*(new_j[:-1]+new_j[1:])
new_jmax = np.maximum(new_j[:-1], new_j[1:])
print('negative J', np.flatnonzero(new_j < 0) + 1)
print('necessary-condition violations',
      np.flatnonzero(new_h**2 > new_jmax*new_k) + 1)
```

#### 음수 대체와 잔차의 정량적 연결

같은 재구성 행렬을 고정하고 직전 SAVE의 원점3–90을 유지했다. 원점3 행을
만족하는 원점2의 값을 대수적으로 구한 다음, 원점2 행을 만족하는 원점1을
구했다. 두 값만 바꾼 가상 배열은 다음과 같다.

| 원점 | 저장 J | 행식에서 역산한 J | 원 오류 로그 raw J |
| ---: | ---: | ---: | ---: |
| 1 | `35595.61824` | `−4.98758162` | 약 `−4.9876` |
| 2 | `35599.81257` | `−6.18324097` | 약 `−6.1832` |

역산값은 당시 마지막 두 오류 행의 음수 raw J와 **로그 출력 정밀도에서
일치**한다. 원점3 행의 원점2 계수는 `−0.24617248`이다. 가상 배열을
90개 행 전체에 대입한 정규화 잔차 최대는 `2.04e-13`이다. 즉 이 snapshot
계수와 J1·J2를 제외한 나머지가 해당 호출의 최종 계수·raw 해라는 전제에서,
두 음수 값을 formal 양수로 교체한 것이 저장 J의 원래 선형 방정식 잔차를
만드는 구체적인 경로가 된다. 이전 로그의 출력 정밀도와 snapshot에서
독립적으로 맞는 양도 늘었지만, 정확한 마지막 호출과 계수의 동일성은
진행 중인 진입 snapshot 재생에서 확인한다.

이것은 **선형화된 한 주파수 방정식의 가상 역산**이지 양의 물리해가 아니다.
원점1·2의 역산값은 음수이므로 저장 J를 이 값으로 바꾸거나 이를 수리로
채택해서는 안 된다. 이보다 앞 주파수의 입력과 경계·closure가 왜 음수
해를 만들었는지가 여전히 근본 추적 대상이다. 수송·인구는 갱신하지 않았다.

재현은 위 `state`를 재사용한다.

```python
import numpy as np
from analyze_cmfgen_mom_capture import residual
from solve_cmfgen_mom_kernel import completed_operator, tri_matrix
A = completed_operator(state)
matrix = tri_matrix(A)
x = state['modules']['jrel']['GAM_RSQJNU_SAVE']['values'].copy()
x[1] += (A[3, 2] - matrix[2] @ x) / matrix[2, 1]
x[0] += (A[3, 1] - matrix[1] @ x) / matrix[1, 0]
print(x[:2], residual(A, x), np.flatnonzero(x < 0) + 1)
```

### 실패 호출에 전달된 현재 formal 모멘트와 구분

같은 원 snapshot의 `JNU_STORE/HNU_STORE/KNU_STORE/NNU_STORE`는
이전 SAVE가 아니라 **현재 실패 주파수** formal 호출의 원래점 모멘트다.
이 네 배열은 모두 90점이고 J는 전점 양수다. 각 점에서 같은 각도 지지
행렬을 검사하면 최소 고유값은 전90점에서 양수이며 최솟값 `0.0104673`은
원점19다. `max(abs(H)/J)=0.813239`, `max(H²/(J*K))=0.949588`이다.
따라서 이 **저장된 현재 formal 모멘트**에는 위 필요조건 위반이 보이지
않는다. 이것은 입력 광선의 독립 재생이나 수송 수렴 검증이 아니다.

이전 주파수 MOM SAVE의 비물리 조합과 현재 주파수 formal STORE의 차이는
시간적으로 인접한 두 자료의 비교이지 같은 주파수에서 두 해를 뺀 오차나
formal 전체 계산의 정확성 증거가 아니다. 다만 현재 포획에 제공된 formal
모멘트 자체가 위 양의 각도 지지 조건을 만족한다는 사실은, 문제를 현재
formal STORE 하나의 불량으로 곧바로 단정하기 어렵게 한다. 이전 주파수의
실제 formal·MOM 대응 및 H 제한의 발생은 앞 호출 재생으로 따로 확인한다.
원 snapshot과 `angular_support()`를 읽어 계산했으며 새 수송은 없다.

현재 포획의 원래 비선형 이산식을 서로 다른 초기값에서 풀면 음수 J를
가진 근에 도달하며, 양수 제약 탐색에서 얻은 후보의 정규화 잔차는
`0.005574`다. 이는 전역적인 양의 근 부재 증명이 아니다. 첫 H 제한이
이후 음수 J를 **일으켰다**는 증명도 아니다. 현재 호출의 J 행렬은 이전
주파수 H를 사용하므로, 같은 호출 첫 반복의 H 보정과 이전 주파수 H의
영향을 구별해야 한다. 제한을 해제하거나 음수를 잘라 생산해로 채택하지 않는다.

다음 수리 대상은 이전 주파수 H의 생성·제한 전 값과 formal 각도 이력,
경계 및 주파수 이산화의 연결이다. 이전 H가 제한값이라는 이유만으로
누락된 이력을 역산하거나 특정 경계 처방을 정답으로 선택하지 않는다.

## 이전 H 네 번째 경계의 조건부 영향

같은 보존 방정식에서 다른 계수·이전 J·나머지 H를 고정하고, 이전 H의
네 번째 경계만 임의로 0 쪽으로 이동하는 **가상 민감도**를 계산했다.
변경된 H가 들어가는 두 인접 우변을 부호에 맞게 모두 갱신하고, 원래의
LINMON 비선형식을 다시 풀었다. 이는 이전 주파수 수송이나 formal 각도
이력을 재생한 계산이 아니며, H 조정을 생산 처방으로 채택하지 않는다.

| 이전 H4의 0 쪽 변화 | 네 번째 점의 해 `γr²J` | 음수 J 점 | 현 주파수 H 제한 위반 경계 |
| ---: | ---: | --- | --- |
| 0% | −3.95547 | 4 | 4 |
| 1% | +6.09515 | 없음 | 4 |
| 34% | +338.22504 | 없음 | 4 |
| 50% | +498.89111 | 없음 | 없음 |

각 행의 원식 정규화 최대 잔차는 `4.1e-13` 이하이며, 90점 전체에서
음수 J와 H 제한을 확인했다. 이 특정 계수 고정 문제에서는 이전 H4를 1%
변경하는 것만으로 음수 J 근이 양수로 바뀌지만, 34% 변경까지는 현재
주파수의 H 제한 위반이 남는다. 50%는 이 한 호출의 수학적 후보이지 실제
이전 H가 그 값이라는 증거, 고정되지 않은 각도·산란장의 일관성이나 전체
CMFGEN의 수렴 증거가 아니다. 다른 가능한 해의 전역 존재 여부도 판정하지
않는다. 따라서 **이전 H 경로의 민감도는 확인됐지만 실제 물리 수리는 아직
없다.**

재현: 위 `MOM_KERNEL.bin`과 `MOM_FAULT.bin`을 `first_repair_equation`으로
읽는다. 0기준 경계 `k=3`의 기존 `H_PREV[k]`를 `(1−f)`배로 바꾸면
`delta=−f*H_PREV[k]`이고, 우변 `b[k]`에 `HS[k]*delta`를 더하며
`b[k+1]`에서는 같은 값을 뺀다. `base@x + adv*linmon(x,R) = b`를 formal
초깃값으로 풀고, 새 H 식에 변경된 이전 H를 사용한다. 기존 90점 원식·경계
정의는 유지한다. grammar debug에서 CPU1·4GiB·최대3분으로 실행했으며
기존 스냅샷을 변경하지 않았다.
