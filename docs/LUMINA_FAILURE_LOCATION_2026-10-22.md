# 실제 원천 적분의 첫 실패 열 재현

## 목적·범위

최종 목적은 자기일관 Si/S 분포·스펙트럼·물리량의 CMFGEN 동질성이다. 현재 전제인 원13003 전주파수 공간적응 수송이 실패하므로, 같은 입력에서 실패 열/세 조각을 특정하고 수치적 원인을 재현한다. 작은 시험 통과로 원 목표를 닫지 않는다.

433944는1시간 한도 안에서204GPU초 후205, 새 native-bin 후보433954도 장치13시험/0.48초 통과 뒤13GPU초/실제Python11.564초에서205로 종료했다. 둘 다 시간초과나512NF/메모리 도달이 아니라 `SUBDIVISION_PRECISION_LIMIT`이다. 실패한 열을 기존 상태가 기록하지 않아 정확한 재현 위치는 아직 없었다. 결과와 봉인 입력은 보존했고 같은 물리 계산을 자동 재시작하지 않는다.

CPU 재현 `/gpfs/kjhan/cmfgen_runs/lumina_three_piece_CPU_20261022-a5AEOS`에서 coarse뿐 아니라 양쪽 half의 같은35열을 조사했다. 새 적분기105개 호출은16.875초 안에 오류 없이 완료했다. 이 조사에서 독립 half 참조 정확도를 대조한 것은 아니다. 원 CPU 적분기 대조는 새 후보가 실패할 때만 하도록 했으므로 실제로 호출되지 않았다. 원 GPU 실패를 CPU105개로 재현하지 못했다. 결과 SHA256 `742a830d4b08d39efe6e1661f245deb25d171936d24c67ab32574cd25c75a8a0`이다. 최초 잘못된 원 라이브러리 경로 로그는 보존하고, 원 coarse 결과와 일치하는 `ClLEqp/cpu-probe.so`의 SHA `cb7074a89a92d9329a41c1d5d0a194ae47fbd8a604c93c65fc48df8a3cb72b74`를 확인해 수정했다.

## 변경과 실행

운전자 Codex가 구현·직접시험·실행·재현을 맡는다. 새 고정 root `/gpfs/kjhan/cmfgen_runs/lumina_failure_location_20261022-VD6e3J`는 앞선 후보의 정확한 입력/코드를 복사했다. 선택 플래그 `CMF_GPU_FAILURE_COLUMN`에서만 기존 sticky 오류 정수를 `100000000+8*(p.begin+i)+code`로 바꾼다. 런타임이100을 더하므로 역변환으로 출력열/수치 상태를 구한다. 기존 계산·분할·오차·입력·기하·맵은 그대로이고 새 장치 버퍼/계측 루프는 없다. 이 열은 처음 관측한 실패이지 가장 작은 실패열이라는 보장은 없다. 어떤 coarse/half인지 CPU에서 같은 열의 세 조각으로 구별한다.

진단 GPU 바이너리 SHA256 `9e7176dc63c04b9364c8579cd6d8e3ebde3cb95e5a290af16822cd338db9bd08`다. strict CPU-only 컴파일은 lageunha CPU1/16GiB/300초 이내다. 앞선 기본 경로 컴파일 증거와 동일 계산의13장치시험을 재사용하며 새 바이너리의 작은 범위질의1개만 같은 할당에서 확인한다.

GPU1/A100 PCIe·CPU1·host/device16GiB·활성1048771496B<1GiB·512NF·노드미고정/no-requeue/자동재시도0이다. 이번은 최대180초 할당/구간140초/내부150초/외부160초의 **위치 식별 진단**이다. 소형시험 최대5초와 수송 진단을 같은180초 안에 넣는다. 앞선 새후보13초+이번최대180초는 승인한 새후보3600초 범위 안이다. 기존 준비1064초·전역144GPUh 사용량을 보존하며0.05GPUh를 별도 예약하고 본할당만 한 번 정산한다. 누적4651초 상한은 유지한다.

## 수용·증거·보존·재현

실패 위치를 얻고 같은 입력/열/조각에서 CPU 상태를 재현하면 원인 조사에 사용할 증거가 생긴 것이다. 전주파수 완성·독립3열·최종 출력별오차·자체장·SE_RE·생산율·CMFGEN 일치의 통과 판정이 아니다. 위치 미관측/시간 만료는 미완으로 남기며 자동 반복하지 않는다. 실패 부분장을 물리 결과로 사용하지 않는다.

봉인 계획/소스·바이너리 해시·CPU 시험·같은 할당 장치시험·`gpu-local.json`·`failure-location.json`·본할당sacct를 남긴다. 실제 계산의 원천1e-8·공간1e-5·독립참조1e-4·최종 출력별 오차 기준은 바꾸지 않는다.

`scripts/lumina_gpu_failure_location.py prepare <root>`와 `run <plan> --sha256 <SHA>`는 이 한정 진단의 준비/실행 명령이다. 후속 CPU 재현은 새 격리 root에서 `scripts/lumina_three_piece_cpu.py <root> --column <관측열>`을 CPU1/16GiB/300초 안에 수행한다. 원본과 실패는 보존하며 새 수정/재현은 새 root로 분리한다.

CPU **32통과/3.48초**, 계획 SHA256 `22cbd5b85aa3b83e9b6fe961c57bffedfa029ba84f3e8b1df9939e3a2aae84b0`으로 봉인했다. 단회 Slurm **433965**를 제출했으며 최초 **PENDING/Resources**다. 아직 위치 관측은 없다. GPU와 같은 원 전역트리 좌표가 필요한 CPU 재현은 `--global-coordinates`를 추가한다. 기본 CPU 표본은 anchor를 옮긴 국소 트리였다는 차이를 기록하며 둘을 같은 전역트리 비트 재현이라고 표시하지 않는다.
