# CMFGEN fixed-T 기준 상태 추가 반복 계획

## 목적과 경계

목적은 미수렴 CMFGEN reference의 Si II/III 및 S 이온분율을 같은 물리 조건에서
계속 계산하여 기준의 반복 안정성을 평가하는 것이다. 최종 목표인 Lumina와의
물리량·관측 스펙트럼 동질성에는 직접 필요한 비교 기준을 개선하지만, 이것만으로
Lumina와 동등하거나 released-T 물리 앵커를 얻는 것은 아니다.

이전 작업 `1225397`은 record70에서 시작해 내부 `NUM_ITS=4`에 따라 record74에서
정상 종료했다. Slurm 12시간을 다 쓰지 않았다. 73→74 최대 이온분율 절대변화는
Si II 6.32e-7, Si III 0.159574, S II 1.35e-4, S III 0.114642였으므로 74를
수렴 기준으로 채택하지 않는다. 실제 추출은
`lumina_native_long_20261027-9RyXe2/run/material`에서 90점 전체, 다섯 상태를
보존했고 출력 SHA는 인수인계서에 남겼다.

## 실행 설계

- 시작점은 검증된 record74만 사용한다. 원70 material identity를 재검증하고,
  이전 실행의 완료 결과·native/build 실행파일 SHA, record70~74 계보,
  POINT1/POINT2=74, RVTJ 완결성과 고정 T를 확인한다.
- 이전 실행을 수정하지 않는다. 기존 원 seed에서 새 run 복제본을 만들고
  record74의 SCRTEMP, 포인터, RVTJ, STEQ_VALS, EDDFACTOR, EDDFACTOR_INFO,
  CUR_MODEL_DATA만 명시 restart overlay로 전달한다. 출력 디렉터리는 신규·배타적이다.
- 이전과 같은 corrected native 실행파일, 순간 침적열, FIX_T=T, FIX_NE=F,
  USE_FIXED_J=F, COMP_BA=T, N_FIX_BA=0, 자동 T/Lambda 전환 금지, 기존 수치
  제어를 유지한다. `NUM_ITS=16`은 record74 이후의 최대 추가 횟수이며 목표
  반복 번호가 아니다. 변경 전 기본 4회는 그대로 보존한다.
- 자원은 CPU16/OMP16/128GiB/GPU0, 내부 최대42600초·Slurm 최대12시간,
  재시도0이다. 이는 수렴 보장이 아니다. 첫 반복의 비용이 선형 확장과 다를 수
  있으므로 시간 완료를 예상하지 않는다. 제한이 끝나면 마지막 완결 record/RVTJ와
  부분 출력을 보존하고 불완전으로 분류한다.

## 관측값과 판정

90점 Si/S 모든 charge-stage 분율, 각 반복 개체수 및 `ne` 변화, raw CMFGEN 보정,
fresh BA 로그, 최종 RVTJ 일관성, 입력·실행파일 신원과 실제 경과/최대 RSS를
보존한다. 각 연속 반복에서 최대 절대 분율 변화를 계산하며 최대 위치도 기록한다.
원소 총수 및 terminal closure는 기존 추출기와 POP 출력으로 대조한다.

반복 수 상한 도달이나 정상 프로세스 종료만으로 수렴을 선언하지 않는다. 최종
동질성 판단에는 사전 물리 수용기준에 따른 active population 통계, 최종 반복들의
분율 변화, 유효 동일세대 RVTJ, Lumina의 동일 물질·공통장 물리량 및 스펙트럼
비교가 모두 필요하다. 이번 묶음은 fixed-T 안정성 조사이며 온도 해제/새 BA 설정/
원자자료/물리식을 바꾸지 않는다.

## 실행 안전과 재현

운전자는 봉인된 저장소 commit에서 전용 Slurm staging을 수행한다. 동일
fixed-T continuation 결과 디렉터리가 이미 있으면 제출하지 않는다. 제출 전
grammar의 같은 job-name 활성 작업 부재, 예상 입력 경로/해시, Slurm CPU·메모리·
시간 한도를 확인한다. 원 1225397과 모든 원본/부분 자료는 보존한다. 재현은
`scripts/submit_cmfgen_fixedt_continuation.slurm`의 인수를 사용하며, 제출 뒤
새 job ID와 모든 출력 해시를 본 문서 및 당일 인수인계서에 기록한다.

검토 역할은 계획·평가 담당 Astra, 구현·실행·재현 담당 운전자다. Astra의
read-only 설계 자문을 받은 뒤 운전자가 최종 실행 판단을 기록한다. 결과는 반드시
운전자가 정확한 source/build/material·명령을 다시 확인하고, `PASS`, `REWORK` 또는
`BLOCKED`가 아닌 과학적 최종목표 `NOT_MET`을 분리해 판정한다.

## Astra 계획·설계 평가

Q-GOAL=`PASS`: Si III/S III가 73→74 사이에도 각각 최대0.159574/0.114642
변했으므로 미수렴 기준을 계속 푸는 것이 코드 간 물리 비교에 직접 필요하다.
단 fixed-T 안정화는 필요 단계일 뿐 최종 물리량·스펙트럼 동질성의 충분조건이
아니다.

Q-LEAN=`APPROPRIATE`: 단일 이어계산에서 재시작 identity·계산 안전·전90점
Si/S 분율과 인구/ne/raw 보정·RVTJ를 함께 본다. 원70 재계산이나 반복별 외부
감사는 불필요하다. 기존 상태 배열과 이온분율 추출기를 재사용한다.

설계에서 지적한 위험을 반영했다. 완료 당시 추출 JSON의 SCRTEMP/RVTJ/POPSIL/
POPSUL 해시와 실행 제어 SHA를 재검증하고, 원70 계보·POINT1/2·동일 T까지
확인한다. 각 신규 반복 종료 후 fresh BA 위반을 재검사하고, 최종 완료는
POINT1=POINT2=마지막 SCRTEMP record 및 같은 세대 RVTJ가 모두 맞아야 한다.
Slurm 12시간에서 후처리 여유를 남기도록 외부 timeout을43,000초로 제한했다.

이 반복 설계는 같은 fixed-T 수식의 record74 초기값에서 계속 푸는 조건부
과학적 재시작으로 타당하다. 재시작은 내부 이력을 초기화하므로 record70부터
한 번에 계산한 것과 비트 단위 동일성을 주장하지 않는다. 16회는 최대 추가
횟수다. 기존4회에2시간33분41초가 걸린 단순 비례 추정은 약10시간15분이므로
12시간은 합리적인 자원 한도이나 완료 보장이 아니다. 끝 반복 수/작은 변화만으로
수렴을 선언하지 않는다.

Astra 자문 모델은 `gpt-6-astra`, read-only 평가였으며 코드·계산은 하지 않았다.
운전자가 해시·물리 기준·시작 state를 독립 재현한 뒤 job1226720을 제출했다.
단일 grammar node, CPU16/OMP16/128GiB/GPU0/최대12시간/재시도0이다.
매개 run 식별자는 `lumina_native_continue74_20261027-QSmVn0`; 사용자 원자료는
변경하지 않았다. 제출 시 `RUNNING`이며 최초 시험 열 개가 통과했다. 이 상태는
생산 계산 성공이나 수렴 판정이 아니다. 후속 실제 run record와 자원 결과를
인수인계서에 갱신한다.

## 완료74 기준의 활성 개체수 확인 — 운전자 읽기 전용 재현

기존 `ptf_gated_metrics.py`의 판독을 완료한
`lumina_native_long_20261027-9RyXe2/run/material`에 적용했다. 새로운 계측기나
수용 게이트를 추가하지 않았으며 원 계산·진행 중인1226720은 변경하지 않았다.
grammar-debug CPU1·4GiB·180초 이내에서71~74반복을 읽었고 입력7개의
SHA256이 전후 같음을 확인했다. STEQ 앞70블록은 이어계산 전 이력이며,
OUTGEN의 실제71~74와 대응한 마지막4블록만 사용했다.

| 반복 | 이온분율 활성 표본 수 | 보정 p95 (%) | 보정 최대 (%) | 최대 항 |
|---|---:|---:|---:|---|
| 71 | 108685 | 419.416 | 13118000 | Co IV SL11, 깊이16 |
| 72 | 108685 | 294.768 | 24797 | Si III SL81, 깊이3 |
| 73 | 109313 | 211.286 | 7267.8 | Si III SL6, 깊이2 |
| 74 | 109727 | 103.191 | 5762.6 | Si III SL90, 깊이2 |

활성 선택은 **직전 상태의 이온분율 >1e-8**인 이온의 모든 SL/깊이다.
율·열·불투명도 기여로만 활성인 항을 추가하지 않은 부분집합이므로 이를
전체 v2 활성 합집합 검사라고 부르지 않는다. 부분집합의 p95가 전체
합집합 p95의 하한이라는 주장도 하지 않는다. 하지만 이 부분집합의 최대가
v2 최대 보정 기준1%보다 크므로 **기준 미달은 이미 확정**이다. 값이 작게
나왔어도 전체 활성 합집합·나머지 앵커 요건의 통과를 입증하지는 못한다.

74의 최대 항이 속한 Si III 이온분율은 직전 상태에서9.787553677e-6이다.
해당 SL90의 실제 인구는1.24560507156e-12→1.24560507156e-11로10배
변했다. 이는 작은 SL 인구에 대한 큰 **제안** 보정5762.6%와 실제 적용
변화를 구별해야 함을 보여준다. 이 수치만으로 SE 잔차·율 오류·원자자료
오류·전체 이온화 변화의 원인을 판정하지 않는다.

반면 실제73→74의 최대 `abs(ne74/ne73-1)`는 **0.048468008745**(깊이28),
최대 `abs(delta ln ne)`는0.049681970893이다. 온도 행은 정확히 같았다.
따라서 fixed-T라는 사실이나 전체 평균 전하의 작은 변화만으로 안정화를
선언할 수 없다. 이어계산에서 같은 원자료 지표가 실제로 줄어드는지 확인하고,
fixed-T 안정화가 되더라도 released-T 앵커/최종 스펙트럼 인증과 구분한다.

RVTJ와 SCRTEMP 최종 상태 대응의 상대차 최대는 반경4.34e-11,
ne3.79e-8, T4.20e-8이며 텍스트 출력 정밀도와 일치했다.

OUTGEN에 인쇄된 증가/감소/반환 MAXCH도 각71~74의 출력 정밀도 범위에서
일치했다. 이로써 큰 보정값을 다른 반복의 자료와 섞어 읽지 않았음을 확인했다.

## 1226720 중단의 직접 기작 — 시간 부족이 아닌 moment 내부 비수렴

저장 OUTGEN의 첫 moment 반복 초과는 **바깥78반복**에 나타난다.
75~77은 완료 pointer에 남았으나78은 완료 물질로 채택하지 않는다.
실패 주파수는 native 표기6.10732968이며 두 호출의 변화량 지표가
0.589/1.00이었다. 원 소스 `plane/mom_jrel_v9.f:975`의 이 지표는
`max(abs((old Gamma*r^2*J-new Gamma*r^2*J)/(new Gamma*r^2*J)))`다.
**moment 방정식 자체의 잔차는 아니다.** 내부 목표1e-8 미달 상태에서
100회에 도달했고, 소스는 Error를 인쇄한 뒤 ACCURATE=true로 루프를
나오며 다음 계산을 계속한다. 운전자의 기존 오류 탐지가 이를 중단했다.
따라서 프로세스가 자체적으로 계속 계산하거나 제한 시간을 늘리는 것을
수렴 성공으로 취급해서는 안 된다.

원 수식은 INCL_ADV_TRANS=T에서 J의 공간 기울기를 반복 갱신한다.
오류가0.01보다 크면 새 기울기10%·이전90%, 작으면80%·20%를 섞는다.
이를 끄거나100회 상한만 늘리는 수정은 하지 않았다. 정확한 행렬과
양수/음수 구간의 반복 이력이 없어 근본 원인을 기울기 갱신·경계/closure·
입력 상태 중 하나로 확정한 것은 아니다.

기존 MOM_J_ERRORS를 grammar-debug CPU1/4GiB/180초 이내에서 읽었다.
파일5538012bytes, 진단41427행·표시 주파수1667개다. 원 WRITE 열은
**I,FREQ,XM,ETA,CHI,ESEC,K_ON_J,주변XM**이며 인쇄 헤더는 이 열과 다르다.
헤더의 WAVE를 실제 파장으로 오독하지 않는다. 실패 주파수의26행은
모두 내부 그리드 I=4이며, 대체 전 XM은−0.18257~−0.019616이다.
그 기록점의 CHI=1.4512e-9, ETA=2.9284e-19, ESEC=1.2144e-9는
모두 양수다. 전체 진단행에서도 기록된 CHI/ETA의 음수는0개다.
이는 **해당 기록점의 음수 소광이 없어도 음수 mean-intensity 해가
발생했음**을 보여주지만 다른 점의 계수·전체 행렬이나 원자자료의 정상성을
증명하지는 않는다. 이 파일은 내부 그리드 번호이며 원90점 번호로 등치하지 않는다.

원 소스는 XM<0일 때 기본 CHK_J=FORM_VAL로 formal-ray J를 넣는다.
CHK_H=MAX_VAL, CHK_XM=NONE도 기본값이며 해당 VADAT/IN_ITS에 덮어쓰기가
없었다. 따라서 단순 음수 검출 개수와 최종 J, 보정 이후의 내부 수렴 여부를
구분한다. 이 대체를 끄거나 다른 clamp를 추가하지 않았다. MOM_J_ERRORS는
주파수 시작 때 rewind되며 바깥 반복 번호/개별 내부 반복 번호를 저장하지
않으므로26행 전부를78의 한 호출에 귀속하거나 전체 궤적을 재현했다고
주장하지 않는다. 현재 분석은 원 소스와 저장 로그의 대응이며 새 native
실행 또는 독립적인 방정식/Jv 동등성 입증은 아니다.

OUTGEN의 외곽 광도 표기는75~78에서8.5844e10,1.28935e11,1.32520e11,
