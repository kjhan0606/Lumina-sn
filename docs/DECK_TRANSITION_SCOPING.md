# 덱 전환 스코핑 — A1(I20 수리) + A2(수소꼴 정확 평가) 생산 반영

2026-08-06 (운전석). user 승인 경로: *"A1+A2 를 묶어 한 번의 전환, 그 전에 전량 회귀
스코핑 먼저."* **이 문서는 전환을 실행하지 않는다 — 비용과 대상을 확정한다.**

---

## 1. ★전제 정정 — 생산 덱은 `_ftos` 가 아니다

스코핑 첫 실측에서 내 전제가 틀린 것이 드러났다.

```
생산 런처(scripts/*.sh, *.slurm)가 참조하는 덱 (빈도)
   79  data/tardis_reference_toy06_19p48d          ← bare, 실제 생산
   13  data/tardis_reference_toy06_19p48d_sivcaiv
    0  data/tardis_reference_toy06_19p48d_sivcaiv_ftos
```

`scripts/run_gate_battery.py:276,434` 도 bare 덱을 쓴다(양성 덱만 `_sivcaiv`).
**`_ftos` 는 R4 vintage 감사용 산출물이고 생산 경로에 없다.**
층 1 측정(I20·I3a·R-5)을 전부 `_ftos` 에서 했으므로 **물리 발견은 이전되지만
"생산에 얼마나 걸리는가"는 다시 재야 했다.**

### 생산 덱의 실제 상태

| | **bare (생산)** | `_ftos` | `_ophys` |
|---|---|---|---|
| 선 | **2,565,342** | 2,220,953 | 3,371,577 |
| 준위 | **25,620** | 31,792 | 36,547 |
| `atomic_vintage_manifest.csv` | **없음** | 있음 | 있음 |
| 충돌자료 `ige_col_*` | **12** | 34 | 41 |
| I20 공기파장 오염 | **32/48 이온 · 1,325,865선 = 51.7%** | 45/58 · 28.6% | 0 |

**생산 덱에는 원자자료 계보 기록이 아예 없다.** 어느 vintage 에서 왔는지 산출물이
말하지 못한다. user 가 2026-08-03 에 확정한 동일성 교리
(*"동일성은 CMFGEN 을 모든 미래 문제의 대조군으로 만든다"*) 아래에서
**계보 미기록 덱은 대조군 자격의 전제를 충족하지 못한다.**

⟹ 전환의 성격이 바뀐다: *"수리를 적용한다"* 가 아니라
**"계보 없는 덱에서 런-종속 덱으로 생산을 옮긴다"** 이다. A1·A2 는 그 안에 포함된다.

## 2. 전환이 **깨지 않는** 것 (실측 확인)

| 항목 | 확인 |
|---|---|
| C 런타임의 덱 결박 | **없음** — `lumina_main.c:108-109` 가 `argv[1]` 로 받는다. `src/` 의 유일한 덱 문자열은 **주석**(`lumina_atomic.c:2515`) |
| `kshape_contract.txt` | **덱마다 자기 것**(line_list/tau/transprob sha256 + n_lines + n_shells). 덱을 바꾸면 계약도 함께 간다 — 결박이 아니라 **정합 장치** |
| 덱 완전성 | `deck_regen.py` 가 완전성·stale 게이트로 강제. `_ophys` 는 `verification.log` 외 누락 0 |

## 3. 전환이 **깨는** 것

| 항목 | 규모 | 성격 |
|---|---|---|
| **바이트-parity** | 전부 | 선 파장·f·A·σ 가 바뀐다. **의도된 것** |
| **`line_id`** | 전부 재배열 | ν 내림차순 정렬이 바뀐다 → macro_atom 연동(같은 빌드에서 함께 생성되므로 내부는 정합) |
| **회귀 대장 138행** | 비교 불능 | `validation/regression_ledger/ledger.jsonl` 의 모든 metric 이 구 덱에서 측정됐다. **틀린 게 아니라 비교 불가**가 된다 |
| 덱 경로 하드코딩 | scripts 55개 + 셸 런처 다수 | 대부분 1회성 분석 스크립트. 생산 경로는 런처의 `data/tardis_reference_toy06_19p48d` 79곳 |

## 4. 비용 — 싼 쪽과 비싼 쪽이 갈린다

**싼 쪽 (코드 층, 즉시 가능)**
- 게이트 배터리 36케이스: 병렬화 후 **~40초**(구 25분)
- selftest 전종 · A2-01 census 체커(배터리 preflight)
- 덱 생성 자체: expand+finalize+coldata+multiplicity+ma_radrecomb 로 **~20분/덱**

**비싼 쪽 (물리 기준선)**
- 회귀 대장의 138 런은 전부 GPU 생산런 산출이다. **재기준선화는 런을 다시 도는 것**이고
  이것이 전환 비용의 본체다.
- 다만 **전량 재실행이 필요한 것은 아니다** — 대장은 append-only 이고
  `input_inventory` 필드가 덱을 기록하므로, **덱 축을 새로 열고 그 위에 쌓으면 된다.**
  구 행은 구 덱의 것으로 남는다(삭제·수정 금지).

**⟹ 진짜 비용은 "회귀를 다시 도는 것"이 아니라 "새 덱 축의 기준선을 만드는 것"이다.**
최소 집합은 대장이 추적하는 metric 을 재현할 수 있는 **대표 런 소수**다.

## 5. ★전환을 지금 검증할 수 없다 (정직 기재)

새 덱이 구 덱보다 낫다는 것을 **CMFGEN 대조로 증명할 수 없다.**
게이트 5종이 `BLOCKED_ORACLE_NOT_CERTIFIED` 이고, user 결정(2026-08-06)으로
수렴한 free-T 런까지 그대로 둔다.

지금 말할 수 있는 것은 **원본 충실도**뿐이다:

| 축 | 근거 |
|---|---|
| 계보 | 덱이 대조 런의 `atomic_links.txt` 와 27/27 동일 원본, sha256 기록 |
| I20 | ν·f·A 를 CMFGEN 과 동형으로 산출, 전정밀도 비트 동일(G1b=0) |
| I3 수소꼴 | CMFGEN 루틴 문장단위 이식, 단위 H 바닥상태 검증 |

**"더 정확하다"가 아니라 "원본에 더 충실하다"이다.** 이 구분을 전환 판정문에 유지한다.

## 6. 권고 — 3단 전환

| 단 | 내용 | 게이트 |
|---|---|---|
| **T1** | 생산 대상 덱을 `deck_regen.py` 로 생성(대조 런 links + I20 + `CMFGEN_EXACT_HYD=1`). **구 덱 보존** | 완전성·stale 게이트 통과, `DECK_PROVENANCE.json` 기록 |

| **T3** | 회귀 대장에 **새 덱 축**을 열고 대표 런으로 기준선 수립. 구 행은 불변 | 대장 자기검사(append-only·음성대조) 통과 |

전환은 **계보·충실도 근거**로 하는 것이며, 그 사실을 대장에 명시한다.
