## 4. 이탈·한계

1. **종료감사 B1·B2 (구현 이탈, 수리됨)**: f2 판독기는 두 가지가 계약과 달랐다.
   - 과반 경계가 미해결이어도 최대 묶음이 분리되면 MIXED_LARGEST를 반환했다(§6.1 위반).
   - 차이·요인을 순합과 같은 부호 쪽만 분류했다(§6.2·§6.3 위반).
   - 판독기를 수리했고(B1·B2 시험 사례 추가), f3로 다시 판독했다. 양의 쪽 분기는 f2와 같다. 음의 쪽 분류는 §3.1·§3.2에 새로 보고했다.
2. **CLI**: §9.3과 다르다.
   - `selftest`는 `--exe`, `--replay-bin`, `--fixture`, `--fixture-components`를 추가로 받는다.
   - `paired`는 `--prior-paired`(선행 mapped 차이)를 추가로 받는다.
   - 물리 정의·입력·산출·게이트는 같다.
3. **직접시험 fixture**: 선행 C 배터리 fixture는 매핑 주입 하류에 미매핑 공명이 놓이는 경우를 담지 않았다. 그래서 `t1`에서 미매핑 감쇠 결함을 드러내지 못했다.
   - 판독기 selftest가 파생 fixture `near`(선 1을 선 0 × 0.998 주파수로)와 `eq`(동주파수)를 만든다. 둘 다 선 0을 짝수 셸에서 매핑으로 바꾸고 ε를 0으로 둔다.
   - C 직접시험은 `near`에서 돌렸다. `eq`는 T2 replay로 mapped 레인을 다시 만들어 폐합을 확인했다.
   - 파생 fixture는 시험 전용이며 실제 캡처를 바꾸지 않았다.
   - 같은 상태·E/R 교환 시험은 공통 쌍 대수 시험이며, 집합 처리 경로 전체를 시험한 것은 아니다.
4. **러너**: `f1`까지의 러너는 빌드·시험이 실패해도 진행했고, 마지막 표지만 출력했다.
   - f3 러너는 각 단계의 rc와 `VALID`를 확인하고, 실패하면 `LINEDECOMP_FAILED`로 멈춘다.
   - f2·f3의 수치 판정은 개별 rc·산출을 확인한 것이다.
5. **산출 누락 (f2, 수리됨)**:
   - f2는 묶음별 쌍수를 표에 넣지 않았다(대역 합집합 총계만 있었다).
   - 전이 표는 판독기 밖에서 만들었고 manifest에 없었으며 구간이 없었다.
   - f3에서 두 산출을 판독기로 옮기고 manifest에 등재했다.
6. **`pairs.bin` 범위와 ω 복원**: 두 대역 어디에도 도달하지 않은 매핑 쌍(H = 0)은 기록하지 않는다.
   - 한쪽 상태에서만 도달한 공통 쌍은 반대 상태의 S·τ를 그 상태의 `lines.bin`에서 읽는다. ω = −expm1(−τ)는 numpy로 계산한다. C `expm1`과의 비트 동일성은 확인하지 않았다.
   - 그 상태의 H가 0이므로 합계 폐합에는 영향이 없다. 해당 쌍의 F_S/F_τ 개별 배분에만 들어간다.
7. **정확 참조**: 계산된 공유 값(감쇠 계수, D, ray 좌표, 대역 함수의 fp 파장 차이, L_ν→L_λ 계수) 위의 정확 산술이다.
