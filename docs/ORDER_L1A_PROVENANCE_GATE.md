## 0. v1 반려의 요지 — 왜 이 게이트가 먼저인가

운전석은 층 1의 9/9 불일치를 "잣대가 잘 정의됐는가"로 한 번에 감사하려 했다.
Codex 검수가 반박 12건을 냈고, **그중 하나가 나머지를 무의미하게 만든다**:

> **epoch 혼합.** 층 1 판정은 전부 `_sivcaiv`(커버리지 51.74%)에서 측정됐다.
> `_ftos`에서 `levels 26,592→31,792`, `Fe IV lines 4,336→72,223`,
> `Ni IV lines 4,199→72,898`, σ SHA 변경.
> ⟹ **I2·I2a–I2d·I3·I3a–I3c·I17의 분모가 통째로 바뀌었다.**

분모가 바뀐 판정을 잣대 감사하는 것은 순서가 틀렸다. **어느 표본 위에서 무엇을
비교하는지부터 고정**해야 한다. 그것이 이 발주다.

부수 반박(전부 채택, 대장 기재 완료): 대상 수 12→**13**(운전석 오산 3회째) ·
I7 "1,000 대 196,185"는 다른 것 비교(역할 대응 = **1,000 ↔ 15,662**) ·
I2 임계 `1e-6`이 데이터 유효숫자(5자리)보다 엄격 · I3 "bin-averaged" 미확증 ·
I3c/I2b는 구 epoch · 판정 3값 부족 · 함정 4종 부족 · **재현기 부재** ·
누락 5건(I2c·I2d·I3a·I3b·I10) · 작업량 초과.

## 2. 작업

### A1. 표본 계보 확정 (provenance gate)

**모든 층 1 ID(18개: I1, I2, I2a–I2d, I3, I3a–I3c, I4–I10, I17)**에 대해 다음을 채운다.
채울 수 없으면 `UNKNOWN`으로 적고 그 사유를 남긴다 — **추정 금지.**

| 열 | 내용 |
|---|---|
| `deck` | 측정에 쓰인 덱 절대경로 |
| `deck_atomic_sha` | 그 덱의 `levels.csv`·`line_list.csv`·`cmfgen_sigma_bf.bin` SHA-256 |
| `binary_sha` | 측정에 쓰인 Lumina 바이너리 SHA-256 (해당 시) |
| `cmfgen_snapshot` | 대조한 CMFGEN 런 디렉터리와 그 안 파일들의 SHA-256 |
| `atomic_tree` | 대조한 CMFGEN 원자 트리 경로 + `atomic_links.txt`/`MODEL_SPEC` 실제 해석 결과 |
| `symlink_resolved` | 위 경로 중 심링크가 있으면 최종 대상 |
| `epoch_status` | `CURRENT`(현 트리와 일치) / `STALE`(구 덱) / `UNKNOWN` |

**이것이 I15(바이너리·실행환경)·I16(symlink 해석)의 해소를 겸한다** — Codex 지적대로
그 둘은 후속이 아니라 **선행 게이트**다.

### A2. 재측정 필요 목록 산출

A1의 `epoch_status`가 `STALE`인 ID를 열거하고, 각각에 대해:
- `_ftos`(또는 적절한 현행 덱)에서 재측정 가능한가
- 재측정 시 분자·분모가 각각 무엇이 되는가 (구 값과 나란히)

**재측정을 수행하지 말라.** 목록과 분모 정의까지가 이 단계다.

### A3. 판정 어휘 확정

Codex가 제안한 4축을 저장소 실물에 대해 검증한다 — **18개 ID 전부가 4축 어디에
들어가는지 시험 배정**하고, 안 들어가는 것이 있으면 축을 고쳐라.

```
posedness   : WELL / ILL / UNVERIFIABLE
outcome     : MATCH / DIFFER / NO-COUNTERPART / RESOLVED / PARTIAL
kind        : BUG / DESIGN / DEFINITION / COVERAGE / PROVENANCE / NUMERIC
disposition : REPAIR / ACCEPT / DEFINE / REMEASURE
```

시험 배정은 **잠정**이며 물리 판정이 아니다 — 어휘가 충분한지 보는 것이 목적이다.

### A4. 함정 체크리스트 확정 (9종)

각 층 1 비교에 강제할 필수 명시 항목. 운전석 4종 + Codex 5종:

| # | 항목 | 유래 |
|---|---|---|
| 1 | 분자와 분모가 각각 무엇인가 | I2a "4,336" 함정 |
| 2 | 좌표·단위·정의가 양쪽에서 같은가 | I8 `L(r)` 함정 |
| 3 | 표본·평균 규칙이 결과를 바꾸는가 (바꾸면 대안 2개로 폭 제시) | 조성 61배 함정 |
| 4 | 임계가 데이터의 유효숫자보다 엄격한가 | I2 `1e-6` 대 5자리 |
| 5 | **권위 원본·실소비 경로·symlink target** | `n_e 1.92×` 잘못된 oracle |
| 6 | **binary/source SHA와 epoch** | epoch 혼합 |
| 7 | **결합키와 중복 처리** | — |
| 8 | **`missing / zero / unsupported` 네 상태 구분** | I3c "0건=임계 아래" |
| 9 | **영분모·절대/상대 오차 규칙** | 조성 상대차 미정의 |

**이 체크리스트를 기계가 검사할 수 있는 형태(스키마)로 확정하라.**

### A5. 재현기 구축

층 1의 핵심 수치를 재산출하는 **read-only** 스크립트를 만든다.
`rg --glob '*.py' '880406|75075|3953894|1233529'` → 출력 없음 = 현재 재현 불가.

요구:
- 입력 = 덱 경로 + CMFGEN 트리 경로 (하드코딩 금지)
- 출력 = ID별 분자/분모/임계별 카운트, **A4의 9종을 헤더에 기록**
- 임계는 인자 (`1e-6/1e-9/1e-12` 및 exact/ULP)
- `missing / zero / unsupported / present` 네 상태를 **분리 집계**
- 구 덱과 `_ftos` **양쪽에서 돌아가야** 한다 (같은 명령, 덱만 교체)

**재현기가 산출한 값이 대장의 기존 수치와 다르면 그것을 보고하라 — 수정하지 말고.**
